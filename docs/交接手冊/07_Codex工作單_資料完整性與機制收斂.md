### 但有一個統計說法要更正

報告寫「配對平均 −0.0229 pp/趟，標準誤也是 0.0229 pp，`t = -1.00`，
無法排除抽樣噪音」。

**`t = -1.00` 不是量測結果，是代數恆等式。** JSON 裡 `mean_difference`
與 `standard_error` 到 15 位有效數字完全相同，那只在**恰好一個觀察非零**
時發生：

```
n 個觀察，一個是 d 其餘為 0
mean = d/n
std(ddof=1) = d/√n
SE = std/√n = d/n = mean
t = 1   恆成立，與 d 和 n 都無關
```

驗證：2016-11-09 的 A = 0.035724527、B = 0.024739132，差 −0.010985395，
÷48 = −0.000228862，與 `mean_difference` 逐位相符。

所以實情是**48 期裡只有 1 期改變**。結論方向不變，但依據應該寫成
「只有一期改變，攤到 48 期是 −0.0229 pp/趟」，不要寫 t 值——
n=1 談不上抽樣噪音，寫 t 會讓讀者以為做過分布檢定。

請在 `docs/原理說明/` 的對應文件補一段更正（不要改寫原文，加註）。

## 任務 N：價格機制收斂（同一條規則現在有兩份實作）

### 問題

撞車的副產品是兩套機制並存：

```
你的      PriceViews(adjusted, actual)     load_price_views() 呼叫 load_prices 兩次
主線的    raw_open / raw_close 欄位        load_prices 單次，欄位一律存在
```

兩者解同一個問題（可負擔性要用實際價、報酬要用還原價）。
**兩份實作就是兩份會漂移的規則。**

### 各自的問題

`PriceViews`：

```python
return PriceViews(
    adjusted=load_prices(adjusted=True, **common),
    actual=load_prices(adjusted=False, **common),
)
```

- 兩次完整 SQL 查詢 + 兩次調整運算
- `drop_incomplete=True` **各自獨立套用**。兩個 frame 的 index 若分歧，
  `actual.loc[day, sid]` 對不上時不會報錯，而是 KeyError 或錯位
- 實測目前 index 相同，但那是「剛好」，不是保證

`raw_open` / `raw_close` 欄位：

- 單次載入，index 不可能分歧
- 但 `bars["close"]` 與 `bars["raw_close"]` 只差一個字，容易誤用
- `resolve_tier` 的 `adjusted_price` 參數目前**不參與判斷**（只為了強迫
  呼叫端區分兩種價格），這個設計要保留還是簡化，由你決定

### 做什麼

1. 選一個機制，寫下理由。**兩個都可以，但不能都留。**
2. 遷移你負責的呼叫點（見檔案分工）。
3. 主線獨占的檔案**只列清單不代改**。
4. 若選 `PriceViews`，必須加一個測試釘住兩個 frame 的 index 完全相同
   ——那是目前唯一沒有保護的假設。
5. 若選單一 frame 的欄位版，`load_price_views` 要留成 deprecated 包裝
   或明確移除，不要留著讓人誤用。

### 驗收

```
□ 只剩一套機制，另一套移除或明確標記 deprecated
□ 選擇理由寫進 docs/原理說明/（檔名含日期）
□ index 一致性有測試（若選 PriceViews）
□ 主線需改的呼叫點清單
□ 全套測試通過
```

## 報數字的規矩（累積到第四張工作單）

### 1. 點估計不算結論，要配對標準誤

實測範例：投組約束「全部嚴格 vs baseline」點估計是 −1.75 pp/趟，
看起來很明確；配對後 SE 1.58 pp、t = −1.11。

而且要說檢定力：2 SE = 3.16 pp，優勢本身只有 3.28 pp，
**這個檢定只能偵測「約束把整個優勢消滅」**。所以寫「無法排除 X 的代價」，
不要寫「沒有影響」。

### 2. 只有一個觀察非零時不要報 t

見第零部分。`mean == SE` 是警訊，不是巧合。

### 3. ⚠️ 新增：模擬的資金記帳會主導結果

主線在漲停事件驅動診斷裡踩到這個，值得寫進規矩：

```python
amount = CAPITAL / N_POSITIONS      # 400000/3 = 133333.33
if cash < amount: continue          # 3 × amount 恰好等於初始資金
```

任何虧損都讓第三個槓位永久填不滿。同一份資料、同一組參數：

```
資金記帳方式                          交易數    年化
固定 CAPITAL/N + cash 閘門（large 錯）    63    10.0%
固定 CAPITAL/N + cash 閘門（large 修正）   75    16.0%
cash / 剩餘空槓位                        92    40.1%
```

**10% 到 40%，只差記帳方式。**

所以：**任何年化／Sharpe／MaxDD 的宣稱，必須至少跑兩種部位大小規則
並列，或者只報路徑無關的統計（每筆命中率、毛／淨、在市比例）。**

單一資金路徑的權益曲線不構成證據。

### 4. PBO / DSR 的輸入很容易餵錯

```
錯   CPCV 的 15 條路徑總報酬當時間序列      那不是序列
錯   2,196 筆重疊的日報酬當觀察數          DSR 讀成 1.0000
對   有效樣本數 = 天數 ÷ 持有期            36 期，DSR 0.9741
```

`n_observations` 要用**有效**樣本數，且需 ≥ 30。

### 5. 掃了幾組就要說幾組

DSR 的懲罰隨候選數變化。掃 126 組時 DSR 是 0.0042，不通過。
**掃了就要報，不可只報最好那一組。**

### 6. 不要用 `pd.offsets.BDay` 算到期日

低估台股假日。持有期 60 日時實測差 5 天、最壞 14 天。
一律用 `data/calendar.due_trading_date()`。
