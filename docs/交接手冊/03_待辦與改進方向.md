# 待辦與改進方向

依「價值 ÷ 成本」排序。每項都附**為什麼值得做**與**怎麼判斷做成了**。

---

## 先看這個：結果本身不穩定

**最有力的證據來自我自己的兩次執行。**

v6 → v7 之間我只做了一件事：**補齊 23 期缺漏的市值快照**
（那些日期是元旦／週末，MI_QFIIS 回空陣列被誤判成失敗）。
純資料完整性修正，**策略參數、門檻、槽位數完全沒動**。

結果：

```
組合             v6（24 期快照）   v7（46 期快照）    差異
動能突破 × 60     +1544.05%       +1738.27%       +194 pp
籌碼跟隨 × 60     +1076.79%       +1022.05%        −55 pp
均值回歸 × 60      +954.87%        +123.93%       −831 pp  ←
均值回歸 × 120     +294.62%        +802.42%       +508 pp  ←
等權對照           +701.37%        +688.79%        −13 pp
```

對照組只動了 13 個百分點（合理，標的池微調），
但**策略擺盪數百個百分點**。

### 這代表什麼

不是 bug，是**路徑相依**。60 日持有下 99.8% 的訊號被槽位擋掉，
實際成交哪 100 筆取決於「槽位空出來時誰在排隊」。標的池換掉幾檔，
排隊順序就變，整條權益曲線跟著變。

**所以「+1738%」這個數字不該被當成策略的能力。**
它是一次抽樣的結果，而抽樣變異大到蓋過訊號。

這也讓下面第 2 項（門檻形同虛設）從「改進項目」升級成**必須先解決的問題**。

## 高價值

### 1. 劃出新的 OOS 區間

**問題**

CLAUDE.md 規格 6：**OOS 區間只跑一次，不得回頭調參。**

我跑了 **7 次**：

| 次 | 原因 | 是否動策略參數 |
|---|---|---|
| 1 | triple-barrier 初版 | — |
| 2 | 路線 A 初版 | 否 |
| 3 | 修決策日對齊 + 年化期數 bug | 否 |
| 4 | 加多槽位組合模擬 | 否 |
| 5 | 換長歷史資料 | 否 |
| 6 | 修還原因子 bug + 換市值標的池 | 否 |
| 7 | 補齊缺的 23 期市值快照 | 否 |

每次都是**修 bug 或補資料**，策略參數（`PULLBACK_QUANTILE=0.80`、
`edge_z=1.0`、槽位數、持有期網格）全程沒動。

**但這不能免除過擬合風險。** 看了 7 次 OOS 就是看了 7 次。

**做什麼**

```
現在   Train 2015-01 ~ 2018-12   OOS 2019-01 ~ 2026-09
建議   把 2024-01 ~ 2026-09 切出來完全不看，
       用 2019-01 ~ 2023-12 當開發集，最後只在新 OOS 跑一次
```

**怎麼判斷做成了**：在被凍結的區間跑出來的結果，與開發集的差距在
合理範圍（Sharpe 掉一半以內）。差太多就是過擬合。

### 2. 門檻在長持有期下形同虛設 ← **最該先做的**

**問題**

```
籌碼跟隨 × 60 日｜訊號 44,319 筆，成交 102 筆
```

**99.8% 的訊號被槽位擋掉。** 60 日持有下期望報酬遠大於成本，
幾乎所有候選都通過 `E[R] − cost > 0`——門檻沒有在篩選任何東西。

實際成交哪 102 筆，取決於「槽位剛好空出來時誰在排隊」。
這讓結果高度路徑相依，也解釋了為什麼隨機對照在不同槽位下從
−4.68% 跳到 +234.90%。

**做什麼（三選一或都試）**

1. **門檻改成相對排名**：只取當日期望報酬前 N% 的候選，
   而不是「淨期望為正」的全部
2. **提高 `edge_z`**：從 1.0 拉到 2.0，讓統計顯著性門檻真的咬得住
3. **改成定期全部換倉**：每 60 日重新選 Top 3，不等槽位空出來——
   這消除排隊效應，但換手率會上升（成本要重算）

**怎麼判斷做成了**：訊號／成交比從 435:1 降到 10:1 以內，
而且**重跑時的擺盪幅度**從數百個百分點降到數十個百分點——
拿 v6/v7 那張表當基準線。

### 3. 有效樣本太少 → 用 block bootstrap 估信賴區間

**問題**

```
60 日持有   有效獨立樣本 30 個
120 日持有  有效獨立樣本 15 個
```

DSR 全部未達顯著（最好的 0.1197），但 DSR 本身在 30 個觀測值下也不可靠。

**做什麼**

對權益曲線做 **block bootstrap**（區塊長度取一個持有期），
產出總報酬與 Sharpe 的信賴區間。這比單一 DSR 數字有資訊量得多。

**怎麼判斷做成了**：能回答「+1076% 的 95% 信賴區間是多少」。
如果下界低於買進持有，結論就是「無法區分」。

並重跑驗證代理的命中率。

### 5. 分批進場（拉回分批買）從未被回測

**現況**

`weekly_plan_trailing.py` 會輸出三批進場價格階梯，
但**標記層假設 T+1 開盤一次買足**。輸出已揭露這件事。

**做什麼**

需要盤中撮合模擬 + 分價量資料。這是另一個量級的工作。

較輕量的近似：假設三批分別在 T+1、T+3、T+5 的開盤成交（若價格觸及），
未觸及的批次放棄。這能回答「分批是否降低平均成本」而不需要 tick 資料。

**怎麼判斷做成了**：能量化分批相對一次買足的報酬差與成交率。

---

### 6. 0050 買進持有應該扣成本

**現況**：對照組是純價格報酬，沒扣任何成本。

策略扣了 6 折手續費 + 滑價，對照組沒扣——**這對策略不公平**。
但 0050 買一次持有 7 年，成本只有一趟來回約 0.6%，影響很小。

等權持有 150 檔就不同了：每季調倉 × 150 檔 × 7.34 年，
成本可能是兩位數百分點。

**做什麼**：等權對照加上季度調倉成本；0050 加上單次來回成本。

**怎麼判斷做成了**：等權對照的報酬下降幅度與調倉頻率一致。

## 低價值但便宜

### 7. `reports/` 沒有納入版本控制

每次驗證的原始輸出都在 `taiwan-quant/reports/`，但那是 gitignore 的常見對象。
**結論的原始證據應該留存。**

### 8. `stock_universe_history` 舊表可以退役

新表 `universe_history` 已含兩種 basis。舊表只是為了向後相容留著，
`loader` 有 fallback。確認沒有其他呼叫端後可以刪。

### 9. 2015-01-01 那期的市值快照缺失

價格資料從 2015-01-05 開始，往前沒有資料可用。
**這是正確行為**（不可用未來的資料），但值得在文件標明。

## 明確不建議做的

| 項目 | 為什麼 |
|---|---|
| 調 `PULLBACK_QUANTILE` 或 `edge_z` 讓數字變好看 | 觸犯 CLAUDE.md 紅線。要調就先劃新 OOS |
| 縮短持有期到 20 日以下 | 年化成本 14.89%，數學上不可行。已寫進 CLAUDE.md |
| 加更多特徵 | 目前 32 個特徵都通過截斷掃描。上游 303 因子的教訓是 dropna 清空樣本 |
| 上深度學習 | 連 LightGBM baseline 都還沒建。規則式基準的鑑別力尚未證實 |
| 重寫資料同步層 | 已驗證可用（新舊庫逐筆比對 88,389/88,389 相同） |

## 如果你只做一件事

**做第 1 項：劃出新的 OOS 區間。**

目前所有結論的共同弱點都是「這個 OOS 被看過太多次」。
其他所有改進都會再增加一次觀察。**先把驗證區間保護起來，
後面的改進才有意義。**
