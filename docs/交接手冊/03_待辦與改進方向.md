# 待辦與改進方向

依「價值 ÷ 成本」排序。每項都附**為什麼值得做**與**怎麼判斷做成了**。

---

## 先看這個：結果本身不穩定

**最有力的證據來自我自己的兩次執行。**

v6 → v7 之間我只做了一件事：**補齊 23 期缺漏的市值快照**
（那些日期是元旦／週末，MI_QFIIS 回空陣列被誤判成失敗）。
純資料完整性修正，**策略參數、門檻、槽位數完全沒動**。

結果：

```
組合             v6（24 期快照）   v7（46 期快照）    差異
動能突破 × 60     +1544.05%       +1738.27%       +194 pp
籌碼跟隨 × 60     +1076.79%       +1022.05%        −55 pp
均值回歸 × 60      +954.87%        +123.93%       −831 pp  ←
均值回歸 × 120     +294.62%        +802.42%       +508 pp  ←
等權對照           +701.37%        +688.79%        −13 pp
```

對照組只動了 13 個百分點（合理，標的池微調），
但**策略擺盪數百個百分點**。

### 這代表什麼

不是 bug，是**路徑相依**。60 日持有下 99.8% 的訊號被槽位擋掉，
實際成交哪 100 筆取決於「槽位空出來時誰在排隊」。標的池換掉幾檔，
排隊順序就變，整條權益曲線跟著變。

**所以「+1738%」這個數字不該被當成策略的能力。**
它是一次抽樣的結果，而抽樣變異大到蓋過訊號。

這也讓下面第 2 項（門檻形同虛設）從「改進項目」升級成**必須先解決的問題**。

### 2. 門檻在長持有期下形同虛設 ← **最該先做的**

**問題**

```
籌碼跟隨 × 60 日｜訊號 44,319 筆，成交 102 筆
```

**99.8% 的訊號被槽位擋掉。** 60 日持有下期望報酬遠大於成本，
幾乎所有候選都通過 `E[R] − cost > 0`——門檻沒有在篩選任何東西。

實際成交哪 102 筆，取決於「槽位剛好空出來時誰在排隊」。
這讓結果高度路徑相依，也解釋了為什麼隨機對照在不同槽位下從
−4.68% 跳到 +234.90%。

**做什麼（三選一或都試）**

1. **門檻改成相對排名**：只取當日期望報酬前 N% 的候選，
   而不是「淨期望為正」的全部
2. **提高 `edge_z`**：從 1.0 拉到 2.0，讓統計顯著性門檻真的咬得住
3. **改成定期全部換倉**：每 60 日重新選 Top 3，不等槽位空出來——
   這消除排隊效應，但換手率會上升（成本要重算）

**怎麼判斷做成了**：訊號／成交比從 435:1 降到 10:1 以內，
而且**重跑時的擺盪幅度**從數百個百分點降到數十個百分點——
拿 v6/v7 那張表當基準線。

### ✅ 2026-09-18 完成。兩個條件都達成，而且不需要新的回測

```
條件 1   訊號／成交比     E3 定期換倉 = 1.0:1        既有報告就有
條件 2   重跑擺盪幅度     見下方「晚間更正」——部分達成，且條件本身混淆了兩件事
```

> ⚠️ **本節原本寫「條件 2 達成：數百 pp → 最大 24.2 pp」。**
> 當晚補做對照實驗後那個說法不成立——見本項最後的「晚間更正」。

#### 選項 1 與 2 已被既有資料否證

`reports/threshold_sweep_dev.json`（動能突破）：

```
E1-top5    訊號 1722   成交 63   +56.50%
E1-top20   訊號 6510   成交 63   +56.50%
E2-z2.5   訊號 30638   成交 63   +56.50%    ← 訊號 ×18，成交與報酬完全不變
E3-rebal     訊號 57   成交 57  +323.90%
```

**六個方案的報酬是同一個數字，不是相近。** 三族都如此。

所以本項的描述要改：門檻不是「沒有在篩選任何東西」，而是
**站在瓶頸的下游**。3 槽位 × 60 日持有決定成交上限約 63 筆，
門檻篩掉多少候選都不影響它——排隊的人再多，櫃檯還是三個。

**選項 1 與 2 都在操作錯誤的變數**（隊伍長度，不是櫃檯數量）。

#### 條件 2 的實測來自一對免費的報告

任務 M 把 `build_dataset` 從 inner 改成 left join，也是純資料完整性
修正。`diagnose_constraints.py` 用定期換倉且修正前後各有一份報告：

```
                      槽位排隊（v6→v7）      定期換倉（task M 前後）
擺盪幅度               +194、−55、−831、+508   −6.6 ~ −24.2 pp
方向                   兩個方向都有            十個設定九個同向
判讀                   混沌                    系統性資料效應
```

⚠️ 兩個擾動不是同一個，這不是對照實驗。方向與數量級的對比成立，
精確倍數不成立。

#### 機制描述要補一句

我寫合成資料驗「99.8% 被擋 → 路徑相依」時，第一版得到**相反**結果
（槽位傳播 0.0%，定期換倉 0.7%）。原因是合成訊號全部同日出場，
三個槽位永遠同時釋放，槽位排隊退化成定期換倉。

```
本項寫的     99.8% 訊號被槽位擋掉 → 路徑相依
應該寫的     99.8% 被擋 + 出場日不規則 → 路徑相依
```

**「被擋」是必要條件，不是充分條件。**

出場日錯開後，移掉一檔的分歧延續到被擾動部位出場之後兩週
（傳播 14.4% vs 定期換倉 0.7%）。⚠️「傳播到末端」不成立，會自行收斂。

#### 主線已經在用選項 3

近兩天所有診斷腳本（`validate_oos_momentum`、`validate_hand_scores`、
`validate_lgbm_baseline`、`diagnose_constraints`、`diagnose_cost_floor`、
`diagnose_position_costs`）都是固定節點取 top N，零槽位邏輯。

**本項在那批工作開始前就實質解決了，只是沒人回來確認、也沒人宣告
槽位那條路作廢。**

#### ⚠️ 晚間更正：對照實驗推翻了條件 2 的說法

`scripts/diagnose_path_dependence.py`——同一組擾動（每決策日從 150 檔
隨機移掉 3 檔 × 6 種子）餵給兩個方案，H=60：

```
策略族      方案        報酬全距    成交重疊中位
動能突破    槽位排隊     174.9 pp      91.0%
動能突破    定期換倉     116.5 pp      91.6%
籌碼跟隨    槽位排隊      37.8 pp      72.1%
籌碼跟隨    定期換倉      24.0 pp      96.6%
均值回歸    槽位排隊      38.8 pp      70.8%
均值回歸    定期換倉      46.2 pp      86.9%   ← 全距反而變大
```

**三點更正：**

1. **報酬全距只有 2/3 支持定期換倉。** 均值回歸反向。
2. **槽位排隊的全距本身就是「數十 pp」（37.8 ~ 174.9），不是「數百 pp」。**
   v6→v7 那個 −831／+508 pp 來自更大的擾動（23 季快照 + 含 H=120）。
   **本項的條件 2 把擾動大小的效果算進了方案的帳上。**
3. **報酬全距這個比較檢定力不足。** 24 ~ 175 pp 全部落在累積報酬的
   600 pp 信賴區間內（見第 3 項）。

**乾淨的訊號是成交重疊，它 3/3 一致**：哪些名字真的被買進，在三族
全部更穩定。那是路徑相依假說直接預測的量，報酬全距只是它的雜訊函數。

```
✓ 訊號／成交比        433~520:1 → 1.0:1      3/3，結構性
✓ 成交重疊            三族全部提高            3/3，機制層面
△ 報酬全距            2/3 較小，且全在雜訊內
✗ 「數百 pp → 數十 pp」 不成立
```

**採用定期換倉的結論不變，理由換掉**——不是「它更穩定」，而是
比值 1.0、成交重疊更高、曝險不流失、結果可推導。

⚠️ 本項的驗收條件建議改寫成「**成交重疊**提高且訊號／成交比降到
10:1 以內」，不要用報酬全距——後者在 n≤36 量不出來。

依據 `../../qlib-tw-trader/docs/原理說明/2026-09-18_門檻形同虛設與路徑相依的根因.md`

### 3. 有效樣本太少 → 用 block bootstrap 估信賴區間

**問題**

```
60 日持有   有效獨立樣本 30 個
120 日持有  有效獨立樣本 15 個
```

DSR 全部未達顯著（最好的 0.1197），但 DSR 本身在 30 個觀測值下也不可靠。

**做什麼**

對權益曲線做 **block bootstrap**（區塊長度取一個持有期），
產出總報酬與 Sharpe 的信賴區間。這比單一 DSR 數字有資訊量得多。

**怎麼判斷做成了**：能回答「+1076% 的 95% 信賴區間是多少」。
如果下界低於買進持有，結論就是「無法區分」。

### ✅ 2026-09-18 完成。答案比預期更糟

`validation/bootstrap.py` + `scripts/diagnose_bootstrap_intervals.py`，
報告 `reports/bootstrap_intervals_dev.json` 與 `_oos.json`。

**樣本外那份已發佈的結果，每一個基準都落在它自己的區間裡：**

```
動能突破 N=10 累積淨      +138.83%
95% 區間（block=1）      [−13.34%, +587.23%]   寬 600 pp

0050 +242.15%｜0051 +110.22%｜0056 +96.67%｜等權 +61.45%
隨機中位 +58.82%｜隨機 5% +15.10%｜隨機 95% +120.97%
                                    ↑ 七個全部在區間內
```

每趟淨報酬 +6.582%，bootstrap 區間 `[−0.322%, +13.928%]`——**含零**。
16 期的樣本外連「會賺錢」都沒有建立。

#### 本項的診斷只對一半

「有效樣本太少」對水準序列成立，對配對差異不成立：

```
水準序列 lag1 ≈ −0.28（有相依，但負自相關降低長期變異）
配對差異 lag1 ≈ −0.02 ~ +0.08（幾乎無相依，有效樣本就是 36）
```

配對差異的問題是**超額峰度 +1.9 ~ +4.7**，不是樣本數。t 檢定假設常態，
n=36 對這種尾部收斂很慢，失準的位置是區間尾端。

#### 一個重要的否定結果

**五個配對比較的判定，t 與 bootstrap 完全一致。** 先前基於配對 t 的
結論全部站得住（模型對虛無 t=2.82、模型與手工 t=0.30、置換 t=−0.02）。

**失效的只有累積報酬的比較**，包括先前當成最可靠負面結論的「輸 0050」
——那個比較也做不出來。兩個方向的結論要用同一把尺。

#### `+1076%` 本身算不出來

沒有任何報告保存籌碼跟隨 × 60 日的逐期序列，而重跑要動用已用掉的
區間（禁令 6）。**那個數字的不確定性是永久不可知的。**

已加規格：報告結論性數字者必須保存逐期序列。

依據 `../../qlib-tw-trader/docs/原理說明/2026-09-18_信賴區間讓累積報酬失去意義.md`

### 5. 分批進場（拉回分批買）從未被回測

**現況**

`weekly_plan_trailing.py` 會輸出三批進場價格階梯，
但**標記層假設 T+1 開盤一次買足**。輸出已揭露這件事。

**做什麼**

需要盤中撮合模擬 + 分價量資料。這是另一個量級的工作。

較輕量的近似：假設三批分別在 T+1、T+3、T+5 的開盤成交（若價格觸及），
未觸及的批次放棄。這能回答「分批是否降低平均成本」而不需要 tick 資料。

**怎麼判斷做成了**：能量化分批相對一次買足的報酬差與成交率。

### 6. 0050 買進持有應該扣成本

**現況**：對照組是純價格報酬，沒扣任何成本。

策略扣了 6 折手續費 + 滑價，對照組沒扣——**這對策略不公平**。
但 0050 買一次持有 7 年，成本只有一趟來回約 0.6%，影響很小。

等權持有 150 檔就不同了：每季調倉 × 150 檔 × 7.34 年，
成本可能是兩位數百分點。

**做什麼**：等權對照加上季度調倉成本；0050 加上單次來回成本。

**怎麼判斷做成了**：等權對照的報酬下降幅度與調倉頻率一致。
