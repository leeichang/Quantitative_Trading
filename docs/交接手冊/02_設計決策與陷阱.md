這份文件回答兩個問題：

1. **為什麼這樣設計**（改之前先看，免得把防護拆掉）
2. **踩過哪些坑**（這些 bug 有共同的模式，很容易再犯）

## 一、抓到的 9 個 bug

**共同點：全部不拋錯，只讓數字看起來正常。**

| # | Bug | 錯誤症狀 | 根因 |
|---|---|---|---|
| 1 | `derive_width` 的 NaN | R:R 門檻靜默放行 | 一列 OHLC 為 NULL → `np.quantile` 回 NaN → `NaN < 2.0` 是 False |
| 2 | 持倉重疊複合 | 淨報酬 **+10,618%** | 回測引擎依序複合，卻餵 105 個重疊的 60 日持倉 |
| 3 | 對照組期間錯位 | 買進持有只涵蓋 7 個月、策略 2 年多 | 用位置索引取起點，落在不同日期 |
| 4 | 年化期數單位錯 | 年化 **+122,560%**、Sharpe 5.759 | 引擎預設每期一週，實際每期 40 個交易日 |
| 5 | 決策日沒跨標的對齊 | 某些日只有 **1 檔**候選，與隨機 100% 重疊卻「跑贏」 | 各檔用位置索引產生決策日，起始日不同 |
| 6 | fold 切分重複扣暖機 | while 迴圈一次都沒跑，**0 筆交易** | `(WARMUP+TRAIN)//STRIDE = 150` > 可用決策日 128 |
| 7 | 年化用錯期數（第二次） | 9 期跨 1.10 年卻當 0.71 年，+286% → **+564%** | 持倉不連續時 `252/horizon` 不成立 |
| 8 | T86 欄位 2018 年改版 | **97 檔只有 1 檔吻合** | 2015 年 16 欄、2018 年起 19 欄，用固定索引解析 |
| 9 | 還原因子缺漏保留原價 | 0050 算出 **84.20%** 假回撤 | 0050 在 2025 做 1:4 分割，11 天缺還原價留在分割前尺度 |

### 這些 bug 的三種模式

**模式 A：NaN 靜默通過門檻**（#1）

```python
float('nan') < 2.0   # False → 放行
```

對策：門檻比較前一律 `np.isfinite()`。

**模式 B：單位／對齊錯誤**（#2 #3 #4 #5 #6 #7）

六個。全都是「兩個東西的單位或索引不一致，但型別相容所以不拋錯」。

對策：**凡是有兩個資料來源的地方，先確認它們查的是同一個。**
bug #5 與 #6 是連鎖的——修好 #5 之後 #6 才浮現，因為碎片化的日期數
原本掩蓋了它。

**模式 C：上游格式變動**（#8 #9）

對策：依**名稱**取值而非位置；欄位名稱重複時（MI_MARGN）維持位置索引
但加結構檢查。兩個端點用相反策略，因為它們的失效模式相反。

## 二、為什麼這樣設計

### 標記層

**triple-barrier → 移動停損（路線 A）**

原因：triple-barrier 的目標價把上檔封死，強勢多頭裡系統性輸給買進持有。
實測合成資料：固定目標 +22.99%（8 天出場）vs 移動停損 +112.09%（跟到 31 天）。

**判定順序不可顛倒**

```python
if bar_low <= stop:   ...   # 先判出場
if bar_high > peak:   ...   # 才更新高點與停損
```

顛倒過來等於用當日盤中最高點回頭保護當日最低點——那是 look-ahead，
而且不會拋任何錯，只會讓回測變好看。

**停損寬度由資料推導，不可寫死**

```
trail_pct = 歷史 horizon 視窗內「最大回落」的第 q 分位數
```

量測方式與觸發邏輯**完全一致**（以 high 累積峰值、以 low 判定），
所以分位數的意義直白：`q=0.80` → 歷史上 80% 的持有期不會被觸發。

⚠️ **不可照抄 triple-barrier 的 `atr_multiple`。** 固定停損只被測試一次，
移動停損整個持有期都在被測試，同樣寬度觸發機率高得多。

### 校準層

**分數不是機率。** 規則式基準輸出 `0.65` 不代表「65% 機率」。
拿它跟 40.22% 門檻比較「結論毫無意義，而且比沒有門檻更危險，
因為它製造了已經做過風險計算的假象」。

**移動停損沒有固定目標 → 命中率不足以描述期望值**，
所以 `ReturnCalibrator` 直接校準「每箱的平均實際報酬」。

**每箱要帶離散度。** 平均 +8% 標準差 40% 與標準差 2%，
對決策的意義完全不同。

**鑑別力門檻用交易成本。** 最高箱減最低箱的報酬差距小於一趟來回成本，
即使排序方向正確也賺不回成本——那等於沒有鑑別力。

### 進場門檻

```
triple-barrier   P(+1) ≥ (stop + cost) / (target + stop)
移動停損         E[毛報酬] − cost > 0
                 且 E[毛報酬] − cost ≥ z × 標準差 / sqrt(樣本數)
```

第二道是對症下藥：樣本少、離散大時自動變嚴。

⚠️ **不得拿「期望報酬 / trail_pct」硬充 R:R。** 那是期望值 vs 最好情況，
兩個不同的量，混用會讓門檻的意義說不清楚。

### 回測層：為什麼有兩個引擎

```
engine.py         單筆交易的品質（報酬、成本、換手率）
portfolio_sim.py  整個組合的表現（權益曲線、曝險、回撤）
```

`engine.py` 把各期報酬依序複合，**結構上只容得下一個持倉**。
為了避免 bug #2 加的「前一筆出場後才開新倉」規則，默默把 Top 3 改成 Top 1：

```
單槽位 OOS 曝險   23 ~ 39%
等權買進持有曝險   100%
```

在多頭裡光這個差距就足以輸掉，**與選股能力無關**。
修掉後跑贏隨機從 3/9 變 8/9。

`portfolio_sim.py` 的權益**逐日標記市值**——只在出場日跳一次會低估
最大回撤，而 MaxDD 正是跟買進持有對比時最關鍵的風險指標。

## 三、資料層的三個代理（都要揭露）

### 標的池代理

真實 0050/0051 的歷史成分股**在免費來源取不到**（元大只公布現況，
指數公司的歷史審核公告沒有 API）。

用市值排名代理，驗證方式是**拿今天真實的名單比對**：

```
市值排名      142 / 150 = 94.7%
成交金額排名  109 / 150 = 72.7%
```

成交金額版系統性漏掉大市值低週轉的傳產（中鋼、亞泥、和泰車），
而 0050/0051 是市值加權指數。

兩種排名**並存**（`universe_history` 的 `basis` 欄位）——
`04` 與 `05` 是用 turnover 版跑的，刪掉就無法重現。

### 還原股價

混用兩種方法：

```
1,111 檔   yfinance Adj Close        （與上游 production 資料驗證過）
  107 檔   官方除權息紀錄推算         （下市股票，yfinance 查不到）
```

驗證時發現一件反直覺的事：

```
2317  除權息法   12 個因子變動日，全部是真實除息日
      yfinance   42 個變動日，含 2016-08-22 ~ 09-13 的連續段
```

那段連續變動不是公司行為，**是 yfinance 自己的資料抖動**。
除權息法反而乾淨。但我只補缺口不覆寫，免得先前的驗證不可比。

⚠️ **yfinance 的 OHLC 不可用。** 它是分割還原價、TWSE 是原始成交價
（2881 富邦金因股票股利差 2.4390%）。本專案只取它的 Adj Close。

### 對照組的分布問題

```
等權平均   +317.99%（未還原）
中位數      +93.32%
贏家/輸家   424 / 118
前 5 名     ×46、×68、×69、×77、×135
```

**不是資料瑕疵**——3017 奇鋐的價格軌跡逐年平滑上行，前六名全是 AI 供應鏈。

但平均數被少數 100 倍股主導。等權買進持有確實會拿到它們，所以那是它
真實的報酬。**這也說明在這種環境裡，任何會換掉部位的策略都很難贏。**

## 四、改之前先讀這裡

### 不可拆的防護

| 防護 | 拆掉會發生什麼 |
|---|---|
| look-ahead 掃描器的 4 個正控制組 | 掃描器壞掉時「全部通過」的假安全感 |
| `label_trailing` 的判定順序 | 回測變好看，而且不拋錯 |
| `_apply_adjustment` 補因子不補價 | 有分割的標的出現假回撤（bug #9） |
| `load_universe_at` 只取不晚於決策日的快照 | survivorship bias 回來 |
| 所有「無法計算回 None」的地方 | 下游把「無法評估」誤讀成「評估結果很差」 |
| `TwseParseError` 不回空清單 | backfill 把那天標記成「已完成」，資料永久缺一天 |

### 慣例

- **註解用繁體中文**，與既有程式碼一致
- **不可變優先**：回傳新物件，不要就地改寫傳入參數（pandas 3.0 會直接壞）
- **費率一律呼叫 `config/costs.py`**，禁止他處重寫
- **測試比對手算值**，不可拿程式輸出反填預期值
- **秘密走環境變數**，不得硬編碼（Telegram token 已有佔位字串偵測）

### CLAUDE.md 的紅線

> 若策略在 OOS 跑不贏等權買進持有與 0050，就如實寫進報告，
> 不要調參數到看起來贏。

這條被觸發過兩次（`03` 的 0/9、`05` 的 20 日組全輸），
兩次都如實寫進報告了。
