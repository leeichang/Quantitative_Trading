## 三條在這個專案裡反覆出現的教訓

這些不是理論，是實測踩出來的。**如果你只讀一段，讀這段。**

### 1. NaN 不會讓比較拋錯，它會讓比較「看起來通過」

```python
float('nan') < 2.0             # False → 門檻靜默放行
float('nan') != float('nan')   # True  → 兩邊都 NaN 被誤判為「不同」
```

踩到 3 次。對策：任何門檻比較前先 `np.isfinite()`。

### 2. 「無法計算」與「算出來很差」必須區分

| 情境 | 錯誤做法 | 正確做法 |
|---|---|---|
| 樣本不足算不出 Sharpe | 回 0 | 回 `None` |
| 未來 K 棒不足無法標記 | 猜一個標籤 | 回 `None` |
| 那天沒有成交（`--`） | 補 0 | 剔除該列 |
| 缺還原價 | 保留原價 | **補因子** |

最後一條是第 9 個 bug 的根因，它讓 0050 算出 84.20% 的假回撤。

### 3. 數字大到離譜時要先懷疑程式

實測抓到的：`+10,618%`、`+564%` 年化、`84.20%` 回撤、`97 檔只有 1 檔吻合`。
**四次都是 bug，零次是真的發現。**
