## 第一部分：2026-11-09 不會有結論

先把這件事說清楚，因為它最容易被誤讀。

那天只有 **1 個事件日**會到期（2026-09-11 那筆，1 檔 2884）。

```
開發集實測   效應 +1.709%／趟   逐日 sd 11.230%   n = 1,172 事件日
n = 1 時     2 SE 可測效應 = 22.5%
```

**22.5% 的偵測門檻對一個 1.7% 的效應毫無意義。**
2026-11-09 交付的是第一個資料點，不是判定。

若那天 2884 漲了 15%，那不是證據。若跌了 15%，那也不是反證。

## 第二部分：鎖定的量測

### 主要指標

```
每個事件日 d：
    事件組報酬(d)  = 當日觸發名單的 forward 報酬平均
    基準報酬(d)    = 當日標的池全體的 forward 報酬平均
    配對差異(d)    = 事件組(d) − 基準(d)

超額 = 配對差異的平均
SE   = 配對差異的標準差 ÷ √(事件日數)
```

- `forward 報酬 = closes[T+40] / opens[T+1] − 1`（T+1 開盤進、T+40 收盤出）
- **觀測單位是「事件日」，不是「股票-事件」。** 同日事件橫斷面相關，
  把每筆當獨立樣本會讓 n 虛增、SE 虛減。
- 基準用**標的池全體平均**，與開發集的研究完全一致。

### 次要指標

帳本裡記了 `margin_spike_null_h40@v1`（檔數相同、同日標的池隨機抽、
種子綁決策日）。

它的用途是**防止基準被事後重算**：全體平均是可以在揭曉後才算的，
而已記錄的隨機名單不行。兩者若給出相反方向，要停下來查原因。

⚠️ 隨機名單只有 1~3 檔，變異遠大於 150 檔的全體平均。
**它是稽核工具，不是主要指標。**

## 第三部分：判定規則（現在就決定）

### 兩個門檻，時間差 7.4 倍

```
問題                      要跨越的距離   需要事件日   約需時間
效應 ≠ 0（毛超額為正）        1.709%         173      0.9 年
效應 > 成本（淨為正）         0.628%       1,279      6.3 年
```

所需樣本與距離的平方成反比。證明「有東西」要跨 1.709%，
證明「賺錢」只要跨 0.628%——**但那只有前者的 37%，所以要 7.4 倍的時間。**

⚠️ **「統計上顯著」與「賺錢」在這裡差 5.4 年。** 不可以用前者宣稱後者。

### 第一階段：n = 173 事件日（約 2027-10）

主要判定是**配對差異 > 2 SE**。

```
通過    超額 > 2 SE            → 毛超額為正，進入第二階段
失敗    超額 < 0 且 |超額| > 2 SE → 方向相反，停止
不確定  其餘                    → 繼續累積，不做任何調整
```

### 第二階段：n = 1,279 事件日（約 2033-01）

經濟判定，以 N=10 的實測成本 1.081%／趟為基準：

```
賺錢      區間下界 > 1.081%   → 淨為正
不賺錢    區間上界 < 1.081%   → 淨不可能為正，停止
不確定    區間跨越 1.081%     → 仍未定
```

### 期中檢視

允許隨時看，**但不得據以調整任何參數**。期中數字只能寫進報告，
不可以觸發「換持有期」「換分位」「換事件定義」。

**唯一的提前停止條件**：n ≥ 60 時若區間上界 < 0（即「效應為負」
本身已顯著），停止。那不是調參，那是方向被推翻。

```
✗ 改 QUANTILE（0.99）、REFRESH_EVERY（20）、MARGIN_WINDOW（20）
✗ 改 HOLDING_DAYS（40）
✗ 從 H = 5/10/20/40 裡挑一個看起來好的
✗ 改事件定義（融資餘額變動 ÷ 自身 20 日平均）
✗ 事後改基準（必須是同日標的池全體平均）
✗ 把「統計顯著」說成「賺錢」
✗ 用單一事件日的結果宣稱任何事
```

**參數要改就換 `STRATEGY_VERSION`，舊版留在帳本裡。**
`margin_spike_h40@v2` 是新的實驗，不是 v1 的修正。

### 為什麼特別禁止挑持有期

開發集四個持有期全部同向、單調上升，**但只有 H=40 淨值為正**：

```
 H   毛超額/趟     淨/趟    年化增量
 5    0.306%   −0.775%   −32.43%
10    0.600%   −0.481%   −11.45%
20    0.793%   −0.288%    −3.57%
40    1.709%   +0.628%    +4.02%
```

H=40 是**事前依成本地板選的，不是事後挑的**。這份登錄把它釘住。

## 第六部分：預期的失敗模式

寫在這裡，因為事後才想到的解釋都是藉口。

### 1. 同一檔跨日重複觸發

實測 2884 在 7 個交易日內觸發 3 次。開發集的研究按「日」叢聚，
**處理了同日相關，沒有處理同一檔跨日重複**。

若前推期間重複度遠高於開發集，有效樣本會比事件日數少。
**結算時要報告重複度**，不可以只報事件日數。

### 2. 容量

要抓到全部事件需同時持有約 108 檔（2.7 檔/日 × 40 日）。
40 萬 ÷ 108 = 3,700 元/檔，低於零股成本地板。

帳本記的是**全部觸發的名單**，所以它量的是「策略的效應」而不是
「40 萬能實現的報酬」。**這兩件事不同，報告時要分開講。**

### 3. 籌碼資料的可得性

融資餘額由交易所在當日收盤後公布。若公布延遲或 FinMind 取得延遲，
T+1 開盤進場就不成立。**每次記錄要確認 `data_asof` 當天的籌碼資料
已經存在**——腳本現在靠 `load_chips` 的回傳自然失敗，那還不夠明確。

### 4. 開發集的效應本身可能是過擬合

融資暴增過了 20 格網格的 Bonferroni 門檻（t = 5.21 vs 3.02）。
但那 20 格是我選的 5 個事件 × 4 個持有期，**而「選哪 5 個事件」本身
沒有進入多重測試的計算**。

真正的格子數比 20 大，所以門檻應該比 3.02 高。前推是唯一能分辨的。
