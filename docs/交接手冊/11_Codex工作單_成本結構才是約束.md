## 第二部分：任務

### 任務 AA：成本結構 vs 集中度的取捨（最高優先）

`reports/cost_floor_dev.json` 已經有整股比率：

```
N=3    每檔 133,333   整股比率 69.4%   成本 0.834%
N=5    每檔  80,000   整股比率 46.7%   成本 0.964%
N=10   每檔  40,000   整股比率 26.1%   成本 1.081%
N=20   每檔  20,000   整股比率 10.1%   成本 1.194%
```

**用融資暴增事件跑 N = 3/5/10/20，同時報告成本節省與集中度代價。**

工具都在：

```
validation/event_study.capacity_constrained_fills(..., n_slots=N)
validation/event_study.event_study(...)
validation/bootstrap.block_bootstrap(...)
```

必須一起報的四欄：

```
□ 毛超額 + bootstrap 95% 區間
□ 實測成本/趟（逐檔 resolve_tier，不是代表值）
□ 抓取率（N/H ÷ 事件密度）
□ 逐期淨報酬的標準差 ← 集中度的代價在這裡，不在點估計
```

⚠️ **N=3 的點估計一定最好看，因為成本最低。** 但它只抓 2.8% 的事件，
實際結果由「剛好持有哪 3 檔」決定。**不可以只比點估計就宣稱 N=3 最好。**

⚠️ 多重測試：主線今日已累計約 62 格，Gumbel 門檻 √(2 ln 62) = **2.87**。

### ⚠️ 新增：不要拿「超額」比一個用中位數 SE 算的門檻

主線踩過：各格 SE 差 61 倍時，那個算法會挑出 SE 最大的格子。

### 不要在未驗證旗標的 grep 後面串 `|| echo "無殘留"`

本機 `rg` 經 rtk hook 解析到 BSD `grep`，`--glob`／`-g`／`--type` 全部
usage error，而 `||` 分不出「零匹配」與「命令壞了」。改用直接掃檔的
Python。

### 改動的腳本必須實際執行，並附上輸出

`1,022 passed` 證明測試通過，不證明腳本能跑。

### 只有一個觀察非零時不要報 t

`mean == SE` 是代數恆等式不是巧合。

### 點估計不算結論，要配對標準誤，並說檢定力

### 統計函式的每個輸入都要有實測依據，預設值不是依據
