### 驗證 1：新舊資料庫一致性

我建的 `history.db` 涵蓋 2015-2026；原本的 `data.db` 只有 2023-2026。
**重疊期必須逐筆相同**，否則所有先前的驗證結論都不可比。

```bash
cd "/Volumes/Mac/Quantitative Trading/taiwan-quant"
.venv/bin/python - <<'PY'
import sqlite3, numpy as np, pandas as pd
new = sqlite3.connect("file:data/history.db?mode=ro", uri=True)
old = sqlite3.connect("file:../qlib-tw-trader/data/data.db?mode=ro", uri=True)
q = """SELECT stock_id, date, open, high, low, close, volume FROM stock_daily
       WHERE date >= '2023-01-03' AND date <= '2026-09-11'"""
j = pd.read_sql(q, old).merge(pd.read_sql(q, new), on=["stock_id","date"],
                              suffixes=("_o","_n"))
print(f"可比對 {len(j):,} 列 / {j.stock_id.nunique()} 檔")
for c in ("open","high","low","close","volume"):
    same = int((j[f"{c}_o"].astype(float) == j[f"{c}_n"].astype(float)).sum())
    print(f"  {c:<8}{same:>8,} / {len(j):,}  完全相同")
new.close(); old.close()
PY
```

**預期**：五個欄位都是 `88,389 / 88,389`

**不符代表**：我的資料來源與你信任的那份不同，後面所有數字都要重算。

## 二、標記與特徵層

### 驗證 6：look-ahead 掃描

這是整套系統最重要的防線。它用**物理截斷**（`bars.iloc[:i+1]`），
不是日期參數——實測證明 qlib 的 `end_time` 擋不住。

```bash
.venv/bin/python -m pytest tests/test_lookahead.py tests/test_strategies.py -v -k "truncation or lookahead"
```

掃描器本身內建 **4 個故意作弊的特徵當正控制組**，抓不到就拋
`LookaheadError`。這是防「掃描器壞掉時全部通過」的假安全感。

**自己驗一次掃描器有沒有壞**：

```bash
.venv/bin/python - <<'PY'
import sys; sys.path.insert(0, ".")
import numpy as np, pandas as pd
from taiwan_quant.validation.lookahead import scan_builder

def cheating(bars):                       # 故意偷看未來
    out = bars.copy()
    out["future"] = bars["close"].shift(-3)
    return out

idx = pd.date_range("2024-01-01", periods=300, freq="B")
bars = pd.DataFrame({"open":100.0,"high":101.0,"low":99.0,
                     "close":np.linspace(100,150,300),"volume":1000}, index=idx)
try:
    scan_builder(cheating, bars)
    print("✗ 掃描器沒抓到作弊特徵 —— 掃描器本身壞了")
except Exception as e:
    print(f"✓ 掃描器抓到了：{type(e).__name__}")
PY
```

**預期**：`✓ 掃描器抓到了`

### 驗證 10：成本假說

策略在 20 日持有下大虧，我的解釋是「成本」。這個解釋可以獨立驗算：

```bash
.venv/bin/python - <<'PY'
import sys; sys.path.insert(0, ".")
from taiwan_quant.config.costs import DEFAULT, Tier
rt = DEFAULT.round_trip_rate(Tier.MID)
print(f"一趟來回成本（中型股）{rt*100:.3f}%\n")
print(f"{'持有':>6}{'每年趟數':>10}{'年化成本':>10}{'7.34 年侵蝕':>14}")
for hold in (20, 40, 60, 120):
    per_year = 252/hold
    print(f"{hold:>6}{per_year:>10.1f}{(1-(1-rt)**per_year)*100:>9.2f}%"
          f"{(1-(1-rt)**(per_year*7.34))*100:>13.1f}%")
PY
```

**預期**

**這是機械性結論，不依賴任何策略假設。** 如果你只信一件事，信這個。

### 驗證 11：對照組的分布

等權買進持有 +701% 看起來很誇張。查它是不是被少數極端值主導：

```bash
.venv/bin/python - <<'PY'
import sqlite3, pandas as pd, numpy as np
con = sqlite3.connect("file:data/history.db?mode=ro", uri=True)
df = pd.read_sql("""SELECT stock_id, date, close FROM stock_daily
    WHERE date >= '2019-01-29' AND date <= '2026-09-11'
      AND stock_id IN (SELECT DISTINCT stock_id FROM universe_history
                       WHERE basis='market_cap')""", con, parse_dates=["date"]).sort_values("date")
g = df.groupby("stock_id")
r = pd.DataFrame({"first_date": g.date.first(), "a": g.close.first(), "b": g.close.last()})
r = r[r.first_date <= "2019-02-15"]
ret = r.b/r.a - 1
print(f"檔數 {len(r)}｜平均 {ret.mean()*100:+.2f}%｜中位數 {ret.median()*100:+.2f}%")
print(f"贏家/輸家 {int((ret>0).sum())} / {int((ret<=0).sum())}")
print("前 5 名倍數：", [f"×{x+1:.1f}" for x in sorted(ret.values)[-5:]])
con.close()
PY
```

**預期**：平均遠高於中位數，前 5 名是 40x~135x 的 AI 供應鏈股。

**這代表**：對照組是「拿得到那些 100 倍股」的結果。任何會換掉部位的
策略在這種環境裡都很難贏。**這不是我調出來的，但它確實限制了結論的普適性。**
