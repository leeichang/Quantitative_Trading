## 三、七方共識（照做就對，不用再討論）

1. **資料源以 FinMind 為主**（6/7 推薦，唯一例外是千問推 AKShare/Tushare）。
2. **Telegram 只推播、不下單**（7/7 一致）。
3. **回測必須內建台股真實成本**：手續費 + 證交稅 0.3% + 滑價。
4. **AI 不進交易決策迴圈**；AI 的位置在「開發策略」與「解釋結果」。
5. **輸出用區間，不用單一點位**：Entry Zone / Target / Invalidation，而非「買 2350 賣 2550」的死點。
6. **MVP 不要前端**（ChatGPT 明說「第一版甚至不要」；Grok 做了但那是 demo）。
7. **禁止未來函數**、必須有樣本外驗證。
8. **`CLAUDE.md` / `AGENTS.md` 是關鍵基礎設施**，不是可選文件——它是約束 AI 不要作弊的地方。

## 四、分歧與衝突（保留各方立場）

### 衝突 1：FinLab 該不該當核心？

- **Claude**：推薦。「FinLab（台股原生開源套件）內建台股回測框架，處理除權息與公布日邏輯，對台股比通用框架省事很多」
- **ChatGPT**：反對，並且是**自我修正過的立場**。「這點我會修正上一個回答……如果你的目標只是『找股票 → 回測 → 看結果』，FinLab 非常方便。但你現在要的是自己建立一個長期可以演化的 AI Quant System，那麼 FinLab 可以當 **Research Accelerator**，而不是系統核心。」
- **DeepSeek**：只在 Codex 案例中提到 FinLab Skill，未表態。

### 衝突 2：Backtrader 還是 vectorbt？要不要兩套？

- **Backtrader 派**：Gemini、ChatGPT、千問、DeepSeek（為核心）
- **vectorbt 派**：Kimi、Grok
- **DeepSeek 明確反對兩套並行**：「日常策略開發用 Backtrader，參數優化用 VectorBT，**不需同時維護兩套**」（語意上是分工，但警告不要兩套都當主線）
- **Grok 反其道而行**：刻意把同一規則在 Python（vectorbt）與 TypeScript 各實作一次，當成交叉驗證手段

### 衝突 3：要不要做盤中即時？

- **ChatGPT**：力主三層（長期 6~10 年 / 中期 20~120 日 / 即時當日），但**明確警告不要每個 tick 跑 AI**，要用「Score 變動 > 5 分」等門檻節流；並在最後一輪改口——即時的角色是**驗證週計畫是否失效**，不是重新選股。
- **其他 6 家**：MVP 只做日頻，不碰盤中。
- **成本現實**（ChatGPT 提出）：TWSE 直接即時資料有正式授權/費用機制；個人研究走券商 Shioaji 較實際。

### 衝突 4：「三個最佳投資建議」到底是什麼？

| 詮釋 | 誰 | 內容 |
|---|---|---|
| 三檔個股 | Gemini | 台積電 2330 / 聯發科 2454 / 廣達 2382（**價位照抄使用者範例 + 自編其餘兩檔**） |
| 三檔個股 | DeepSeek | 台積電 2330 / 鴻海 2317 / 廣達 2382（後兩檔價位標「依回測模型產出」，不編造） |
| 三檔個股 | Grok | 台積電 / 聯電 2303 / 聯發科 2454（**全部自算，與範例不同**） |
| 三條操作紀律 | Kimi | R:R ≥ 1:2 才動手 / 用回測選策略不憑感覺 / 單筆風險 1% 倒推部位 |
| 三個配置方向 | 千問 | 啞鈴策略（AI 龍頭 + 高股息防禦） / 降低交易頻率回歸基本面 / 資產配置動態再平衡 |
| 拒絕生成 | Claude | 「前三名標的要由 Claude Code 實際跑完 backtrader/vectorbt 的績效排名後才能產生，不是我現在用文字生成」 |
| 五輪推導 | ChatGPT | 沒直接給股票，給出產出 Top 3 的完整漏斗（100→30→10→5→3 + Portfolio Optimizer） |

**這個分歧最值得注意**：同一個問題，三家直接編股票、一家明確拒絕、兩家改答方法論。從工程可信度角度，**Claude 與 Kimi 的處理方式是對的**（沒有資料就不要生成數字），而 Gemini 直接把使用者給的範例數字當成「回測結果」回吐（僅標註「假設性情境」）風險最高。

### 衝突 5：進場哲學 — 追勢 vs 拉回承接

- **使用者範例 / Gemini / DeepSeek / 千問**：買進區間 2,330～2,370（低於當時現價 2,450 約 −3%～−5%）→ **拉回承接**
- **Grok（自算）**：買進區間 2,430～2,470（現價附近）→ **順勢進場**
- **ChatGPT 的解法**：不要人工設 `Buy = 現價 × 0.96`，而是讓模型研究「歷史上這種型態，什麼價格位置進場最有效」再反推 Entry Zone

### 衝突 6：資料源 AKShare/Tushare vs FinMind

千問是唯一推 AKShare/Tushare 的。這兩者是**中國市場**工具，台股覆蓋度與更新頻率都不如 FinMind。此處**採納多數意見（FinMind）**，千問這條建議品質較低。

### 7.4 核心建模方式（把 ChatGPT 的觀念落地成可實作規格）

ChatGPT 反覆強調「不要預測高低點，要預測條件式報酬分布」。落地做法是 **Triple-Barrier Labeling**：

```
給定 T 日收盤（只能用 T 日及之前的資料）
設定三道柵欄：
    上柵 = entry × (1 + target_pct)
    下柵 = entry × (1 - stop_pct)
    時間柵 = T + 5 個交易日

標籤 y =
    +1  若未來 5 日內「先」觸及上柵
    -1  若未來 5 日內「先」觸及下柵
     0  若 5 日後都沒觸及（時間柵到期）

（用當日 high/low 判定觸發順序；同一根 K 同時觸及兩柵時，
  保守起見判為 -1）
```

訓練後模型輸出 `P(y=+1)`，再組合成計畫：

```
Expected R  = P(+1) × target_pct - P(-1) × stop_pct
R:R         = target_pct / stop_pct
進場門檻     = P(+1) ≥ 0.55 且 R:R ≥ 2.0 且 Expected R > 交易成本 × 2
```

`target_pct` / `stop_pct` **不要人工設**（ChatGPT 的關鍵意見）。做法：對每檔股票用近 N 年 ATR 分位數決定 stop（例如 1.5×ATR20），target 由「歷史上相同型態下，5 日內報酬分布的第 70 百分位」決定，再檢查 R:R 是否過門檻。Entry Zone 用相同方法反推最佳進場位置的區間，而不是固定 `現價 × 0.96`。

### 7.5 成本模型（必須寫死在一個地方，不准各處重寫）

```python
# 台股現股做多，一趟來回
FEE_RATE       = 0.001425        # 券商手續費
FEE_DISCOUNT   = 0.6             # 網路下單折扣，依你的券商調整
TAX_RATE       = 0.003           # 證交稅，只在賣出收
SLIPPAGE       = 0.001           # 滑價，保守估
MIN_FEE        = 20              # 最低手續費 20 元（小額交易會被這條吃掉）

# 買入成本率 = FEE_RATE * FEE_DISCOUNT + SLIPPAGE          ≈ 0.00186
# 賣出成本率 = FEE_RATE * FEE_DISCOUNT + TAX_RATE + SLIPPAGE ≈ 0.00486
# 一趟來回 ≈ 0.67%
```

**這是附件 `quant_tw_pipeline.py` 目前最嚴重的缺陷**——它的 `fees` 只有 0.0855%，漏掉整個 0.3% 證交稅（見 [08 技術審查](來源原文/08_附件程式碼盤點與技術審查.md)）。對週頻策略（一年數十趟）少算 0.3% 會讓回測結論整個反轉。

### 7.6 驗證紀律（不可協商）

```
資料切分（採 ChatGPT 建議）
    Train       2015-01 ~ 2021-12
    Validation  2022-01 ~ 2023-12
    Out-of-Sample 2024-01 ~ 2025-12   ← 只看一次，不准回頭調參
    Paper       2026-01 ~ 今天         ← 純前推觀察

Walk-Forward（採 DeepSeek 建議）
    滾動窗口 156 週（3 年）訓練 → 預測下一週 → 前推
    每週重訓，只用該週之前的資料

必跑對照組（採 Kimi 建議）
    買進持有同一檔
    0050 買進持有
    → 若策略在 OOS 跑不贏這兩者，結論就是「這個策略沒有優勢」，
      如實寫進報告，不要調參數到看起來贏

多重測試校正
    掃 N 組參數 / N 個策略時，最佳 Sharpe 必然被運氣污染。
    至少回報：Deflated Sharpe Ratio 或 PBO（Probability of Backtest Overfitting）。
    這是千問提到「真實優勢還是統計巧合」的量化答案。

禁止清單（採 ChatGPT 的 CLAUDE.md 十條）
    1. 禁止 look-ahead bias（T 日決策只用 T-1 收盤前可得資料）
    2. 禁止 survivorship bias（退市股票要留在樣本內）
    3. 必須加入交易成本
    4. 必須加入滑價
    5. 必須 walk-forward
    6. 必須 out-of-sample
    7. 必須保存 strategy version
    8. 必須保存 backtest parameters
    9. 不得直接修改 production
   10. 所有策略必須有 unit test
    ＋ 11. 財報／月營收一律用「公布日」對齊（Claude 的補充）
    ＋ 12. 一律用還原股價（Claude 的補充）
```

### 7.7 投組層約束（採 ChatGPT + 千問）

Top 3 不能全押同一個因子／族群：

```
最多 2 支同產業
最多 1 支高波動（ATR 分位 > 80%）
至少 1 支 defensive / 高股息 / 低 beta   ← 千問「啞鈴策略」的落地
三檔之間 60 日報酬相關係數 < 0.7
```

Grok 的實際輸出（台積電 + 聯電 + 聯發科）**全部是半導體**，正好違反這條——這是需要在程式裡擋掉的具體案例。

### 7.8 部位規模（採 Kimi）

```
單筆風險上限 = 總資金 × 1%
張數 = floor( 總資金 × 1% ÷ (entry − stop) ÷ 1000 )
若算出 0 張 → 這個計畫不推播（風險相對資金太大）
```

鐵律（ChatGPT）：**Quant 負責決策，AI 負責解釋。**
