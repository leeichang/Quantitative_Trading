## D3. 成本模型：FEE_DISCOUNT = 0.6 為預設，並跑雙組敏感度

**背景**：使用者指出「程式不牽涉下單，只提出投資建議」。

**釐清**：成本模型不是為了下單，是為了**回測不高估**。週頻策略一年約 40 趟來回，真實來回成本約 0.67%，一年約吃掉 27%。回測若不扣，會把實際在虧的策略排進 Top 3 推播。因此成本模型屬於**建議品質的一部分**。

**決議**：使用者不需提供實際折扣。

- `FEE_DISCOUNT = 0.6`（6 折，台股網路下單最常見）為預設
- 所有成本常數集中於 `config/costs.py`，**禁止他處重寫**
- 回測報告**同時跑 `FEE_DISCOUNT = 0.6` 與 `1.0` 兩組**做敏感度
- 若策略僅在 0.6 下勝出、1.0 下落敗 → 報告標紅為「邊際過薄」，不得推播

**成本模型規格**：

```python
# config/costs.py — 單一來源，禁止他處重寫
FEE_RATE      = 0.001425   # 券商手續費基本費率
FEE_DISCOUNT  = 0.6        # 預設 6 折；敏感度另跑 1.0
TAX_RATE      = 0.003      # 證交稅，僅賣出收，不可折
MIN_FEE       = 20         # 最低手續費 20 元（小額單會被這條咬）

SLIPPAGE = {               # 分層，因為要做零股（見 D4）
    "0050": 0.003,         # 大型股零股 0.3%
    "0051": 0.004,         # 中型股零股 0.4%
}

def buy_cost(amount: float, tier: str) -> float:
    """買進總成本（含手續費下限與滑價）"""
    fee = max(amount * FEE_RATE * FEE_DISCOUNT, MIN_FEE)
    return fee + amount * SLIPPAGE[tier]

def sell_cost(amount: float, tier: str) -> float:
    """賣出總成本（含證交稅）"""
    fee = max(amount * FEE_RATE * FEE_DISCOUNT, MIN_FEE)
    return fee + amount * TAX_RATE + amount * SLIPPAGE[tier]
```

> 注意 `MIN_FEE` 不能寫成純比例。部位低於約 23,400 元時（6 折），20 元下限會讓實際費率高於 0.0855%——以 40 萬資金做零股，這個情況會常常發生。這是附件 `quant_tw_pipeline.py` 沒處理的第二個成本缺陷。

## D4. 部位以百分比表達；資金 40 萬；**以零股為單位**

**決議**：推播訊息用「佔總資金 %」+「股數」表達，總資金 400,000 TWD。

### 關鍵約束：買不起整張

台積電 2,430 × 1,000 股 = 243 萬，遠超 40 萬。**系統必須以零股（盤中零股交易）為輸出單位，不可用張數。**

1% 風險規則試算：

| 標的 | 參考價 | 停損幅度 | 每股風險 | 建議股數 | 部位金額 | 佔資金 |
|---|---|---|---|---|---|---|
| 台積電 2330 | 2,430 | 3.4% | ≈ 83 元 | ≈ 48 股 | 117,600 | 29% |
| 聯發科 2454 | 1,470 | 3.1% | ≈ 46 元 | ≈ 87 股 | 127,900 | 32% |
| 聯電 2303 | 76 | 6.0% | ≈ 4.5 元 | ≈ 888 股 | 67,500 | 17% |

三檔合計 78% 資金，可容納。

### 部位規模公式（兩道上限取小）

```python
RISK_PER_TRADE = 0.01      # 單筆風險上限 1% 總資金
MAX_POSITION   = 0.33      # 單檔資金上限 33%（3 檔不超過 100%）

def position_shares(capital, entry, stop, ) -> int:
    risk_based = capital * RISK_PER_TRADE / (entry - stop)
    cap_based  = capital * MAX_POSITION / entry
    return int(min(risk_based, cap_based))   # 向下取整到「股」

# 若結果 < 1 股 → 不推播此檔
```

**為什麼要第二道 33% 上限**：若某檔停損幅度只有 2%，單筆 1% 風險倒推出的部位會是資金的 50%，三檔就爆到 150%。33% 上限擋掉這種情況。

### 推播格式調整

## D7 修訂（2026-09-12，依實測資料）

**修訂原因**：原 D7 的參數組合在真實資料上內部矛盾，已由 `taiwan-quant/scripts/diagnose_barrier_params.py` 實測證實。

### 原規格的下場

`horizon=5、atr_multiple=1.5、target_quantile=0.70、min_risk_reward=2.0`

以 0050 前 10 大、2023-01 ~ 2026-09、共 8,919 個決策日實測：

```
覆蓋率      0.38%（34 / 8919）
類別分布    +1 = 0     0 = 28     −1 = 6
```

**`+1` 類別完全為空。** 原因：ATR×1.5 導出的停損約 3%，搭配 R:R ≥ 2 會要求約 7% 的目標，而 5 個交易日內觸及 7% 的機率極低。規格三個要求（5 日 horizon、R:R ≥ 2、ATR×1.5 停損）無法同時成立。

### 修訂後參數

**不動 R:R ≥ 2.0**（那是風險紀律要求，來自 Kimi 的意見），改掉原本拍定的兩個參數：

| 參數 | 原值 | 修訂值 | 理由 |
|---|---|---|---|
| `horizon` | 5 | **5**（不變） | 使用者需求就是「未來 5 個交易日」 |
| `min_risk_reward` | 2.0 | **2.0**（不變） | 風險紀律，不可為了湊樣本放寬 |
| `atr_multiple` | 1.5 | **0.8** | 1.5 倍 ATR 的停損太寬，逼得目標必須拉高到不可觸及 |
| `target_quantile` | 0.70 | **0.85** | 0.70 分位數導出的目標太小，過不了 R:R 門檻 |

修訂後實測（同一資料集）：

```
覆蓋率      55.5%（4,946 / 8,919）
類別分布    +1 = 951     0 = 1,404     −1 = 2,591
平均目標    6.20%        平均停損 2.38%        R:R 2.605
```

三類都有 900+ 樣本，可訓練。

### 修訂帶出的關鍵事實：無條件期望值是負的

```
R:R                  2.605
基礎勝率（排除到期）   26.85%   （951 / 3,542）
損益兩平勝率          27.74%
勝率缺口              −0.89 個百分點

無條件期望毛報酬/趟    −0.076%
一趟來回成本          −1.071%
無條件期望淨報酬/趟    −1.147%
```

**含成本後，模型必須把勝率從 26.85% 提升到 40.22% 以上才有正期望。**

這是對模型的明確量化要求，也是紅線：

> 若 Walk-Forward 的 OOS 勝率無法穩定站上 40.22%，這個策略族就是沒有優勢，如實寫進報告，不進 Top 3。

這條門檻比原本 CLAUDE.md 寫的 `P(+1) >= 0.55` 更有意義——0.55 是拍的，40.22% 是從實際柵欄寬度與成本算出來的。

### 對 CLAUDE.md 的連動修改

進場門檻改為：

```
P(+1) >= (stop_pct + round_trip_cost) / (target_pct + stop_pct)
```

不再用固定的 0.55。門檻隨每檔標的的實際柵欄寬度與流動性分層動態計算。
