## 二、`fetch data.py`（Claude 產出）

### 設計要點

- 直接打 FinMind REST endpoint `https://api.finmindtrade.com/api/v4/data`，dataset 為 `TaiwanStockPrice`
- **增量更新**：讀 `data/{stock_id}.csv` 的 `date.max()`，只抓缺少區間，省 API 額度
- `REQUEST_INTERVAL_SEC = 1.0`，多檔之間 sleep，避免撞 600 req/hr 限流
- `save_cache()` 會 `sort_values` + `drop_duplicates(subset="date", keep="last")`
- Token 走環境變數 `FINMIND_TOKEN`（符合不硬編碼原則）
- CLI 支援 `update` 子命令批次更新所有已快取股票

### 需注意的技術債

1. **抓的是未還原股價**。`TaiwanStockPrice` 是原始收盤價，**沒有還原除權息**。這與 Claude 自己在對話中提出的警告（「除權息要還原，否則回測有 look-ahead bias」）矛盾。台積電 2020→2026 有多次配息，用未還原價回測長期策略會系統性低估報酬。
   → **修正方向**：改用 FinMind 的還原股價資料集（`TaiwanStockPriceAdj`），或自行以 `TaiwanStockDividend` 回推調整因子。
2. `fetch_start > end_date` 的字串比較是 ISO 日期字串比較，剛好正確，但不夠明確；建議轉 `date` 物件比較。
3. 沒有處理 FinMind 回傳 402/429（額度用盡、限流）的重試與退避。

## 三、`add indicators.py`（Claude 產出）

### 設計要點

- 輸入 `data/{id}.csv` → 輸出 `data/processed/{id}.csv`
- 指標：MA5/10/20/60、RSI14、KD(9,3,3)、MACD(12,26,9)、布林(20,2)、VOL_MA20
- `COLUMN_MAP` 把 FinMind 的 `max`/`min`/`Trading_Volume` 映射為標準 OHLCV
- 明確檢查必要欄位缺失並拋 `ValueError`（符合「系統邊界驗證」原則）
- 選 `pandas-ta` 而非 `TA-Lib`：純 Python、pip 直裝，不用編譯 C library，適合交給 agent 自動化的環境

### 需注意的技術債

1. **`pandas_ta` 對新版 pandas / numpy 的相容性已知有問題**（`numpy.NaN` 在 numpy 2.x 被移除）。放進 CI 前要鎖版本，或改用 `ta` / 自行實作。
2. MACD 欄位取值用 `macd.iloc[:, 0/1/2]` 的位置索引，pandas-ta 版本一變欄位順序就錯。**建議改用欄名比對**（`MACD_12_26_9`、`MACDh_12_26_9`、`MACDs_12_26_9`）。同樣問題存在於 `stoch` 與 `bbands`。
3. `existing_cached_stock_ids()` 用 `p.parent == DATA_DIR` 過濾，但 `Path.glob("*.csv")` 本身就不遞歸，這個判斷是多餘的。
4. 指標算完直接覆寫輸出，無版本標記；未來要重現「某次回測用哪版指標」會困難。

## 四、`CFNetworkDownload_aIzj87.py` = `quant_tw_pipeline.py`（Kimi 產出）

這是四個附件中**最接近可交付 MVP** 的一支，但有 3 個必須先修的缺陷。

### 設計要點

- 四層清楚分離：`load_data`（FinMind）→ `run_backtest`（vectorbt）→ `build_plan`（訊號/計畫）→ `send_telegram`（推播）
- **vectorbt 同場比較四個組合**：雙均線交叉(5/20)、RSI 均值回歸(14)、布林突破(20,2)、買進持有基準
- 績效指標齊全：總報酬、年化報酬、最大回撤、夏普率、交易次數
- `build_plan()` 產出**條件式計畫**而非點位預測，依現價落在哪個區間給不同 stance（四種情境）
- 自帶**部位規模公式**：`總資金 × 1% ÷ (entry − stop) ÷ 1000`
- Telegram Token / Chat ID 走環境變數；未設定時只印出不發送（優雅降級）
- `direction="longonly"`（台股散戶現股，不做空）

### 缺陷（依嚴重度排序）

**缺陷 1（嚴重）：成本模型漏了證交稅 0.3%**

```python
fees = 0.1425 * 0.6 / 100   # = 0.000855，只有手續費打 6 折
slippage = 0.001
```

註解寫「手續費 0.1425%*0.6 + 賣出證交稅 0.3% + 滑價 0.1%」，但 `fees` 只有 0.0855%。**證交稅 0.3% 完全沒進成本模型**。

台股一趟完整來回的真實成本約：
`0.0855%（買）+ 0.0855%（賣）+ 0.3%（賣出證交稅）≈ 0.471%`，加滑價約 0.67%。

目前模型只算了約 0.37%，**每筆交易少算約 0.3%**。對高頻策略（雙均線 5/20 年交易數十次）會嚴重高估績效——這正好是「回測騙自己」的典型來源。

→ **修正**：vectorbt 的 `fees` 對買賣兩邊對稱收取，證交稅只在賣出。最簡近似是把 `fees` 提到 `(0.0855 + 0.15)/100 = 0.002355`（把 0.3% 平攤到買賣兩邊），或改用 `from_signals` 的 `fixed_fees`/自訂成本回呼分開建模。

**缺陷 2（中）：`BT_TABLE` 是隱式全域變數**

`build_plan()` 在 f-string 裡引用 `{BT_TABLE}`，但該名稱只在 `if __name__ == '__main__':` 區塊裡賦值。目前能跑，但：

- `build_plan` 被其他模組 import 使用時會 `NameError`
- 違反「函式不依賴隱式全域狀態」
→ **修正**：把 `bt_table: str` 加入 `build_plan()` 參數。

**缺陷 3（低）：股票名稱硬編碼**

`build_plan` 的訊息模板寫死「台積電」，但 `--stock` 可傳任意代號。傳 2317 會推播成「2317 台積電」。
→ **修正**：加一張 `stock_id → name` 對照（FinMind `TaiwanStockInfo` 可取）。

### 其他觀察

- 沒有 Walk-Forward / 樣本外切分，四個策略都是在同一段資料上比較（in-sample）。DeepSeek 與 ChatGPT 都明確要求要切 Train/Validation/OOS，這支還沒做。
- `load_data` 用 `taiwan_stock_daily`（未還原股價），與 `fetch data.py` 同一個問題。註解寫「含還原股價」但實際 API 不是。

## 五、`1789108251314.docx`（千問產出）

### 內容

Backtrader + `TelegramNotifier` class + `SmaCross(5/20)` 策略 + `run_backtest_and_notify()` 主流程。

### 評估

- **資料層是空的**：`cerebro.adddata(data)` 被註解掉，只留「這裡可以替換為 AKShare 或 Tushare 獲取的台股歷史數據」的提示。**這支程式目前無法執行**。
- `commission=0.001` 是佔位數字，不是台股真實費率（應為 0.001425，且要加證交稅）。
- `TelegramNotifier` 封裝乾淨：`requests.post` + `raise_for_status` + try/except + logging，這部分品質最好，可直接沿用。
- 文件附的 4 條擴展建議有價值：
  1. `pip install backtrader requests`
  2. 台股資料建議走 AKShare / Tushare（註：這是中國市場工具，對台股支援不如 FinMind，**此建議品質較低**）
  3. **敏感資訊存環境變數或 `.env`，不要硬編碼**（正確）
  4. **整合 QuantStats 產 HTML 績效報告**，把連結或核心指標推到 Telegram（有價值，其他來源都沒提到）
