## 問題一：試越多組參數，最好的那組越不可信

### 直覺

假設你有 63 組**完全沒有優勢**的策略（全是隨機）。每組跑回測，Sharpe 會在 0 附近隨機分布。

你挑出最高的那個。它的 Sharpe 會是正的——**而且可能相當高**。

這不是因為它有優勢，而是因為你從 63 個隨機數裡挑了最大值。

### 數學

N 個獨立標準常態隨機變數的最大值，期望值約：

```
E[max] ≈ sqrt(2 · ln N)
```

| N | E[max] |
|---|---|
| 1 | 0.00 |
| 10 | 2.15 |
| 63 | 2.88 |
| 1,000 | 3.72 |

所以：**63 組全無優勢的策略，最佳那組的 Sharpe 期望值就有 2.88。**

要證明有真實優勢，觀測 Sharpe 必須顯著**高於這個運氣天花板**。

---

## Deflated Sharpe Ratio

```
E[max Sharpe] ≈ σ · [ (1 − γ)·Φ⁻¹(1 − 1/N) + γ·Φ⁻¹(1 − 1/(N·e)) ]

z   = (觀測 Sharpe − E[max Sharpe]) / SE
DSR = Φ(z)
```

其中：

- γ = Euler-Mascheroni 常數（0.5772...）
- Φ = 標準常態 CDF
- SE = Sharpe 估計量的標準誤 ≈ `sqrt(1/(n_obs − 1))`
- N = 試驗次數

`N = 1` 時 `E[max] = 0`，DSR 退化為單純的 Sharpe 顯著性檢定（沒有選擇偏誤）。

### 應用到 qlib-tw-trader

它跑了 **9 策略 × 7 hedge config ≈ 63 種組合**，報告最佳那個：

```
Sharpe 1.724、156 週、63 組合
```

DSR 計算結果：**判為不顯著。**

這與它自己報的 t-stat 1.89（< 2）一致。

**最諷刺的是**：它的 README 引用了 Harvey, Liu & Zhu 的多重測試論文：

> Harvey, Liu & Zhu. "...and the Cross-Section of Expected Returns."
> Review of Financial Studies, 2016.

**引了論文卻沒套用。**

測試 `test_dsr_flags_qlib_tw_trader_case` 把這個案例釘成迴歸測試。

### 為什麼自己實作 `_normal_ppf`

需要標準常態的反 CDF。用 Acklam 的有理近似（精度約 1e-9），避免為了一個函式引入 scipy 依賴。

MVP 階段依賴越少越好——scipy 會拖進整個編譯工具鏈。

## 問題二：PBO —— 樣本內排名能不能預測樣本外

DSR 回答「這個 Sharpe 可不可信」。PBO 回答一個更直接的問題：

> 樣本內表現最好的策略，在樣本外落到後半段的機率有多高？

### 做法

```
重複 n_splits 次：
    隨機把觀測期對半切成 IS / OOS
    在 IS 段挑出 Sharpe 最高的策略
    看它在 OOS 段的排名分位（1.0 = 最佳、0.0 = 最差）

PBO = P(排名分位 < 0.5)
```

### 判讀

| PBO | 意義 |
|---|---|
| 接近 0 | 樣本內排名可靠地預測樣本外 |
| 0.5 | 樣本內排名等於丟硬幣 |
| > 0.5 | **樣本內排名比丟硬幣還差** |

`CLAUDE.md`：**PBO > 0.5 → 該策略族判定過擬合，不得進入 Top 3。**

### 隨機切分而非固定切點

```python
order = rng.permutation(n_obs)
half = n_obs // 2
is_idx, oos_idx = order[:half], order[half:]
```

固定切點（例如前半當 IS、後半當 OOS）會受市場 regime 影響——若後半剛好是空頭，所有策略都會變差，測不出「排名是否可靠」。

隨機切分把 regime 效應平均掉。

### 輸入驗證

```python
if is_returns.shape[1] < 2:
    raise ValueError("需要至少 2 個策略才能談排名")

if not (np.isfinite(is_returns).all() and np.isfinite(oos_returns).all()):
    raise ValueError(
        "報酬矩陣必須全為有限值。NaN 會讓 argmax 給出無意義結果且不拋錯。"
    )
```

`np.argmax` 遇到 NaN 的行為是未定義的，而且**不會拋錯**——它可能回傳 NaN 的位置，讓「最佳策略」變成一個垃圾值。這又是 NaN 靜默通過的同類問題。

## 問題三：valid/live IC 相關係數（規格 14）

這是三者中**最重要**的，因為它診斷的不是「結果好不好」，而是「整個流程有沒有意義」。

### IC 是什麼

Information Coefficient：預測分數與實際報酬的**橫斷面**相關係數。

```
每天：corr(今天模型給 100 檔的分數, 這 100 檔接下來的報酬)
再取平均
```

- IC = 0 → 排名毫無資訊
- IC = 0.05 → 股票預測算不錯（訊噪比本來就極低）

### 兩種 IC

```
valid IC    驗證期的 IC    ← 用來選模型、選超參數
live IC     樣本外的 IC    ← 真正的表現
```

### 關鍵問題

**valid IC 能不能預測 live IC？**

如果不能，那整個「用驗證期挑最好的模型」的流程就是在挑噪音。

### qlib-tw-trader 的實測結果

```
平均 valid IC  +0.0362
平均 live IC   −0.0263      ← 負的
IC 衰減        172.6%
valid/live 相關係數  −0.1588  ← 負相關
```

**相關係數是負的。** 意思是：

> 驗證期表現好的模型，樣本外表現反而**略差**。

這比虧錢嚴重得多。虧錢可能是市場不配合；**選擇機制方向相反**代表整個調參流程都在製造反效果。

在這種情況下繼續調參數，只會讓模型更貼合驗證期的噪音，樣本外更差。

### 三種判定

```python
correlation < 0                    → 失效且方向相反
0 <= correlation < 0.3             → 失效（幾乎無資訊量）
correlation >= 0.3                 → 有效
```

### verdict 要能直接貼進報告

```python
"模型選擇機制**失效且方向相反**（相關係數 −0.159）：
 驗證期表現好的模型樣本外反而較差。此時調參數是在調噪音，
 應先檢查特徵與標記，不要繼續最佳化。"
```

不只報數字，還要講清楚「所以我該怎麼辦」。

測試 `test_ic_health_verdict_is_actionable` 檢查 verdict 含「調參數」或「噪音」字樣。

### IC 衰減不截斷到 100%

```python
decay = (mean_valid - mean_live) / mean_valid
```

live IC 為負時，衰減會超過 100%：

```
valid  0.0362
live  −0.0263
衰減 = (0.0362 − (−0.0263)) / 0.0362 = 0.0625 / 0.0362 = 172.65%
```

（qlib-tw-trader 實測報 172.6%，吻合。）

**這個數字要如實呈現，不可截斷到 100%。** 截斷會掩蓋「live IC 是負的」這個關鍵事實。

測試 `test_ic_health_decay_over_one_when_live_negative` 把這條釘住。

## 零變異的處理：一個真 bug

第一次跑測試時失敗：

```python
def test_ic_health_handles_zero_variance():
    result = ic_selection_health([0.03] * 10, ...)
    assert result.correlation is None
    # AssertionError: 4.348462988582825e-17 is None
```

### 根因

`[0.03] * 10` 在浮點運算下，`std(ddof=1)` 不是精確的 0，而是約 1e-18 的噪音。

```python
if valid.std(ddof=1) == 0:    # ✗ 永遠是 False
```

於是 `np.corrcoef` 被呼叫，回傳一個同樣是噪音的相關係數（4.3e-17）。

### 為什麼這是真 bug

`correlation = 4.3e-17` 會被判定為「有算出來，結果是沒有相關」，而正確的判定應該是「**無法計算**」。

兩者對使用者的意義完全不同：

- 「沒有相關」→ 模型選擇機制失效，該檢討特徵
- 「無法計算」→ 資料有問題（valid IC 全部相同），該檢討資料

### 修正

```python
ZERO_VARIANCE_TOLERANCE = 1e-12

if valid.std(ddof=1) < ZERO_VARIANCE_TOLERANCE or live.std(ddof=1) < ZERO_VARIANCE_TOLERANCE:
    correlation = None
```

**對計算出來的浮點數做精確相等比較本來就脆弱。** 這是本專案第三次踩到同類問題（前兩次是 NaN 通過門檻、NaN 汙染 quantile）。

## 三者的關係

```
DSR    問「這個 Sharpe 可不可信」          → 針對單一最佳結果
PBO    問「排名可不可靠」                  → 針對整組策略
IC 監控 問「模型選擇機制有沒有意義」        → 針對整個流程
```

嚴重度由輕到重。

IC 監控最嚴重，因為它若失效，前兩者算出來的結果都沒有意義——**你連「哪個策略比較好」都判斷不了。**

## 使用時機

| 階段 | 用什麼 |
|---|---|
| 每次 Walk-Forward 完成 | IC 監控（規格 14） |
| 比較多個策略族時 | PBO |
| 報告最佳策略的 Sharpe 時 | DSR，且必須誠實填寫 `n_trials` |

### `n_trials` 必須誠實

DSR 的核心參數是「你試了幾組」。

這包含：

- 參數網格的所有組合
- 試過但沒報告的策略變體
- 換過的特徵組合
- 調整過的標記參數

**低報 `n_trials` 等於自欺。** 這是 DSR 唯一無法從資料驗證的輸入。
