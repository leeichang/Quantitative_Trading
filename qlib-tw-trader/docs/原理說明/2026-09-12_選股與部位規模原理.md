## 核心原則：寧可少推幾檔，也不違反風控

湊滿 3 檔**不是目標**。

ChatGPT 來源的原話（見 `來源原文/02_ChatGPT`）：

> Top 3 若全部是 AI / 半導體 = **Factor concentration**，風險很高。

三檔全是半導體，表面上分散成三個標的，實際上是同一個賭注下三次。市場回檔時三檔同步下跌，「分散」完全沒發揮作用。

所以程式的邏輯是：**先滿足約束，再看能湊到幾檔。** 湊不到 3 檔就推 2 檔，並在訊息裡說明原因。

```python
if len(positions) < TOP_N:
    warnings.append(
        f"僅選出 {len(positions)} 檔（目標 {TOP_N} 檔）："
        "候選不足以在滿足投組約束下湊滿。寧可少推也不違反風控"
    )
```

## 動態進場門檻（D7 修訂）

```
P(+1) ≥ (stop_pct + round_trip_cost) / (target_pct + stop_pct)
```

### 推導

期望值為 0 的臨界點：

```
p × target − (1 − p) × stop − cost = 0
p × target − stop + p × stop = cost
p × (target + stop) = stop + cost
p = (stop + cost) / (target + stop)
```

### 為什麼不用固定的 0.55

原本 `CLAUDE.md` 寫的 0.55 是拍的。動態門檻有三個好處：

1. **隨柵欄寬度變化**：目標寬的標的容錯高，門檻自然低
2. **隨流動性分層變化**：中型股滑價 0.4% > 大型股 0.3%，門檻自然高（要更確定才值得做）
3. **可解釋**：每個數字都能追溯到成本與柵欄

### 實測值

```
target 6.20%、stop 2.38%、0050 來回成本 1.071%

門檻 = (0.0238 + 0.01071) / (0.0620 + 0.0238)
     = 0.03451 / 0.0858
     = 40.22%
```

這就是 CLAUDE.md 的新紅線。

## 部位規模：兩道上限取小（D4）

```python
risk_based = capital × 1% ÷ (entry × stop_pct)      # 風險倒推
cap_based  = capital × 33% ÷ entry                   # 資金上限
shares = floor(min(risk_based, cap_based))
```

### 第一道：單筆風險 1%

來自 Kimi 的意見（見 `來源原文/06_Kimi`）：

> 部位張數 ＝ 總資金 × 1% ÷ (2,350 − 2,280) ÷ 1,000

意義：即使停損被觸發，損失也只佔總資金 1%。

### 第二道：單檔資金上限 33%

**這道是我加的，Kimi 的原始公式沒有。**

理由：停損幅度很窄時，1% 風險倒推出的部位會爆掉。

```
entry 100、stop 1%
    每股風險 = 1.0 元
    風險倒推 = 400,000 × 1% ÷ 1.0 = 4,000 股
    部位金額 = 400,000 元  ← 100% 資金！

三檔都這樣 → 300% 資金（需要 3 倍槓桿）
```

33% × 3 檔 = 99%，剛好不超過 100%。

測試 `test_position_shares_capital_cap_binds_on_tight_stop` 把這個情境釘住。

### 為什麼是零股不是張數

使用者資金 **40 萬**。

```
台積電 2,430 元 × 1,000 股 = 243 萬
```

**買不起一張。** 系統必須以零股為輸出單位。

實測：

```
entry 2,430、stop 2.38%
    每股風險 = 2,430 × 0.0238 = 57.834 元
    風險倒推 = 4,000 ÷ 57.834 = 69.16 股
    資金上限 = 132,000 ÷ 2,430 = 54.32 股
    取小並向下取整 → 54 股（部位 131,220 元，佔資金 32.8%）
```

向下取整是必要的——向上取整會超出資金上限。

### 算出 < 1 股 → 不推播

```python
if position_shares(capital, c.entry_price, c.stop_pct) < 1:
    rejected.append(Rejection(..., RejectReason.POSITION_TOO_SMALL, ...))
```

單股價格超過資金上限（13.2 萬）時，連 1 股都買不起。推播一個買不起的標的沒有意義。

## 投組約束

### 最多 2 支同產業

三檔全同產業就是單一賭注。上限 2 讓至少有一檔來自不同產業。

### 最多 1 支高波動（ATR 分位 > 80%）

高波動標的貢獻的組合波動度遠高於其權重。兩檔高波動 + 一檔低波動的組合，風險實際上由那兩檔主導。

### 至少 1 支 defensive

`CLAUDE.md` 原文寫「defensive / 高股息 / 低 beta」。

**實作只用低 beta（< 1.0），因為高股息資料不可用**——上游 `stock_daily_per`（含殖利率）覆蓋率僅 4.3%（FinMind 免費額度撞牆）。

程式與文件都記錄這個代理選擇，拿到完整殖利率資料後應改為「低 beta **或** 高股息」。

#### 為什麼需要主動替換

貪婪選法依期望值排序取前 3，可能全部是高 beta。所以要有 `_promote_defensive()`：

```python
# 從期望值最低的持股開始換（犧牲最小）
for drop_idx in range(len(picked) - 1, -1, -1):
    remaining = [c for i, c in enumerate(picked) if i != drop_idx]
    for defensive in defensive_pool:
        if _violates_constraints(defensive, remaining, correlations) is None:
            return remaining + [defensive]
```

換不成就發警告，不硬塞：

```
組合中沒有 defensive（低 beta）標的，
全部集中在高 beta——市場回檔時三檔會同步下跌
```

### 相關係數 < 0.7

產業分類是粗糙的代理。兩檔可能屬於不同產業但走勢高度同步（例如台積電與其設備供應商）。

相關係數直接量測這件事。

#### 缺資料時保守拒絕

```python
if rho is None:
    return Rejection(..., RejectReason.CORRELATION_UNKNOWN,
        "缺少與 X 的相關係數資料。保守拒絕——當成 0 等於假設無關，"
        "可能讓高度相關的標的同時入選")
```

當成 0 等於假設「無關」，可能讓兩檔高度相關的標的同時入選，而使用者以為已經分散了。

這與 NaN 靜默通過門檻是同一類問題：**缺資料不等於安全值。**

## 排序依期望淨報酬，不是 P(+1)

```python
def expected_return(self, cost):
    gross = self.prob_up * self.target_pct - (1 - self.prob_up) * self.stop_pct
    return gross - cost.round_trip_rate(self.tier)
```

### 為什麼不用 P(+1) 排序

勝率高不代表期望值高。

```
A: p=0.70、target 5%、stop 2.5%
   期望毛 = 0.70 × 0.05 − 0.30 × 0.025 = 0.0275

B: p=0.65、target 9%、stop 3.0%
   期望毛 = 0.65 × 0.09 − 0.35 × 0.030 = 0.0480
```

**B 的勝率較低但期望值高 75%。** 用勝率排序會選錯。

測試 `test_ranked_by_expected_return_not_probability` 把這條釘住。

### 時間柵到期併入 P(−1)

`(1 - prob_up)` 包含了 label 0（時間柵到期）的情況。到期時實際報酬介於兩柵之間，這裡假設最差（等同觸停損）。

保守處理，與校準模組的 `P(+1) = n_hits / n_total` 一致。

## 可稽核性：每筆剔除都有原因

```python
class RejectReason(str, Enum):
    BELOW_ENTRY_THRESHOLD = "below_entry_threshold"
    BELOW_RISK_REWARD = "below_risk_reward"
    INDUSTRY_LIMIT = "industry_limit"
    VOLATILITY_LIMIT = "volatility_limit"
    CORRELATION_LIMIT = "correlation_limit"
    CORRELATION_UNKNOWN = "correlation_unknown"
    POSITION_TOO_SMALL = "position_too_small"
    TOP_N_REACHED = "top_n_reached"
```

每筆剔除都帶 `detail` 文字：

```
P(+1) 22.1% < 門檻 40.22%（target 6.20%、stop 2.38%、成本 1.071%）
同產業（半導體）已有 2 檔，上限 2
與 2330 相關係數 0.85 ≥ 0.7
```

沒有這些就無法回答「**為什麼 2026-09-12 沒有推薦台積電**」（CLAUDE.md 禁令 7、8）。

測試 `test_every_rejection_has_a_reason` 驗證：入選 + 剔除的聯集必須等於全部候選，不可有候選「憑空消失」。

## 排序可重現

```python
ordered = sorted(passed, key=lambda c: (-c.expected_return(cost), c.stock_id))
```

期望值相同時用代號升冪。沒有這個 tie-breaker，同樣的輸入可能給出不同的輸出（dict 順序、浮點比較），回測就不可重現。
