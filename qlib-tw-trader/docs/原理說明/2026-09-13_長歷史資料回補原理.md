## 一、為什麼要回補

`04_路線A驗證結果.md` 的七條限制裡，前三條指向同一件事：

```
1. 有效獨立樣本 5 ~ 16 個
2. OOS 只有 1.56 年，且是極端多頭（等權 +305%）
3. 標的池是今日名單的市值代理 → survivorship bias
```

這些**不可能靠改程式解決**。唯一的辦法是把資料拉長。

回補後：

| | 回補前 | 回補後 |
|---|---|---|
| 資料起點 | 2023-01-03 | **2015-01-05** |
| 交易日 | 915 | **2,850** |
| 標的 | 100 檔（今日市值前 100） | **1,218 檔**（含 159 檔已下市） |
| OOS 長度 | 1.56 年 | **7.34 年** |
| OOS 涵蓋 | 只有多頭 | 2020 疫情崩跌、2022 空頭 |
| 標的池 | 一份今日快照 | **47 個季度快照** |

## 二、來源選擇：走過三條路

### 2.1 TWSE 官方日報（驗證用，但被 WAF 擋下）

```
MI_INDEX    每日收盤行情（全部）   OHLCV，含 ETF 與當年掛牌的所有證券
T86         三大法人買賣超         個股別
MI_MARGN    融資融券彙總           個股別
```

**與既有資料的重疊期交叉驗證（2024-01-03、2025-07-15）：**

```
MI_INDEX    97 / 97 完全吻合
T86         97 / 97 完全吻合
MI_MARGN    93 / 93 完全吻合
```

但連續抓取數百次之後：

```
HTTP 307   「因為安全性考量，您所執行的頁面無法呈現。」
           server: HiNetCDN
```

那是防爬蟲機制。**不繞過**——解析程式留下來當驗證基準，抓取改走別的路。

### 2.2 yfinance（只用於還原價）

**不能用它抓 OHLC。** 實測 2023~2026 重疊期比對 8 檔：

```
7 檔   OHLC 相對誤差中位數 0.000000   完全吻合
2881   OHLC 四欄都差 2.4390%          系統性偏差
```

2.4390% = 1 − 1/1.025。查證：富邦金 2023-09-04、2024-09-09、2025-09-25 各有一次股票股利，Yahoo 記為 split。

> **yfinance 的 OHLC 是分割還原價，TWSE 是原始成交價。**

在 2023-01 接起來，有配股的個股會在接點產生假跳空。

### 2.3 FinMind（主要來源）

請求經濟性差兩個量級：

```
TWSE      一天一請求  ×  2,850 天  ×  3 端點  =  8,550 次
FinMind   一檔一請求（整段 11 年）  ×  1,284 檔  =  1,284 次
```

實測 2330 的 11 年價格：一次請求、2,850 列、0.6 秒。

**數值一致性**：FinMind 2015-01-05 的 2330 是 `open 140.5 / max 140.5 / min 137.5`，與 TWSE MI_INDEX 同日完全相同。兩者都是原始成交價。

## 三、驗證方法：用重疊期當標尺

新來源不能靠「看起來合理」就採用。既有的 2023-2026 資料已經驗證過，
它就是現成的標尺——**新舊在重疊期必須逐筆一致**。

### 結果

```
                完全相同      不符    不符佔比
open/high/low/close   88,389 / 88,389       0    0.00%
volume                88,389 / 88,389       0    0.00%
adj_close             最大相對誤差 0.000499，>0.5% 的 0 筆
三大法人 外資/投信     86,926 / 86,926       0    0.00%
三大法人 自營商        86,834 / 86,926      92    0.11%
融資融券 六欄全部      83,359 / 83,359       0    0.00%
```

### 那 0.11% 查到底了

92 筆不符**全部集中在單一日期 2026-09-10**，且只有自營商欄位：

```
舊庫自營買進合計   09-09: 58,570,007
                  09-10: 20,349,883   ← 異常偏低
                  09-11: 49,682,483

新庫自營買進合計   09-09: 86,827,373
                  09-10: 67,228,532   ← 與前後一致
                  09-11: 68,533,586
```

舊庫在那天的自營商資料公布完成前就被抓取了。**新資料是對的。**

同一天的外資與投信 100% 一致，也印證不是解析錯誤。

## 四、抓到一個會污染八年資料的 bug

### 症狀

用 2015 年的欄位索引解析 2024 年的 T86：

```
97 檔裡只有 1 檔吻合
外資碰巧對、投信與自營商全錯
而且不拋任何錯
```

### 根因

```
T86  2015-01-05   16 欄   外資買進股數 / 外資賣出股數 / 投信... / 自營商...
T86  2018-01-03   19 欄   外陸資買進股數(不含外資自營商) / 外資自營商買進股數 / ...
```

2018 年起「外資」被拆成「外陸資」與「外資自營商」，後面所有欄位往後位移三格。

### 對策

**依欄位名稱取值，不用位置索引。** `T86_ALIASES` 同時認得兩種命名：

```python
"foreign_buy": ("外陸資買進股數(不含外資自營商)", "外資買進股數"),
```

取窄定義（不含外資自營商）以與既有資料一致。實測外資自營商佔外陸資
的 0.000% ~ 1.252%，2018 年的定義斷點影響很小，但仍記錄在此。

### MI_MARGN 反而不能用名稱

它的欄位名稱**有重複**：

```
['代號','名稱','買進','賣出','現金償還','前日餘額','今日餘額','次一營業日限額',
          ' 買進','賣出','現券償還','前日餘額','今日餘額','次一營業日限額','資券互抵','註記']
             ↑ 融資區塊                      ↑ 融券區塊，名稱相同
```

`買進` 同時出現在融資與融券兩區塊，用名稱查會取到錯的區塊。所以維持
位置索引，但解析前先比對整張欄位表，不符就拋錯。

**兩個端點用相反的策略，因為它們的失效模式相反。**

## 五、survivorship 怎麼解

### 5.1 資料層：把下市的抓回來

```
TaiwanStockInfo        現存證券
TaiwanStockDelisting   725 檔下市證券及下市日期 → 其中 159 檔在 2015 之後
```

2015 之後才下市的股票，在回測區間內是**真實可交易的標的**。
只用今天的名單回溯歷史，就是把它們全部漏掉。

### 5.2 標的池層：逐季快照

由價格資料的日均成交金額排名，每季取前 150 名，共 47 個快照。

**排名依據是成交金額，不是市值。** 市值需要流通股數，FinMind 免費層
沒有。這是流動性代理，已寫進 `UniverseWarning`。

### 5.3 效果有多大

```
歷來入池                586 檔
曾入池、今已下市          34 檔
2015Q1 與 2026Q3 的成員重疊   70 / 150
2015 有、今天沒有的            80 檔
```

**2015 年標的池裡超過一半今天已不在。** 而且不是邊緣股：

| 代號 | 名稱 | 最佳排名 | 下市日 |
|---|---|---|---|
| 2456 | 奇力新 | 5 | 2022-01-05 |
| 2448 | 晶電 | 6 | 2021-01-06 |
| 3474 | 華亞科 | 6 | 2016-12-06 |
| 2311 | 日月光 | 9 | 2018-04-30 |
| 2325 | 矽品 | 13 | 2018-04-30 |

### 5.4 快照的內容通過直覺檢驗

```
2015  台積電、鴻海、聯發科、大立光、可成
2018  台積電、國巨、華新科、玉晶光       ← 2018 的 MLCC 狂潮
2022  台積電、長榮、陽明、智原            ← 2022 的航運行情
2026  台積電、南亞科、聯發科、國巨
```

每一期的組成都對應當時真正熱門的族群。這是排名機制抓到真實市場結構的
強證據——如果只是雜訊，不會這麼整齊。

### 5.5 反 look-ahead

`load_universe_at(as_of)` **只取不晚於 `as_of` 的最新快照**。

早於第一個快照時**拋錯**，不可退回最早的那一份——回最早的等於用
2015 的名單去跑 2014，那同樣是 look-ahead。

## 六、還原股價：為什麼這裡用 yfinance 是安全的

FinMind 的 `TaiwanStockPriceAdj` 要付費，TWSE 的除權息報表被擋。
所以走 yfinance 的 Adj Close。

**關鍵：只取 Adj Close，不取 OHLC。** 因子是

```
adj_close(yfinance) / close(原始成交價)
```

分子含分割與股利還原、分母是原始價，比值正好就是完整的還原因子。

而且**既有的 `stock_daily_adj` 本來就是這樣組的**。實測比對 4 檔 × 892 根：

```
相對誤差中位數  0.000002 ~ 0.000040   （DB 存兩位小數的捨入）
超過 0.5% 的列  0 / 3568
```

方法學在 2023-01 沒有斷點。

### 已知缺口

yfinance 查不到下市股票，107 檔拿不到還原價。那些列保持未還原，
`loader` 會在 `is_adjusted` 標記。整體覆蓋率 95.8%，標的池成員 97.01%。

## 七、效能：一個 85 倍的加速

### 問題

11 年 × 586 檔 × 3 族 的分數計算，實測 4.0 ms/次 → 超過一小時。

### 根因

```python
row = build_technical(bars).iloc[-1]
```

每次呼叫都重建**整張**特徵表，只為了取最後一列。

### 對策

把 row → 分數的運算抽成獨立函式，特徵表每檔只算一次：

```
score_fn(bars)      單點：吃整段日 K，回最後一天的分數      （保留，供既有呼叫端用）
score_series(bars)  向量：只建一次特徵表，逐列套用同一組運算
```

實測（2330，11 年、520 個決策點）：

```
動能突破   向量 0.03s vs 逐次 2.2s   加速 85×
籌碼跟隨   向量 0.04s vs 逐次 1.9s   加速 54×
均值回歸   向量 0.02s vs 逐次 2.1s   加速 83×
```

### 兩條路徑必須完全等價

`test_score_series_matches_score_fn_pointwise` 逐點比對。真實資料上
最大差 2.8e-13（tanh 的浮點噪音）。

**只要有任何實質差異，先前所有的驗證結論在新資料上就不可比。**

## 八、踩到的兩個工程坑

### 8.1 SQLite 鎖競爭讓回補靜默卡死

第一版寫進 `qlib-tw-trader/data/data.db`。背景行程跑五分半後：

```
WAL 30 秒零成長
CPU 0.85 秒 / 5 分鐘
TCP 連線 ESTABLISHED
```

原因：qlib-tw-trader 的 uvicorn 服務開著同一個 DB 已 20 小時。

**對策：寫進獨立的 `taiwan-quant/data/history.db`。** 沒有鎖競爭，而且
完全不碰已驗證的 production 資料（比 `INSERT OR IGNORE` 更徹底地滿足
禁令 9）。誤寫進去的 10 天資料已從備份還原。

### 8.2 解析失敗一律拋錯，不回空清單

回空清單會讓 backfill 把那天標記成「已完成、沒有資料」，之後不再重試，
資料就永久缺一天且無人察覺。

這與「無法計算」與「算出來很差」必須區分是同一條原則。
`_classify()` 明確區分：

```
stat 不是 OK        → no_data  （那天沒開市，不重試）
其他解析失敗         → error    （程式問題，會重試）
```

## 十、長歷史揭露了什麼

這是整件事的重點——**資料拉長之後，先前的結論翻盤了**。

完整數字見 [05_長歷史驗證結果.md](../../../docs/需求規劃/202609/05_長歷史驗證結果.md)。

摘要（20 日持有、OOS 2019-01 ~ 2026-09、7.34 年）：

```
動能突破    −68.91%
籌碼跟隨     +6.15%
均值回歸    −34.34%
隨機進場    −45.53%
等權買進持有  +442.97%
```

先前在 1.56 年多頭裡的 +372.79% 是**環境的產物**，不是策略的能力。

而且**隨機進場也是 −45.53%**，代表虧損主要來自機制而非選股。
一趟來回成本 1.271%（中型股），20 日持有等於每年 12.6 趟：

```
持有  20 日  年化成本 14.89%   7.34 年累積侵蝕 69.4%
持有  40 日  年化成本  7.74%   7.34 年累積侵蝕 44.7%
持有  60 日  年化成本  5.23%   7.34 年累積侵蝕 32.6%
持有 120 日  年化成本  2.65%   7.34 年累積侵蝕 17.9%
```

這正是 CLAUDE.md 規格 13 寫的：**持有期是成本的主導因素。**

## 十一、對照組為什麼這麼大

等權買進持有 +442.97%（還原價）／+317.99%（未還原），年化約 21.5%。

前六名的報酬是 42x ~ 135x：

| 代號 | 名稱 | 2019-01 | 2026-09 | 倍數 |
|---|---|---|---|---|
| 3017 | 奇鋐 | 24.95 | 3,370 | ×135.1 |
| 2368 | 金像電 | 13.25 | 1,030 | ×77.7 |
| 3653 | 健策 | 82.00 | 5,765 | ×70.3 |
| 2383 | 台光電 | 77.40 | 5,365 | ×69.3 |

**不是資料瑕疵。** 3017 的價格軌跡逐年平滑上行
（24.95 → 42.75 → 67.5 → 89 → 112.5 → 329.5 → 615 → 1,455），
前六名全是 AI 供應鏈。

但要注意**平均數被極端值主導**：

```
等權平均   +317.99%   （未還原）
中位數      +93.32%
贏家/輸家   424 / 118
```

等權買進持有確實會拿到那些 100 倍股，所以平均數是它真實的報酬。
但這也說明：**在這種環境裡，任何會把部位換掉的策略都很難贏。**
