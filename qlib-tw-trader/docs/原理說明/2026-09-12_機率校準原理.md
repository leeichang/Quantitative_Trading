## 問題：分數不是機率

模型與規則式基準輸出的是**分數**，不是機率。

```python
def momentum_score(features):
    parts = [tanh(momentum_20 × 8), tanh(momentum_60 × 4), ...]
    return 0.5 + 0.3 * mean(parts)     # 映射到 [0.2, 0.8]
```

這個 `0.65` 不代表「65% 機率達標」。它只是一個**排序用的數字**，值域是設計者拍的。

### 為什麼這件事致命

進場門檻的設計是：

```
P(+1) ≥ (stop + cost) / (target + stop) = 40.22%
```

拿未校準的分數去比：

```
0.65 ≥ 0.4022  →  通過
```

**結論毫無意義。** 更糟的是，它製造了「已經做過風險計算」的假象——系統看起來嚴謹，實際上門檻形同虛設。

LightGBM 的 `predict_proba` 有同樣問題。梯度提升樹在類別不平衡時（triple-barrier 的 +1 只佔約 19%）通常過度自信。

---

## 解法：分箱校準

用歷史 triple-barrier 標籤回答一個直白的問題：

> 分數落在 [0.6, 0.7) 的歷史樣本中，實際有多少比例是 +1？

那個比例才是這一箱的 `P(+1)`。

```
分數區間          樣本數     實際 P(+1)
[0.238, 0.308]      100       0.1900
[0.658, 0.728]     1335       0.2090
[0.728, 0.798]      562       0.2206
```

分數 0.76 的真實機率是 **22.06%**，不是 76%。

---

## 三條設計原則

### 1. 樣本不足的箱回 `None`，不猜

```python
if not bucket.is_usable(self.min_samples_per_bin):
    return None
```

**不可**用相鄰箱或整體基準硬補。硬補會讓罕見分數區間看起來有統計依據，實際上那個區間只有 3 筆樣本。

呼叫端收到 `None` 應視為「**無法評估**」而剔除該候選，不是「機率很低」。兩者對決策的意義不同。

### 2. 超出訓練期分數範圍回 `None`，不外推

```python
if score < self.score_min or score > self.score_max:
    return None
```

外推在金融資料上特別危險：**極端分數往往出現在極端行情，而那正是歷史關係最可能失效的時候。**

用歷史上從沒見過的分數去查一條外推的曲線，等於在最不確定的時刻給出最有信心的數字。

### 3. 時間柵到期（label 0）算 P(−1)

```python
hits = (labels == 1)
empirical_prob = n_hits / n_samples     # 分母含 label 0
```

與 `Candidate.expected_return` 的保守假設一致——到期時實際報酬介於兩柵之間，這裡取最差情況。

若把 label 0 排除在分母外，P(+1) 會被高估（分母變小）。

## 反 look-ahead

**校準器只能用訓練期資料擬合。**

```python
CALIBRATION_TRAIN_END = date(2025, 12, 31)
cal_scores, cal_labels = build_calibration_set(bars_by_stock, CALIBRATION_TRAIN_END)
```

用全樣本擬合等於讓系統知道未來的命中率分布（CLAUDE.md 禁令 1）。

這是一個容易忽略的洩漏管道——校準看起來像「後處理」，但它其實是模型的一部分。

## 實測結果：momentum 基準幾乎沒有預測力

在 40 檔標的、2023-01 ~ 2025-12 訓練期、**10,243 筆樣本**上校準：

```
總樣本      10,243
基礎 P(+1)  0.1867
分數範圍    [0.2378, 0.7984]

分數區間                  樣本數    實際 P(+1)      落差
[0.238, 0.308]             100      0.1900     +0.0828
[0.308, 0.378]             623      0.1862     +0.1567  ⚠️ 過度自信
[0.378, 0.448]            1475      0.1654     +0.2476  ⚠️ 過度自信
[0.448, 0.518]            2101      0.1880     +0.2951  ⚠️ 過度自信
[0.518, 0.588]            2145      0.1599     +0.3932  ⚠️ 過度自信
[0.588, 0.658]            1902      0.2061     +0.4171  ⚠️ 過度自信
[0.658, 0.728]            1335      0.2090     +0.4843  ⚠️ 過度自信
[0.728, 0.798]             562      0.2206     +0.5428  ⚠️ 過度自信
```

### 兩個結論

**1. 分數的鑑別力極低。**

分數從 0.24 跑到 0.80（整個值域），實際機率只從 **19.0% 動到 22.1%**——**3 個百分點**。

這代表 `momentum_score` 幾乎無法區分「會達標」與「不會達標」的樣本。它產生的排序接近隨機。

**2. 過度自信達 0.54。**

最高分數箱的分數中位數 0.763，實際機率 0.221，落差 **+0.54**。

未校準時這些標的會以「P = 76%」通過 40.22% 門檻。校準後它們全部被擋下。

## 校準前後的對比：這是校準的全部價值

同一條管線、同一天、同一批資料：

| | 校準前 | 校準後 |
|---|---|---|
| 推播檔數 | **3 檔** | **0 檔** |
| 顯示的 P(先達標) | 60.5% ~ 64.6% | 最高 22.06% |
| 剔除原因 | `top_n_reached` 32 檔 | `below_entry_threshold` 29 檔 |
| 結論 | 「本週推薦 1303、3443、2303」 | **「本週無符合條件的標的」** |

**校準前的版本會推播三檔股票，配上看起來很有根據的 64.6% 機率。**

那三個數字是我用 `tanh` 映射出來的，與實際勝率無關。

校準後系統誠實地說：沒有任何標的的真實機率能覆蓋交易成本。

## 這個結果觸發了紅線

`CLAUDE.md` 的紅線（D7 修訂）：

> 若 Walk-Forward 的 OOS 勝率無法穩定站上 **40.22%**，這個策略族就是沒有優勢，
> 如實寫進報告，不進 Top 3。

實測：

```
基礎勝率           18.67%
最佳分數箱的勝率     22.06%
進場門檻           40.22%
```

**差距 18 個百分點。** momentum 基準沒有優勢，而且差很遠。

### 這是好消息還是壞消息

**是好消息。**

系統在**尚未投入任何真錢之前**，就用 10,243 筆歷史樣本證明了「這個策略沒用」。

對比 qlib-tw-trader：303 個因子、DoubleEnsemble、Optuna 調參、16 小時訓練，最後 live IC 是 **−0.0263**。而那個結論是在跑完 20 週完整回測後才浮現的。

校準讓「沒有優勢」這件事在 **10 秒內**、用一張表就說清楚。

## 可靠度報告的設計

```
分數區間                  樣本數    實際 P(+1)      落差  備註
[0.728, 0.798]             562      0.2206     +0.5428  ⚠️ 過度自信
```

四欄缺一不可：

| 欄位 | 為什麼需要 |
|---|---|
| 分數區間 | 定位是哪一段 |
| 樣本數 | 判斷這個機率可不可信（562 筆 vs 3 筆差很多） |
| 實際 P(+1) | 真正要用的數字 |
| 落差 | **過度自信一眼看得出來** |

「過度自信」（分數 > 實際機率）是**最危險的失準方向**——它讓不該進場的標的通過門檻。所以報告會明確標示並在結尾重申。

反方向「過度保守」也標示，但危害小得多（只是錯過機會）。

## 下一步：這個結果怎麼用

校準把問題從「模型準不準」變成一個可量化的目標：

```
現況：最佳分數箱 22.06%
目標：40.22%
需要提升：18.16 個百分點
```

ML 模型必須跨過這道門檻才值得採用。跨不過就是跨不過——調參數只會讓訓練期的數字變好看。

也可以反向思考：**降低門檻**。門檻 = (stop + cost) / (target + stop)，所以：

- 降低成本 → 降低換手率（拉長持有期）
- 提高 target/stop 比 → 但 R:R 已經是 2.6，再拉高目標會更難觸及

這兩條都指向同一個方向：**這個柵欄設定下的 5 日交易，成本佔比太高。**
