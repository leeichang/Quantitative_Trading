# 平手排序偏差與 E3 的 CPCV 結果

- 日期：2026-09-15
- 對應程式：`taiwan_quant/ranking/tie_break.py`、`scripts/diagnose_cpcv.py --scheme E3`
- 測試：707 passed（tie-break 之前 698）
- 原始輸出：`taiwan-quant/reports/cpcv_dev_h60.txt`、`cpcv_dev_h60_E3.txt`

## 兩個結論

### 1. 字母序 tie-break 讓動能突破虛增 17.5 pp

同一份資料、同一組參數，**只換 tie-break**：

```
策略族      修正前中位數   修正後    差異      修正前全距   修正後      差異
動能突破      +22.60%    +5.06%   −17.54 pp   269.50 pp  126.42 pp  −143 pp
籌碼跟隨      +47.12%   +43.49%    −3.63 pp   197.17 pp  176.53 pp   −21 pp
均值回歸      +22.03%   +28.73%    +6.70 pp   189.73 pp  174.17 pp   −16 pp
```

**三族的全距全部下降。** 動能突破降幅最大——它從低代號偏差裡拿到的好處
最多，所以修掉之後掉最兇。

### 2. E3 沒有解決路徑變異，而且 PBO 更糟

```
機制        動能突破全距   籌碼跟隨   均值回歸   PBO
slot        126.42 pp    176.53    174.17   0.629
E3          187.23 pp    191.16    152.11   0.857   ⚠️
驗收目標      數十 pp
```

**兩個機制都沒達標，E3 還更差。** PBO 0.857 遠超過 CLAUDE.md 的 0.5 門檻。

E3 的 5% 分位仍然是負的（−16.86% / −6.99% / −27.36%）——切分方式換一種
就從賺變賠。

## 為什麼字母序是 bug 而不是慣例

三個地方都用同一個排序鍵：

```python
sorted(candidates, key=lambda s: (-s.rank_score, s.stock_id))
#                                               ^^^^^^^^^^^
# thresholds.py:41（E1）、thresholds.py:82（E3）、portfolio_sim.py:250（槽位）
```

看起來只是「確保可重現」，實測不是。動能突破在開發集有 33,900 筆通過門檻
的候選，但**只有 12 個相異 `rank_score`**：

```
CALIBRATION_BINS = 6        ReturnCalibrator.predict() 回傳的是箱平均值
× 2 個流動性分層（成本不同）
= 12 個相異值
```

從 ~150 檔選 Top 3，第 3 名平均有 **3.8 檔同分**：

```
2017-01-11  候選 133｜與第 3 名同分 3 檔｜選中 ['1707', '2345', '3008']
2019-06-27  候選 146｜與第 3 名同分 6 檔｜選中 ['2303', '2379', '1102']
2021-02-18  候選 144｜與第 3 名同分 6 檔｜選中 ['2301', '2303', '2344']
```

**Top 3 裡通常有 1~2 個位置是股票代號決定的，不是訊號決定的。**

### 代號不只無資訊，它有偏

| 次要鍵 | 與報酬相關 | 可重現 | 可量測任意性 |
|---|---|---|---|
| `stock_id` | 否，但**與公司特性系統性相關** | 是 | **否** |
| 確定性抖動 | 否 | 是 | **是** |

台股代號與上市年份、產業、規模都相關。用它破平手等於在模型裡偷偷塞進
一個沒有宣告的因子——而上面那 17.54 pp 就是它的實際影響。

更關鍵的是**可量測性**。抖動帶 seed 之後，換 seed 重跑就知道有多少結果
來自平手運氣。字母序給你一個任意答案，而且沒有辦法知道它有多任意。

### 為什麼不用內建 `hash()`

CPython 的 `hash(str)` 每個行程換一次 salt，同一份程式今天跑跟明天跑會
排出不同順序，回測就不可重現（違反禁令 7、8）。

用 `blake2b`，跨行程、跨平台、跨版本都穩定。測試裡真的另開一個行程驗過。

### 這修的是偏差，不是變異

抖動讓平手不再偏向低號碼，但**平手本身還在**。全距從 269 降到 126 pp，
離「數十 pp」還很遠。

真正的解法是讓 `rank_score` 有更高的解析度——**12 個等級排 150 檔本來
就太粗**。這個模組只保證：分不出來的時候，不要假裝分得出來，也不要偷偷
用一個有偏的代理。

## E3 為什麼沒用

Codex 的 E3 把訊號／成交比從 435:1 壓到 1:1，那是真的。但：

```
slot   訊號進佇列，槽位空出來才成交      99.8% 被擋掉
E3     每 60 個交易日固定選 Top 3       佇列消失，57/57
```

**1:1 不代表門檻開始篩選，是佇列不存在了。** 而路徑變異的來源有兩個：

| 來源 | E3 解決了嗎 |
|---|---|
| 槽位何時釋放（排隊順序） | ✅ 消除了 |
| 平手時誰勝出（tie-break） | ❌ 還在 |

第二個沒解決，所以全距沒降。實測 187 / 191 / 152 pp，跟 slot 同一個量級。

而 PBO 從 0.629 惡化到 0.857——E3 讓每個節點都強制選 Top 3，等於把
「12 個等級排 150 檔」這個解析度問題放大了：以前佇列會過濾掉一部分，
現在每 60 天都要從一堆同分的候選裡硬挑 3 檔。

## 對任務的影響

### 任務 E 未達標

```
□ 訊號／成交比 ≤ 10:1              ✅ E3 達成（1:1）
□ CPCV 全距 ≤ 數十 pp              ❌ 152 ~ 191 pp
```

**第二條沒達成，任務 E 不算完成。** 工作單寫得很明白：訊號／成交比是
手段，路徑變異才是目的。

### 任務 G 不該現在做

PBO 0.857（E3）與 0.629（slot）都超過 0.5。CLAUDE.md：
**PBO > 0.5 → 判定過擬合，不得進入 Top 3 排名。**

在這個數字降下來之前，pseudo-OOS 跑出來只會是「未被否定」，價值有限。

### 下一步應該是提高 rank_score 的解析度

問題根源不是機制，是**排序解析度**：12 個等級排 150 檔。可能的方向：

| 方向 | 代價 |
|---|---|
| 提高 `CALIBRATION_BINS` | 每箱要 ≥ 50 樣本，6 → 12 箱需要兩倍樣本 |
| 用連續模型取代分箱（Ridge / LightGBM） | CLAUDE.md 說先有 LightGBM baseline，還沒做 |
| 排序改用原始分數，校準只當門檻 | 假設「校準器分不出來的差異，原始分數分得出來」，需先驗證 |

第三個最便宜，而且可以用 `diagnose_rank_ic.py` 先驗證原始分數在箱內是否
還有排序能力——**如果有，這就是解法；如果沒有，前兩個方向也救不了。**

## DSR 通過但不要當成好消息

```
E3     觀察到的年化 Sharpe 0.9258   運氣門檻 0.4264   DSR 0.9933   通過
slot   （見 reports/cpcv_dev_h60.txt）
```

DSR 通過只代表「掃 3 個策略族這件事本身，不足以用運氣解釋 0.9258」。

**PBO 0.857 同時說：樣本內選出來的贏家，樣本外有 86% 的機率落到中位數
以下。** 兩者衝突時以 PBO 為準——它量的是選擇過程有沒有資訊，那才是
這裡的關鍵問題。

## 限制

### 成交層級的平手稽核

彙總的訊號數與成交數無法回答「最後是哪幾檔因平手而入選」。因此門檻掃描
JSON 現在會在每個方案下保存 `transactions`，逐筆列出：

- `stock_id`
- `entry_date` / `exit_date`
- `rank_score`
- `tie_count`（選股當下與該分數完全相同的完整候選數）

`tie_count` 在 Top N 截斷前計算，不能只對勝出的股票重算；例如三檔同分
取二檔，兩筆成交都必須記為 3。欄位隨訊號進入組合模擬器，只有實際成交
並平倉的交易才寫入 JSON，避免把候選誤報成成交。

⚠️ CPCV 的 15 條路徑**不是 15 個獨立樣本**，共用同一份歷史。
用它否定比用它肯定可靠得多。

⚠️ CPCV 的訓練集會用到測試段之後的資料（違反禁令 5），**不能宣稱實盤
表現**。實盤模擬仍然要用 `validate_oos_trailing.py`。

⚠️ 本次全部跑在開發集（`--end 2023-12-29`），2024 之後完全沒載入，
符合禁令 6。
