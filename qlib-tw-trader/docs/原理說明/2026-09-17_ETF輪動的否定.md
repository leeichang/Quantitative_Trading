## 為什麼往 ETF 看

所有股票策略都撞同一面牆：

```
              來回成本    年化成本拖累
股票 N=10 H=40  1.081%      6.8%
ETF  整股 H=120 0.571%      1.2%     ← 5.7 倍
```

**40 萬做 1.08% 的來回，年化先送掉 6.8%**，而台股長期報酬約 12~16%。
一個 1 pp／年的優勢在 ETF 區間活得下來，在股票區間活不下來。

這個結構論證不依賴任何回測數字，所以值得投入。

## 第一版的結果無效：流動性

8 檔 ETF 跑輪動得到年化 12.5%、MaxDD −16.1%，看起來比任何單一買進持有的
回撤／報酬比好 1.5~2 倍。

**但 6 檔吃不下 40 萬的部位。** 開發集（2015-01 ~ 2023-12）的日成交額中位
與 133,333 元部位的佔比：

```

```

對照：股票策略實證「4 萬元部位對當日成交額中位僅 98.9 ppm」= **0.0099%**。

**0053 的一個部位佔掉當日成交額的 27.4%**（一天只成交約 19 張）。

跳動單位毫無意義——那時決定價格的是你自己。

### ⚠️ 我差點犯的 look-ahead

先量的是 2024 年之後的流動性：

```
代號   2024 後日成交額中位   開發集期間日成交額中位
0052       1.92 億              667 萬     ← 後來才長大
0053        203 萬               49 萬
0051        730 萬              102 萬
```

0052 在 2024 年後看起來完全夠。**但它是後來才長大的。**
用今天的流動性合理化 2015-2023 的回測，本身就是 look-ahead。

**篩選一律用回測期間本身的流動性。**

### 通過的只有兩檔

```
篩選條件   部位佔比中位 < 0.1%  且  佔比 > 1% 的天數 < 5%
通過       0050、0056
```

兩檔的「輪動」是一個二元傾斜（大盤 vs 高股息），不是策略空間。
但它是唯一流動性站得住的版本，而且參數空間小 → 多重測試懲罰也小。

## 正式檢定：0050 vs 0056

開發集 2015-01-05 ~ 2023-12-29，2,197 交易日。兩檔在 40 萬全押下都買得起
整張（0050 一張約 13.5 萬），所以整股比例 100%。

```
來回成本   稅 0.3% → 0.571%    稅 0.1% → 0.371%
試驗數     16（4 個回看 × 4 個持有期）
```

### walk-forward（回看期由訓練窗選，不是我指定）

   20    89  1.27%  0.70%   7.2%    9.9%   0.47  −31.1%
   40    40  2.43%  1.86%  10.6%   12.0%   0.65  −27.7%
   60    24  3.91%  3.34%  12.6%   13.5%   0.68  −21.8%
  120     8  3.64%  3.07%   5.7%    6.2%   0.47  −14.8%
```

### 必跑對照組

```
0050 買進持有            總報酬 209.85%   年化 15.3%   MaxDD −33.8%

## 三個獨立的否定依據

### 1. PBO 全部超過紅線

```
    H      PBO     判定
   20    0.750    過擬合
   40    0.750    過擬合
   60    0.625    過擬合
  120       —     期數 16 < 32，CSCV 無法切分
```

CLAUDE.md：**PBO > 0.5 → 判定過擬合，不得進入 Top 3 排名。**

### 2.「選參數」這件事本身沒有資訊——這是最直接的證據

```
    H  walk-fwd   固定20   固定60  固定120  固定250
   20      7.2%    6.9%    5.4%    5.7%    8.8%   輸
   40     10.6%    9.9%    9.0%   10.9%   12.4%   輸
   60     12.6%   14.4%   12.1%   14.9%   14.0%   輸
  120      5.7%   13.2%   13.3%   13.3%   14.6%   大輸
```

**4 個持有期裡 walk-forward 全部輸給固定回看期。**

PBO 是間接推論（「樣本內的贏家在樣本外會不會落到中位數以下」），
而這張表是**直接量到的**：從訓練窗挑參數比隨便固定一個還糟。

H=120 最戲劇化——walk-forward 給 5.7%，而任何固定回看期都給 13.2~14.6%。
選擇機制主動摧毀了它。

### 3. 唯一贏的地方可以更便宜地取得

H=60 的 MaxDD −21.8% 確實比 0050 的 −33.8% 好。但：

```
70% 0050 + 30% 現金    年化約 10.7%   MaxDD 約 −23.7%   不需要任何策略
ETF 輪動 H=60          年化    12.6%   MaxDD    −21.8%   PBO 0.625
```

差距約 2 pp，而 PBO 說那 2 pp 不可重現。

## ⚠️ 我在這次檢定中犯的兩個錯（第一個會翻轉結論）

### 錯誤一：DSR 的 `sharpe_std` 用了預設值

`deflated_sharpe_ratio(observed_sharpe, n_trials, n_observations, sharpe_std=1.0)`
的第四個參數預設是 1.0，意思是「各試驗的 Sharpe 橫斷面標準差是 1.0」。

本次 16 個試驗的 Sharpe 落在 0.47~0.68，**實測標準差是 0.1958**：

```
sharpe_std = 1.0（預設）     運氣的期望最佳 Sharpe = 1.799   DSR 0.0000   全部不通過
sharpe_std = 0.1958（實測）   運氣的期望最佳 Sharpe = 0.180   DSR 0.88~0.99  全部通過
```

**這個參數直接決定結論。** 用預設值我會報出一個假的否決。

改用實測值之後 DSR 反而通過，但 PBO 不通過。專案先前已定案
（`2026-09-15_平手排序偏差與E3的CPCV結果.md`）：

> 兩者衝突時以 PBO 為準——它量的是選擇過程有沒有資訊，那才是關鍵問題。

而這次 walk-forward 的直接比較**獨立證實了 PBO**，不是只能靠慣例決定。

這與先前 `n_observations` 餵錯兩次是同一類錯誤：**統計函式的每一個輸入
都要有實測依據，預設值不是依據。**

### 錯誤二：決策網格沒對齊

第一版用 `start = max(lookback, 1)`：

```
回看 20  的決策日   20, 20+H, 20+2H, ...
回看 250 的決策日  250, 250+H, 250+2H, ...
```

兩個網格只在 (250−20) = 230 是 H 的倍數時才重合。H=20 時 230/20 = 11.5，
**交集是空的**，walk-forward 一律回報「測試期不足」。

所有候選必須跑在同一個決策網格上，否則比較的不是同一段歷史。
已修並加測試釘住。

### 以及上一輪的「年化 81.8%」

第一版 8 檔測試跑出年化 81.8%。那不是發現，是索引錯位：

```python
cl = cl.dropna(how="any")     # cl 被過濾了
cl.iloc[i] / op.iloc[i + 1]   # 但 op 沒有 → iloc 位置對應到不同日期
```

修正後是 12.5%。**這就是為什麼輪動邏輯要從臨時腳本抽成有測試的模組**
（`ranking/etf_rotation.py`），而 `aligned_views()` 存在的唯一理由就是
擋住這個。
