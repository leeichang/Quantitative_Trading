## 要回答的問題

修完 tie-break 後，CPCV 全距從 269 降到 126 pp，離驗收目標「數十 pp」
還很遠。根源是排序解析度：`rank_score` 只有 12 個相異值要排 150 檔。

三個解法，第 3 個最便宜：

```
1. 提高 CALIBRATION_BINS
2. 換連續模型（Ridge / LightGBM）
3. 排序改用原始分數，校準只當門檻   ← 前提：箱內還有排序能力
```

**這份文件驗證第 3 個的前提。答案是沒有。**

---

## 答案：0 / 18 箱有箱內排序能力

開發集 2015-01 ~ 2023-12、持有 60 日、單箱單日最少 12 檔：

```
策略族      達 |t| > 2 的箱   箱內 |平均 IC| 的平均
動能突破        0 / 6              0.0292
籌碼跟隨        0 / 6              0.0129
均值回歸        0 / 6              0.0221
```

最高的 t 值是動能突破箱 2 的 +1.17，離 2.0 還很遠。

**分數的資訊已經被分箱吃乾了。** 換排序鍵沒用（解法 3 死），加更多箱
也救不了（解法 1 死）——箱內本來就沒有東西可以再切出來。

## 更重要的發現：優勢集中在一個很薄的箱

跑這個診斷時順手印了箱本身的樣子，那才是真正的問題所在。

### 動能突破

```
箱    分數區間              樣本      箱平均報酬
0    [0.014, 0.179)      1,597       7.53%   ← 排序會選這個
1    [0.179, 0.343)      7,018       2.67%
2    [0.343, 0.507)     16,893       2.29%
3    [0.507, 0.671)     17,086       2.62%
4    [0.671, 0.836)      8,399       3.33%
5    [0.836, 1.000)      2,889       4.69%
```

### 三族並列

| 策略族 | 排序會選哪箱 | 該箱報酬 | 占候選比例 | 每期平均檔數 | 扣成本後 |
|---|---|---:|---:|---:|---:|
| 動能突破 | 箱 0 | 7.53% | **3.0%** | **4.3 檔** | +6.26% |
| 均值回歸 | 箱 5 | 7.45% | **1.2%** | **1.7 檔** | +6.18% |
| 籌碼跟隨 | 箱 3 | 3.37% | 14.2% | 18.4 檔 | +2.10% |

**整個策略的優勢都來自一個薄箱。**

均值回歸每期只有 1.7 檔落在最佳箱，但 Top 3 需要 3 檔——大部分期數根本
湊不滿，只能往下溢到 2.66~3.00% 的中間箱。

這**完整解釋了路徑變異**：標的池一動，落進那個薄箱的名單就換人，而整條
權益曲線幾乎全靠那幾檔。v6/v7 補 23 期快照就擺盪 −831 pp，來源就是這裡。

## 一個更正

我第一眼看到「最低分箱報酬最高」時說「排序方向錯了」。**那是錯的。**

`ReturnCalibrator.predict()` 回傳的是**箱平均報酬**，不是分數本身：

```python
return bucket.mean_return
```

所以 `rank_score = predict(score) − cost`，排序會正確選中報酬最高的箱
（動能突破的箱 0）。校準器不需要 score 與報酬單調相關——它學的就是
那個映射。

分數與報酬非單調（三族都是 U 型或倒 U 型）代表**原始分數是個弱訊號，
只在極端值有效**，但校準器處理得對。

## 查到的不一致：回測不檢查鑑別力

```python
DISCRIMINATION_MIN_SPREAD = DEFAULT.round_trip_rate(Tier.LARGE)   # 1.071%

@property
def has_discrimination(self) -> bool:
    """差距是否大到足以覆蓋交易成本"""
    return spread is not None and spread >= DISCRIMINATION_MIN_SPREAD
```

實測：

```
策略族      箱間全距    has_discrimination
動能突破     5.24 pp         True
均值回歸     4.79 pp         True
籌碼跟隨     0.54 pp         False   ⚠️
```

**籌碼跟隨的箱間差異只有 0.54 pp，不到來回成本 1.271% 的一半。**
校準器自己判定它沒有可用的鑑別力。

但是：

```bash
$ grep -rn "has_discrimination" --include="*.py" .
scripts/weekly_plan_trailing.py:312:    if not calibrator.has_discrimination:
```

**只有產出週計畫的腳本會檢查，回測與驗證路徑完全不檢查。**

後果：

| | 籌碼跟隨 |
|---|---|
| 回測（`validate_oos_trailing.py`） | 照跑，+75.03%、Sharpe 0.64 |
| CPCV 中位數 | +48.47%，**三族最高** |
| 實際推播（`weekly_plan_trailing.py`） | 會被 `has_discrimination` 擋掉 |

**回測在衡量一個實盤不會做的策略。** 而且它剛好是 CPCV 中位數最高的那個
——如果只看回測排名，會選中一個上線就被擋掉的策略族。

這與禁令 3、4 是同一類問題：成本相關的判定必須貫穿整條路徑，不能只在
最後一哩擋一次。

## 對三個解法的結論

| 解法 | 狀態 | 理由 |
|---|---|---|
| 1. 提高 `CALIBRATION_BINS` | ❌ 死 | 箱內沒有資訊可切，0/18 箱達 t > 2 |
| 2. 換連續模型 | ⚠️ 唯一剩下的 | 見下面的保留 |
| 3. 排序用原始分數 | ❌ 死 | 同上，這就是本次驗證的直接結論 |

### 解法 2 的保留

箱內 IC = 0 說的是「**這個手工分數**在箱內沒有排序能力」，不是「特徵裡
沒有資訊」。分數是特徵的手工組合，連續模型直接吃特徵有可能找到更多。

但不要期待太高：

```
籌碼跟隨的箱間全距 0.54 pp，來回成本 1.271%
```

就算完美選箱，籌碼跟隨的可用差距也不到成本的一半。**這一族的問題不是
模型，是特徵本身沒有足夠訊號。**

動能突破與均值回歸的箱間全距（5.24 / 4.79 pp）確實覆蓋得了成本，但優勢
擠在 1.2~3.0% 的候選裡，**樣本薄到估計值本身就不可靠**——那 7.53% 是
1,597 個樣本算出來的，且箱內 t = 0.18。

## 建議的下一步

不是「上 LightGBM」。是先回答一個更基本的問題：

> **動能突破箱 0 的 7.53% 是真的，還是 1,597 個樣本的雜訊？**

便宜的檢查：

```
1. 把箱 0 逐年拆解——如果集中在某一兩年，就是雜訊
2. 用 CPCV 的 15 條路徑分別算箱 0 的報酬，看分布
3. 檢查箱 0 的組成：是不是集中在少數幾檔或某個產業
```

⚠️ 這些都在開發集做（`--end 2023-12-29`），不動評估區間。

如果箱 0 的優勢站得住，方向是**提高那個箱的候選密度**（每期 4.3 檔太少），
而不是提高全體的排序解析度。如果站不住，那三族都沒有可用優勢，
應該如實寫進報告。

## 限制

⚠️ 箱內 IC 用的是全樣本擬合的校準器（不切分），因為要問的是「箱內還有
沒有資訊」這個結構性問題，不是樣本外表現。**這個數字不能當成 OOS 結論。**

⚠️ 單箱單日最少 12 檔的門檻會排掉薄箱的多數日子：動能突破箱 0 只有 36
期達標（共 ~370 期），有效期數 3.0。**那一箱的 IC 本身就很不可靠**——
但這剛好也是它的問題：薄到算不出統計量。

⚠️ 全部跑在開發集，2024 之後完全沒載入，符合禁令 6。
