## bug 是什麼

三個檔案用 `closes.shift(-1 - horizon)`，也就是 T+1+horizon 收盤出場。

```
models/lgbm_baseline.py
scripts/validate_lgbm_baseline.py
scripts/validate_hand_scores_vs_uninformed.py
```

而另外三個檔案用 `closes.shift(-horizon)`：

```
scripts/diagnose_constraints.py
scripts/diagnose_cost_floor.py
scripts/diagnose_position_costs.py
```

### 哪一個對

T+1 開盤進、X 收盤出，持有天數 = X − T。要 horizon 天就是 **X = T + horizon**。

專案自己的算術也證實：CLAUDE.md 的持有期表寫「20 日 → 每年 12.6 趟」，
252 / 20 = 12.6；若是 21 天會是 12.0。

而 Codex 在工作單 08 建立的 `data/integrity.holding_dates` 是單一來源：

```python
entry_index = decision_index + 1
target_index = decision_index + holding_days
```

**所以 `shift(-horizon)` 對，我的 `shift(-1 - horizon)` 多算一天。**

### 我的測試把錯的慣例釘住了

```python
def test_label_matches_the_backtest_definition():
    # 斷言 closes[2] / opens[1]，也就是 T+1+horizon
    assert value == pytest.approx(13.0 / 11.0 - 1)
```

程式與測試是同時寫的，兩邊照同一個誤解，所以測試通過而行為是錯的。
**測試驗證了我的理解，不是行為。**

現在改成斷言 `closes[1] / opens[1]`，並加了第二個測試直接把出場日對齊
`holding_dates`——不再各自算。

## 規格怎麼改

`CLAUDE.md` 的「必跑對照組」在 2026-09-17 加了第四條「無資訊對照組」，
理由是「隨機進場太弱」。**那個理由不成立了。**

但**做法要保留**，理由換掉：

```
2026-09-17 的理由（錯）  隨機對照組太弱，一個無資訊的模型也能顯著贏它
2026-09-18 的理由（對）  置換檢定是管線的驗證。它現在「通不過」
                        （打亂 − 隨機 = −0.01%，t = −0.02），
                        那正是我們要的結果——證明優勢不是來自洩漏
```

一個通不過的置換檢定是**好消息**：它說模型的優勢來自特徵與標籤的關係，
不是來自切分或索引的洩漏。而它先前「通過」（打亂仍顯著贏隨機）才是
警訊——那時我誤讀成「對照組太弱」，實際是「標籤算錯」。

## 對 LightGBM 結論的更正

2026-09-17 我寫「模型沒有贏」。**對正確的虛無假設，它贏了而且顯著：**

```
真模型 − 打亂 = +3.14%／趟   SE 1.11%   t = 2.82
```

但仍然有三個限制，方向不變：

```
⚠️ 真模型 − 手工 = +0.61%，t = 0.30——**與手工分數無法區分**
⚠️ 前 10 檔與手工分數重疊中位 1 檔、10/36 期完全不重疊
   兩者同意因子、不同意名字
⚠️ DSR 1.0000 毫無意義（n_trials = 1 時運氣門檻退化為 0）
⚠️ 36 期，SE 1.11 pp。t = 2.82 是單一未調參配置的結果，
   一旦開始掃超參數，多重測試懲罰會回來
```

**所以正確的說法是「LightGBM 對無資訊對照組有可量測的優勢，但它與手工
分數之間量不出差別」**——而不是「模型沒有用」。

## 為什麼那一天的差異這麼大

隨機選股那一組只掉 0.48 pp（+1.05% → +0.57%），而標籤打亂那一組掉了
2.38 pp（+2.94% → +0.56%）。不是一致的位移。

原因：打亂的模型是在 `forward` 的**橫斷面排名**上訓練的。改變 `forward`
一天就改變標籤，改變標籤就改變擬合出來的函數，也就改變它選的名字。
所以那一組不只報酬變，**選股也變**。

隨機那一組的選股與 `forward` 無關，所以只受報酬本身影響。

⚠️ 這是機制推論，不是實測。要確認需要比對兩個版本各自選出的名字。
