## 修掉的 bug：可負擔性用還原價

`config.costs.resolve_tier` 用 `amount >= price * LOT_SIZE` 判斷整股。
N=10 時 `amount = 40,000`，門檻是股價 **40 元**。

但回測傳進去的是**還原價**。`load_prices(adjusted=True)` 用 `adj_close`
覆寫 `close` 並同比例調整 OHL，實際價就被丟掉了。

還原是**回溯調整、錨在最新日**，所以越早的日期還原價越低：

```
年度   還原/實際平均   40 元門檻分層錯邊的比例
2016      0.8666          13.41%
2020      0.8715          10.89%
2024      0.9259           3.46%
```

開發集（2015~2023）正是落差最大的那一段。

### 修正後的差異

```
                     修正前     修正後      差異
整股比例（N=10）      39.4%     26.1%    −13.3 pp
平均來回成本          0.913%    0.967%   +0.054 pp
```

### ⚠️ 我在工作單裡把幅度寫大了

`06_Codex工作單` 寫「成本被低估 **0.4 pp/趟**」。那是**單檔分層的差**
（零股 1.071% vs 整股 0.671%），不是投組平均。

投組平均只有 **0.054 pp/趟**——因為只有 13.3% 的名字會翻邊。

方向判斷是對的（低估成本、對策略有利），量級寫錯了 7 倍。

### 解法：兩種價格各有明確欄位

```
close      / open        還原價    報酬用（禁令 12）
raw_close  / raw_open    實際價    可負擔性用
```

只保留 open 與 close，因為只有它們做交易決策（進場 T+1 開盤、
出場 T+H 收盤）。high / low 只進 ATR 與柵欄寬度，那些是**比例**運算，
用還原價才對。

**兩欄一律存在**（`adjusted=False` 時相同），呼叫端不需要 `if adjusted`
分支——少一個分支就少一個忘記處理的可能。

### 前推帳本不受影響，但現在是構造上正確

決策日當天兩價相同（實測 10 檔落差全部 0.0%），因為還原錨在載入範圍的
最後一天。**但那是巧合不是保證**：換一個 `end`、或錨定日之後有除權息，
就會分開。

所以 `record_forward.py` 現在明確用 `raw_close`，而且兩價差超過 1% 就
拋錯。`entry_price` 也改記實際價——那是使用者拿去下單看的數字。

## 順手修掉的潛在崩潰

`_apply_adjustment` 在整檔沒有還原價時會拋
`TypeError: ufunc 'isfinite' not supported`——`adj_close` 全 NULL 被
SQLite 讀成 object dtype。

而那個函式的說明明寫「整檔完全沒有還原價時保留原價」，**所以那條路徑
應該走得通**。

目前資料庫 1,218 檔全部有還原價，所以這是潛在而非現行故障。但還原價是
`adj_backfill_log` 那個獨立步驟補的，**新上市股在補完前就會踩到**。

### 三個槓桿，效力差 20 倍

```
槓桿              可挖空間（成本/趟）    可挖空間（年化成本）
持有期 H           0.02 pp（幾乎無）     4.5 pp   ← 最大
檔數 N             0.28 pp               1.7 pp
手續費折扣         0.185 pp              1.2 pp   ← 最小
ETF 納入           0                     0
```

**H 幾乎不改變每趟成本，但它直接除以趟數。** 這就是 CLAUDE.md
「持有期不得低於 60 個交易日」那條的來源。

N 改變的是整股比例（69.4% → 10.1%），也就是每趟成本。

手續費折扣最小：

```
折扣     成本/趟    vs 6 折
1.00    1.081%   +0.114%
0.60    0.967%   +0.000%
0.28    0.896%   −0.071%
```

**談到 2.8 折只省 0.071 pp。** 不值得花時間。

## ETF 納入完全沒效果，而且不是接線錯誤

含 ETF 與不含 ETF 的結果**逐欄完全相同**。這有兩種可能原因，意義完全不同：

```
接線錯誤   ETF 沒進候選池      → 要修
排不進去   ETF 在池裡但排太後   → 這個槓桿本來就沒用
```

查了，是後者：

```
     出現期數   排名中位   最佳   進前 10 的期數
0050    36       73      24        0
0051    35       64      16        0
0056    35       67      27        0
```

**每期都在候選池、都有分數，但從來沒進前 10。** 史上最佳第 16 名。

結構性原因：**分散的一籃子在定義上不會出現動能突破。** 所以
`--include-etfs` 這個旗標對動能突破族是死的。

`is_etf` 與 ETF 成本分層仍然需要——必跑對照組要用。但上一次把 ETF
加進標的池那件事，對選股沒有產生任何效果。

## ⚠️ 我在這份診斷裡犯的錯：跨持有期做了配對檢定

第一版把每一格都對現行 (N=10, H=40) 做配對差異，結果 20 格裡有 3 格
`|t| > 2`，**全部是 H=120**：

```
N=10, H=120   +15.13%   SE 6.97%   t = 2.17   顯著較好
N=15, H=120   +13.93%   SE 6.27%   t = 2.22   顯著較好
N=20, H=120   +11.87%   SE 5.51%   t = 2.15   顯著較好
```

那個「顯著」是假的。`net_per_trip` 在 H=40 是 **40 日報酬**、在 H=120 是
**120 日報酬**。相減再叫「淨差異」等於在量持有期長度，不是量參數好壞。

修正成**只在同一個 H 之內比較不同的 N**，結果 16 組全部「量不出差別」：

```
N=3,  H=40    +2.65%   SE 2.51%   t =  1.06
N=20, H=40    −1.58%   SE 0.94%   t = −1.69
N=5,  H=120   −6.70%   SE 3.56%   t = −1.88
（其餘 13 組 |t| 更小）
```

跨 H 只能看年化欄，而且**不是配對的**：決策日不同、期數不同
（H=120 只有 12 期）。H=120 的判定早就有了——**PBO 0.971、DSR 算不出來**。

## 對「週頻抓漲停」的結論

把成本壓到地板之後重算：

```
最高 1% 分位的 5 日毛報酬      0.85%
成本地板（N=3，整股 69.4%）    0.793%
淨                            +0.057%/趟 × 50.4 趟 ≈ +2.9% 年化
```

**從明確為負推到損益兩平附近，但沒有推到可用。**

而且這個算式把兩個不同樣本混在一起（0.85% 是「最高 1% 分位的所有名字」，
0.793% 是「N=3 取前三名」），所以連 +2.9% 都不該當數字看。

真正的結論：

```
降成本可挖的空間   年化 4.5 pp（H），1.7 pp（N）
取得它的代價       H=120 只剩 12 期（PBO 0.971）
                  N=3 只剩 144 筆樣本、逐年 4/6 為正
```

**降成本的空間是真的，但拿它的方式會直接抵銷統計證據。** 這不是取捨
沒做好，而是 40 萬資金在台股成本結構下的實際邊界。
