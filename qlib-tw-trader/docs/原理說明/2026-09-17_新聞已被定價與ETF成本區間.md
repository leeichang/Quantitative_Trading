- 日期：2026-09-17
- 起點：使用者提問「不能預測漲停，還有什麼方式？新聞的影響比任何因素都大，能收集新聞嗎？」
- 對應資料：`history.db` 開發集（2015-01 ~ 2023-12-29）
- 這份文件同時記錄**三個否定結論**與**一個值得往下走的方向**

---

## 先講結論

| 主張 | 判定 |
|---|---|
| 新聞的影響比任何因素都大 | ✅ 成立——**但它在落地當天收盤就反映完了** |
| 收集新聞可以加進判斷 | ❌ 無法誠實回測，且實測超額不足以覆蓋成本 |
| 三個策略族合成訊號 | ❌ 動能與均值回歸是 −0.505 負相關，平均會落到最差的中段 |
| ETF 輪動比股票策略有機會 | ❌ 見 `2026-09-17_ETF輪動的否定.md` |

## 一、新聞：影響很大，但不是我們能拿到的那一段

### 用機械足跡代替新聞本身

新聞落地會留下痕跡：爆量、外資大買、當日大漲。這些在資料庫裡有**乾淨的
時戳**，不需要爬新聞就能量。

而我們實際的執行方式是**盤後決策、T+1 開盤進場**。所以問題變成：
事件當天的移動，隔天開盤還剩多少？

```
事件（T 日）                 樣本      T 日當天   T+1開→T+20收   超額    成本      淨
當日漲>5% 且量>3 倍        3,699     +7.71%      +1.87%    +0.58%  1.08%  −0.50%
當日漲>5% 且外資買超>3 倍    2,665     +7.50%      +1.96%    +0.68%  1.08%  −0.40%
當日漲>7% 且量>5 倍          939     +9.13%      +1.89%    +0.61%  1.08%  −0.47%
外資買超>10 倍               362     +4.50%      +1.15%    −0.13%  1.08%  −1.21%
基準（全部名字·全部日）   540,942     +0.07%      +1.28%       —       —       —
```

「超額」是扣掉基準漂移（+1.28%/20 日，開發集是多頭期）之後的部分。

**事件當天漲 4.5% ~ 9.1%，從 T+1 開盤起算只剩 0.58 ~ 0.68 pp，而來回成本
1.08%。全部為負。**

樣本 939 ~ 3,699 筆對照 540,942 筆基準，不是雜訊。

### 「外資買超 > 10 倍」是反轉，不是延續

當天 +4.50%，20 日超額 **−0.13%**。極端的外資買超之後是回吐。
這與「跟著法人走」的直覺相反。

### 所以新聞的用法只有一個

**技術上拿得到**（Exa / WebSearch / agent-reach 都在），但有兩道牆：

#### 牆一：無法誠實回測

```
搜尋引擎回的是「現在的相關性排序」，不是 2018 年當時看得到的東西
文章會被改標題、改內容、刪除
後來崩掉的公司，回頭看報導量被放大（倖存者偏差的鏡像）
```

最致命的是**我讀 2018 年的新聞時已經知道 2019 年發生什麼**。時戳再準也
擋不住這個污染——那是詮釋層的 look-ahead，違反禁令 1 而且無法用程式檢查。

#### 牆二：就算能回測，上表說它不會有用

新聞要賺錢必須比市場快。盤後決策、隔日開盤進場，**結構上不可能快**。

#### 站得住的用法：當否決條件，不當訊號

財報延遲、重大訴訟、經營權爭議的名字不持有。**那是風控，不需要回測背書。**

#### 真要讓它可測，只有一條路

**現在開始存帶時戳的新聞檔，跟前推帳本一樣不可改寫。** 一兩年後才有能測
的東西。慢，但那是唯一不被污染的方式。

## 二、三族合成訊號：不可行，而且原因是機制性的

三個策略族一直分開測，從未測過合起來。而「優勢集中在 1.7 ~ 4.3 檔」那個
脆弱性，合成訊號看起來正好對症。

實測（36 個決策期、時點標的池）：

```
配對                  Spearman 中位   前 10 重疊中位   完全不重疊的期數
動能突破 / 均值回歸        −0.505            0          34/36
籌碼跟隨 / 均值回歸        −0.320            0          28/36
動能突破 / 籌碼跟隨        +0.526            3           3/36
```

**動能突破與均值回歸是強負相關，34/36 期選出完全不重疊的名字。**
機制上本來就相反：一個買漲過的，一個買跌過的。

所以**排名平均會把兩個相反的排序平均到分布中段**，而實測中段是最差的區域：

```
分位桶      5 日漲停率
0%~50%        0.83%
50%~80%       0.62%   ← 比最低 50% 還差
99%~100%      8.38%
```

排名平均這條路不用做。

### 但 −0.505 有另一個用途

**它們是互相分散，不是互相競爭。** 分成兩個 sleeve 各半資金，降低投組變異
不需要任何一邊變強。

代價是稀釋：均值回歸年化淨 5.2%、籌碼跟隨 12.3%，都遠弱於動能突破。
Sharpe 會不會改善是可測的，尚未測。

## 三、ETF：成本區間確實便宜，但故事不在這裡

所有股票策略都撞同一面牆：

```
              來回成本    年化成本拖累
股票 N=10 H=40  1.081%      6.8%
ETF  整股 H=120 0.571%      1.2%     ← 5.7 倍
```

**40 萬做 1.08% 的來回，年化先送掉 6.8%**，而台股長期報酬約 12~16%。
這是為什麼所有東西都輸買進持有——不是訊號特別差，是通行費特別貴。

所以 ETF 值得測。**但測完是否定的**，而且否定的原因不是成本，是流動性
與多重測試。完整過程見 `2026-09-17_ETF輪動的否定.md`。

### 順帶查到一件要確認的事

`config/costs.py` 統一套 0.3% 證交稅：

```python
TAX_RATE = 0.003
def tax(self, amount): return abs(amount) * TAX_RATE if self.apply_tax else 0.0
```

台股證券交易稅：股票千分之三，而**ETF（受益憑證）可能是千分之一**。
若成立，ETF 來回成本從 0.571% 降到 0.371%。

**這是稅法事實，不是我能離線確認的。請查證 證券交易稅條例 第 2 條。**
未查證前不改 `costs.py`；所有 ETF 的報告一律並列兩種稅率。

## 四、建議的順序

```
1. 查證 ETF 證交稅率，修 costs.py          便宜、可能值 0.2 pp/趟
2. ✅ ETF 輪動的 walk-forward + PBO / DSR  **已做，否定**
3. 兩個負相關 sleeve 的 Sharpe 測試        便宜，用既有分數
4. LightGBM baseline                       CLAUDE.md 明文要求，還沒做
5. 開始存帶時戳的新聞檔                     現在不花錢，一兩年後才有價值
```

第 2 項已完成且是否定的，所以結論就是「40 萬在台股成本結構下，買進持有
難以被打敗」。**那不是放棄，是測出來的邊界**——知道邊界在哪裡讓你不會
把錢交給一個 PBO 0.75 的東西。

## 五、我在做這份診斷時犯的錯

第一版 ETF 測試跑出「年化 81.8%」。那不是發現，是索引錯位：

```python
cl = cl.dropna(how='any')       # cl 被過濾了
...
cl.iloc[i] / op.iloc[i+1]       # 但 op 沒有 → iloc 位置對應到不同日期
```

三個 frame（收盤、開盤、實際開盤）必須對齊到同一個 index，否則
`iloc` 的位置意義不同。修正後是 12.5%。

**實測出現「太好」的數字時，先查對齊，不要先寫結論。** 這與先前抓到的
第 13 個 bug（跳過時點標的池導致 40 日淨報酬讀成 72.8% 而非 33.6%）
是同一類錯誤。
