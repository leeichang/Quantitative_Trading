# 台股交易成本模型原理

- 日期：2026-09-12
- 程式：`taiwan-quant/taiwan_quant/config/costs.py`
- 測試：`taiwan-quant/tests/test_costs.py`（25 個測試，預期值全部手算）

---

## 為什麼一個「不下單」的系統需要成本模型

使用者當初的質疑很合理：

> 我的程式不牽涉下單！只提出投資建議！

成本模型跟下單無關。它的用途是**讓回測不騙自己**。

系統要回答的問題是「這個策略值不值得聽」。週頻策略一年約 40 趟來回，每趟真實成本約 1.07%，一年吃掉約 43%。回測若不扣這些，會把「其實在虧」的策略排進 Top 3 推給你。

**所以成本模型是「建議品質」的一部分，不是「交易執行」的一部分。**

### 實測證據

在 qlib-tw-trader 上的 20 週實測（`docs/需求規劃/202609/02_驗證結果_qlib-tw-trader.md`）：

| 情境 | 累積報酬 | Sharpe |
|---|---|---|
| 無成本（毛報酬） | **+26.27%** | 1.047 |
| 只含手續費+證交稅（無滑價） | +0.41% | 0.566 |
| 含滑價 | **−19.08%** | 0.113 |

同一組交易，成本假設不同，結論從「賺 26%」變成「虧 19%」。**光是「有沒有算滑價」就差 19.5 個百分點。**

## 成本的四個組成

### 1. 券商手續費

```
法定上限   0.1425%
網路折扣   常見 6 折 → 0.0855%
買賣各收一次
```

### 2. 證交稅

```
0.3%，只在賣出時收，不可折扣
```

這是台股成本的最大單項。0.3% 比手續費打折後的 0.0855% 大了三倍半。**漏掉它等於把成本低估一半以上。**

附件 `quant_tw_pipeline.py` 的註解寫「含證交稅 0.3%」，但程式只有 `fees = 0.1425 * 0.6 / 100`，稅完全沒進去。

### 3. 最低手續費 20 元

這條容易被當成小數點問題，但對小資金做零股是致命的。

門檻計算：

```
20 元 ÷ (0.001425 × 0.6) = 20 ÷ 0.000855 = 23,391.81 元
```

**部位金額低於 23,392 元時，實際費率高於名目的 0.0855%：**

| 部位金額 | 手續費 | 實際費率 |
|---|---|---|
| 5,000 | 20.00 | **0.4000%** |
| 10,000 | 20.00 | **0.2000%** |
| 20,000 | 20.00 | **0.1000%** |
| 23,392 | 20.00 | 0.0855% |
| 50,000 | 42.75 | 0.0855% |
| 117,600 | 100.55 | 0.0855% |

40 萬資金做三檔零股，單檔部位常落在 3~13 萬，多數時候安全，但若某檔停損很寬導致部位很小，就會踩到這條。

因此程式用 `max(金額 × 費率, 20)` 而非純比例。

### 4. 滑價

這是最容易被省略、也是影響最大的一項。

**為什麼不能沿用整張常見的 0.1%：**

使用者資金 40 萬。台積電 2,430 元 × 1,000 股 = **243 萬**，買不起一張。系統必須以**零股**為單位。

盤中零股交易的買賣價差明顯比整張寬（成交量小、掛單稀疏）。用整張的 0.1% 會低估。

分層設定：

```
0050 成分股（大型股零股）  0.3%
0051 成分股（中型股零股）  0.4%
```

## 一趟來回的總成本

```
買進   0.001425 × 0.6  +  0.003         = 0.003855   （手續費 + 滑價）
賣出   0.001425 × 0.6  +  0.003 + 0.003 = 0.006855   （手續費 + 稅 + 滑價）
                                   合計  = 0.01071    → 1.071%
```

分層對照：

| 模型 | 0050 | 0051 |
|---|---|---|
| 6 折 + 滑價（預設） | **1.071%** | 1.271% |
| 無折扣 + 滑價 | 1.185% | 1.385% |
| 只含手續費+稅（qlib-tw-trader 的模型） | 0.585% | 0.585% |

預設與 qlib-tw-trader 模型差 **0.486 個百分點／趟**。

## 換手率 → 年化成本拖累

這是整個成本模型最有價值的一條推導，因為它把「持有期」與「成本」直接綁在一起。

```
年化來回次數 = 週換手率 × 52
年化成本拖累 = 年化來回次數 × 一趟來回成本率
```

### 實測對照

| 週換手率 | 年化來回次數 | 年化成本拖累 | 情境 |
|---|---|---|---|
| 9.9% | 5.15 | **5.51%** | qlib-tw-trader README 的 HoldDrop 策略 |
| 50% | 26.0 | 27.85% | — |
| 100% | 52.0 | 55.69% | 平均持有 5 天（週頻換一輪） |
| **271.5%** | 141.2 | **151.2%** | qlib-tw-trader API 的日度調倉（實測值） |

最後一列是關鍵發現：**日度調倉在台股的成本結構下根本不可執行。**年化成本 151% 意味著任何毛報酬都會被吃光。

這也解釋了為什麼 qlib-tw-trader 的 README 數字看起來好——它報的是 `HoldDrop`（有持有期參數壓換手），而產品化路徑跑的是換手率 27 倍的 `topk`，且完全不扣成本。

### 手算驗證（9.9% 換手率）

```
0.099 × 52 = 5.148 趟/年

5.148 × 0.01071
  = 5.148 × 0.01     = 0.05148
  + 5.148 × 0.00071  = 0.00365508
  = 0.05513508                        → 5.51%
```

## Sharpe 的成本敏感度（解析估算）

有實測資料時一律用實測。沒有時可解析估算：

```
隱含波動度 = 毛年化報酬 ÷ 毛 Sharpe
淨年化報酬 = 毛年化報酬 − 年化成本拖累
淨 Sharpe  = 淨年化報酬 ÷ 隱含波動度
```

假設：成本只降低報酬、不改變波動度。這偏樂觀（成本本身幾乎無波動），但差距不大。

對 qlib-tw-trader README 宣稱績效的估算：

```
毛年化 55.1%、毛 Sharpe 1.724、週換手 9.9%

隱含波動度 = 0.551 / 1.724 = 0.31960557
年化拖累   = 0.05513508
淨年化     = 0.551 − 0.05513508 = 0.49586492
淨 Sharpe  = 0.49586492 / 0.31960557 = 1.55149
```

**Sharpe 1.724 → 1.55**，僅計滑價。

## 工程設計原則

### 單一來源，禁止他處重寫

`CLAUDE.md` 禁令 3 明文規定所有費率只能來自 `config/costs.py`。

理由是實測教訓：qlib-tw-trader 把成本寫在 `scripts/evaluate_models.py`，而 `src/services/walk_forward_backtester.py` 完全沒有成本。

```
$ grep -rniE "commission|slippage|tax|cost" src/ --include="*.py"
（無任何命中）
```

結果：API 與 Dashboard 顯示毛報酬、離線腳本顯示淨報酬，兩套數字不一致且長期無人察覺。

### 不可變（frozen dataclass）

`CostModel` 是 `frozen=True`。回測中途若成本模型被改掉，前後段的數字就不可比，而且不會有任何錯誤訊息。

### 敏感度組合強制並列

```python
SENSITIVITY_SET = {
    "無成本（毛報酬）":          GROSS,
    "僅手續費+證交稅（無滑價）":  FEE_TAX_ONLY,
    "6折+滑價（預設）":          DEFAULT,
    "無折扣+滑價":               NO_DISCOUNT,
}
```

`CLAUDE.md` 規格 15 要求報告至少並列三檔。只報一個數字，讀者無法判斷結論有多脆弱——這正是 +0.41% vs −19.08% 那 19.5 個百分點的教訓。

### 比率 vs 絕對金額

程式提供兩組介面：

| 介面 | 用途 | 注意 |
|---|---|---|
| `round_trip_rate()` | 回測（比率） | **忽略最低手續費**，小額部位會低估 |
| `buy_cost()` / `sell_cost()` | 部位金額已知時 | 含最低手續費，精確 |

回測用比率方便（不需要知道每筆部位金額），但必須知道它在小額時偏低。

## 測試如何保證正確

25 個測試，**每個預期值都在註解裡手算**，不是拿程式輸出反填。例如：

```python
def test_sell_cost_large_tier() -> None:
    """
    賣出 100,000 元、0050 分層：
        手續費 85.5 + 證交稅 300.0 + 滑價 300.0 = 685.5
    """
    assert DEFAULT.sell_cost(100_000, Tier.LARGE) == pytest.approx(685.5)
```

另有結構性測試：

- `test_one_way_rates_sum_to_round_trip` — 單邊相加必須等於來回
- `test_sell_minus_buy_equals_tax` — 賣買價差恰為證交稅
- `test_sensitivity_set_covers_required_scenarios` — 情境之間必須真的不同，否則並列沒意義
- `test_cost_model_is_frozen` — 不可變性
