# 特徵工程原理

- 日期：2026-09-12
- 程式：`taiwan-quant/taiwan_quant/features/technical.py`、`chips.py`
- 測試：46 個（24 技術面 + 22 籌碼面）

---

## 設計原則：少而可驗證，不是多而未驗證

qlib-tw-trader 有 **303 個因子**。實測結果（20 週 Walk-Forward）：

```
平均 valid IC（驗證期）  +0.0362
平均 live IC（樣本外）   −0.0263      ← 負的
valid/live 相關係數      −0.1588      ← 負相關
```

**因子數量不是優勢來源。**

本專案刻意保持小規模：技術面 16 個 + 籌碼面 16 個 = **32 個**。

理由：

1. 每個特徵都有手算值測試 + 物理截斷驗證。32 個做得到，303 個做不到。
2. 先建立可信的 baseline，再談擴充（`CLAUDE.md`：先有 baseline 再談複雜度）。
3. 特徵少，模型過擬合的空間小，PBO 檢定比較容易通過。

---

## 兩層保障

每個特徵都要過兩關：

| 層級 | 驗證什麼 | 方法 |
|---|---|---|
| 1. 手算值比對 | **算得對不對** | 構造已知輸入，預期值手算在註解裡 |
| 2. 物理截斷掃描 | **有沒有偷看未來** | `validation/lookahead.py` |

第 2 層是重點。手算只能驗正確性，驗不出 look-ahead。全樣本標準化這種洩漏，手算測試完全看不出來。

## 技術面特徵（16 個）

### 分類

| 類別 | 特徵 | 用途 |
|---|---|---|
| 均線偏離 | `ma_ratio_5/20/60` | 趨勢位置 |
| 動能 | `momentum_5/20/60/120` | D7 動能突破族的核心 |
| 超買超賣 | `rsi_14`、`bollinger_position_20`、`high_low_position_20` | D7 均值回歸族的核心 |
| 量能 | `volume_ratio_5/20` | 確認訊號強度 |
| 波動度 | `true_range_ratio_14` | 風險度量 |
| 日內型態 | `gap_ratio`、`intraday_range`、`close_position_in_bar` | 短線行為 |

### 關鍵實作細節

#### 一律用 rolling，不用裸 mean/std

```python
# ✗ 洩漏
return (close - close.mean()) / close.std()

# ✓ 只用過去 N 天
ma = close.rolling(window, min_periods=window).mean()
return close / ma - 1
```

`min_periods=window` 確保視窗不足時回 NaN，不用不完整視窗硬算。

#### pct_change 的方向

```python
close.pct_change(periods=window)    # ✓ 正數 = 往過去看
close.pct_change(periods=-window)   # ✗ 負數 = 看未來
```

這是容易寫錯又不會報錯的一行。`AGENTS.md` 檢查項 1 明文要求審查 `shift()` 方向。

#### 除零防護

所有比率型特徵都要處理分母為 0：

| 情境 | 分母 | 處理 |
|---|---|---|
| 整段停牌 | 均量 = 0 | 回 NaN（「沒有成交」無法定義量能倍數） |
| 完全平盤 | 標準差 = 0 | 布林位置回 **0.5**（平盤就是中性狀態） |
| 一價到底（漲停鎖死） | high − low = 0 | K 棒位置回 **0.5** |

**為什麼有的回 NaN、有的回 0.5**：

- 「無法定義」→ NaN（量能倍數）
- 「有明確的中性解」→ 具體值（平盤時收盤確實在通道正中間）

硬給數字會誤導模型；該給數字時給 NaN 會浪費樣本。

最後統一把 inf 轉成 NaN：

```python
return frame.replace([np.inf, -np.inf], np.nan)
```

inf 進到模型會讓訓練崩潰或給出荒謬權重。

#### RSI 的邊界

```
只漲不跌 → 平均跌幅 0 → RS = ∞ → RSI = 100
只跌不漲 → 平均漲幅 0 → RS = 0 → RSI = 0
完全平盤 → 兩者皆 0   → RSI = 50（中性）
```

用 Wilder 原始定義的簡單移動平均版本（非指數平滑），讓「只用過去 window 天」這件事一目了然。指數平滑的 EMA 理論上會用到無限長的歷史，雖然不算洩漏但不易驗證。

測試把三個邊界都釘住：`test_rsi_is_100_on_monotonic_rise`、`test_rsi_is_zero_on_monotonic_fall`、`test_rsi_is_50_on_alternating_equal_moves`

## 籌碼面特徵（16 個）

台股特有的資料優勢——美股沒有逐日的三大法人買賣超與融資融券餘額。

### 公布時序：D7 標註此族 look-ahead 風險最高

```
T 日 09:00-13:30   交易發生
T 日 13:30         收盤價確定
T 日 15:00-18:00   三大法人買賣超公布      ← 收盤已過
T+1 09:00          進場
```

兩條規則：

```
✓ 決策日 T 可以用 T 日的籌碼資料（因為是盤後才決策）
✗ 但進場必須在 T+1 開盤，不可用 T 日收盤價進場
```

第二條由 `triple_barrier.py` 的 `LABEL_ENTRY_OFFSET = 1` 保證。特徵模組只負責第一條（不偷看 T 之後）。

### 分類

| 類別 | 特徵 | 意義 |
|---|---|---|
| 外資 | `foreign_net_ratio_1/5/20`、`foreign_buy_streak`、`foreign_sell_streak` | 權重最高，動向最受關注 |
| 投信 | `trust_net_ratio_5/20`、`trust_buy_streak` | 季底作帳行為明顯 |
| 自營商 | `dealer_net_ratio_5` | 波動大，單獨訊號弱 |
| 三大法人合力 | `institution_strength`、`institution_agreement_5/20` | 同步買超比單一法人有訊息量 |
| 融資融券 | `margin_change_5/20`、`short_margin_ratio`、`margin_to_volume_20` | 散戶情緒的代理 |

### 關鍵實作細節

#### 買賣超必須用成交量正規化

```python
net_sum = bars[column].rolling(window).sum()
volume_sum = bars["volume"].rolling(window).sum()
return net_sum / volume_sum
```

**為什麼**：買超 10,000 股對台積電是噪音、對小型股是主力進場。絕對股數無法跨標的比較。

#### 連續買超天數：持平要中斷連續

```python
is_streak = (net > 0)           # 嚴格大於 0
group = (~is_streak).cumsum()   # 每次中斷換一個 group id
counts = is_streak.groupby(group).cumsum()
```

買超為 0（持平）**中斷**連續，不是「維持不變」。

測試：買、買、賣、買 → `[1, 2, 0, 1]`（賣超那天歸零，不是「不增加」）

這個 cumsum 技巧完全不涉及未來資料——以「非連續事件」為分組鍵做組內累計。

#### 三大法人合力

```python
signs = [np.sign(bars[col]).fillna(0.0) for col in INSTITUTION_COLUMNS]
return sum(signs)    # −3 ~ +3
```

三家同步買超（+3）比單一法人買超更有訊息量。

一致度用絕對值：

```python
rolled.abs() / (3.0 * window)
```

取絕對值的理由：「一致看空」與「一致看多」**都是**強訊號，不該互相抵銷。

#### 缺欄位必須報錯，不可產出全 NaN

```python
raise ValueError(
    f"缺少必要欄位：{sorted(missing)}。"
    "籌碼資料不完整時請先確認 coverage_report()，"
    "不可用全 NaN 的特徵訓練——那會讓 dropna 清空整個樣本。"
)
```

這是 qlib-tw-trader 訓練失敗的直接原因：

```
Check failed: (num_data) > (0) at .../dataset.cpp, line 44
```

303 個因子中只要有一個整欄 NaN，dropna 就會丟掉**所有**樣本，LightGBM 收到空資料集。原專案沒有這道防護，只在訓練跑到 92% 時炸掉。

## 結構性測試

除了個別特徵的手算值，還有整組的結構檢查：

| 測試 | 檢查什麼 |
|---|---|
| `test_build_*_returns_all_declared_features` | 產出欄位與目錄宣告一致，不可默默多或少 |
| `test_build_*_preserves_index` | 索引與輸入對齊 |
| `test_build_*_does_not_mutate_input` | 不修改傳入的 DataFrame |
| `test_build_*_has_no_infinite_values` | 無 inf |
| `test_build_*_tail_has_no_nan` | 資料充足時最新決策日算得出所有特徵 |
| `test_all_*_features_pass_truncation_scan` | 物理截斷掃描 |

最後一項 `tail_has_no_nan` 的意義：若最新一列有 NaN，就代表**最新的決策日算不出特徵** → 系統無法產出今天的建議。
