## 必須先更正的數字（第 14 個 bug）

`08_動能突破N10的樣本外結果.md` 報告的 OOS 成本是 0.671%，**那是錯的**。
實際逐檔計算後是 **1.016%**：

```
指標          原報告      更正後      差異
平均來回成本   0.671%     1.016%    +0.345 pp
淨/趟         +6.93%     +6.58%    −0.35 pp
累積淨報酬    +151.65%   +138.83%   −12.82 pp
Sharpe        1.130      1.075     −0.055
最大回撤       19.78%     21.24%    +1.46 pp
```

### 錯在哪

我用「40 萬 × 33% 單檔上限 = 132,000 元」論證「265 檔裡有 153 檔（58%）
買得起整張」，然後把整股滑價 0.1% 套用到整個回測。

**但 N=10 時每檔只有 40,000 元。** 買得起整張的門檻從股價 132 元掉到
**40 元**：

```
160 筆實際持倉的成本分層
  0050（零股）    138 筆 (86.2%)   來回 1.071%
  0050-lot（整股） 22 筆 (13.8%)   來回 0.671%

進場價中位 185.3 元｜一張要 185,281 元｜4 萬元遠遠不夠
```

**我拿 N=3 的部位大小去論證 N=10 的成本。** 這是第 14 個抓到的 bug，
而且第 13 個都是「讓結果變好看」的方向。

### 根因：成本寫在腳本裡而不是單一來源

第一版：

```python
SLIPPAGE_ONE_WAY = 0.001          # ← 寫死在 scripts/validate_oos_momentum.py
ROUND_TRIP = FEE_RATE * 2 + TAX_RATE + SLIPPAGE_ONE_WAY * 2
```

**那違反 CLAUDE.md 禁令 3**（一律呼叫 `config/costs.py`，禁止他處重寫
費率）。而且它在結構上無法表達「這一檔買不起整張」——一個常數沒有
per-position 的維度。

現在成本逐檔決定：

```python
tier = resolve_tier(price=price, amount=CAPITAL / N_POSITIONS, is_etf=is_etf(sid))
cost = DEFAULT_COST.round_trip_rate(tier)
```

禁令 3 存在的理由，這次自己示範了一遍。

## 成本模型擴充：整股／零股 × 標的類別

原本的 `Tier` 只有兩個成員，都隱含「零股」：

```
Tier.LARGE = "0050"   0050 成分股、零股、0.3%（禁令 4）
Tier.MID   = "0051"   中型100成分股、零股、0.4%（禁令 4）
```

新增四個，**既有兩個原封不動**（禁令 4 是明文規格）：

| 分層 | 滑價 | 依據 |
|---|---:|---|
| `LARGE` / `MID` | 0.3% / 0.4% | CLAUDE.md 禁令 4，不可改 |
| `LARGE_WHOLE` / `MID_WHOLE` | 0.1% | 跳動單位半價差中位 0.0937%（490 筆持倉） |
| `ETF_ODD` | 0.1% | ETF 跳動下限的 25 倍 |
| `ETF_WHOLE` | 0.05% | 同上的 13 倍 |

ETF 的跳動單位實證（2024 年起收盤價最小差距）：

```
0050 (ETF)   tick 0.0100   半價差 0.0037%
0056 (ETF)   tick 0.0100   半價差 0.0133%
2330 (股票)  tick 1.0000   半價差 0.0463%
1303 (股票)  tick 0.0500   半價差 0.0503%
```

**ETF 比股票細 4~10 倍。** 所以不可以把 0050 當成 `Tier.LARGE`（0.3%）
——那是「0050 成分股」的零股滑價，不是 0050 本身，會高估三倍。

## ETF 納入候選

```python
ETF_CANDIDATES = ("0050", "0051", "0056")
```

就是 `validation/benchmarks.py` 的 `ETF_BENCHMARKS` 那三檔——它們的資料
本來就在，而且已經被當成「策略要打敗的東西」。現在讓策略可以直接持有。

### 為什麼不寫進 universe_history

那張表是市值排名的季度快照，`metric` 欄位是市值。ETF 沒有「市值排名」
的意義，硬塞會讓表的語意變混。ETF 是結構上不同的一類：永遠可交易、
跳動單位細 10 倍、成本分層不同。

### 為什麼用白名單而不是「代號開頭 00」

台股有數百檔 ETF，多數流動性遠不如這三檔，滑價分層也沒有實證依據。
白名單讓「哪些 ETF 可交易」成為明確的決定，不是代號的副作用。
`00878` 存在但不在名單內，`is_etf("00878")` 回 `False`。

### 0051 缺籌碼資料

```
代號     價格    還原價   三大法人   融資券
0050    2,845   2,845    2,845    2,850
0051    2,847   2,850        0        0   ⚠️
0056    2,850   2,850    2,831    2,850
```

實測三個策略族對 0051 的可用分數期數：動能突破 775、**籌碼跟隨 0**、
均值回歸 775。全 NaN 會被 `dropna()` 剔除，**不會靜默變 0** ✓。

## 檔數與成本的張力（開發集、逐檔成本）

```
  N    每檔金額     毛/趟   實際成本    淨/趟   年化淨  整股比例  逐年正
  1   400,000    9.54%   0.671%   8.86%   70.8%  100.0%   6/8
  3   133,333    5.38%   0.771%   4.61%   32.8%   75.0%   4/8
  5    80,000    4.75%   0.844%   3.91%   27.3%   56.7%   5/8
 10    40,000    4.89%   0.913%   3.98%   27.9%   39.4%   7/8   ←
 15    26,667    4.13%   0.950%   3.18%   21.8%   30.3%   6/8
 20    20,000    3.90%   0.986%   2.92%   19.9%   21.2%   6/8
```

**這是一個先前沒被量過的 trade-off：**

```
N 變大   樣本變多、統計力變強、逐年更穩（N=10 是 7/8）
N 變大   每檔金額變小 → 整股比例掉（100% → 21%）→ 成本上升
```

N=10 仍是最佳平衡：淨/趟 3.98% 幾乎等於 N=5 的 3.91%，但逐年為正
7/8 最好、樣本 480 筆（N=3 只有 144）。

N=1 的年化 70.8% 看起來最好，但只有 48 筆樣本、6/8 年為正，而且
**單檔集中，40 萬全押一檔**——那不是投組，是賭注。

## ⚠️ ETF 的效果無法在本區間驗證

2024-01 ~ 2026-08 已經在 `momentum_top10_h40@oos-2026-09-16` 用掉了。

**加了 ETF 之後在同一個區間重跑，就是「看過結果之後調整設計再重跑」
——正是禁令 6 要防的事。**

所以 `--include-etfs` 預設關閉，而且：

```
□ ETF 納入的效果要等新資料（2026-09-12 之後）才能驗

```
