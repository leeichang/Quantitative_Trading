### 所以待辦的描述要改一個字

待辦說「門檻**沒有在篩選任何東西**」。更精確的說法是：

> **門檻站在瓶頸的下游。**

3 個槽位 × 60 日持有 × 開發集長度，決定了成交數上限約 63 筆。門檻篩掉
多少候選都不影響這個上限——排隊的人再多，櫃檯還是只有三個。

**這讓選項 1（相對排名）與選項 2（提高 edge_z）都失效**，因為兩者都在
操作錯誤的變數。它們改的是隊伍長度，不是櫃檯數量。

### 方向一致性是更強的證據

比幅度更有說服力的是**方向**：

```
槽位排隊（v6→v7）    +194、−55、−831、+508     兩個方向，數百 pp
定期換倉（task M）    十個設定有九個為負，−6.6 ~ −24.2 pp
```

定期換倉下所有設定往同一個方向移動，幅度隨基準大小縮放。
**那是一個系統性的資料效應。** 槽位排隊下往兩個方向各跳數百 pp，
**那是混沌，不是效應。**

⚠️ **兩個擾動不是同一個，這不是對照實驗。** v6→v7 補了 23 期快照；
task M 改了 join 方式。兩者同屬資料完整性修正、都改變名字可用性，
但輸入變動的大小不同。**方向與數量級的對比成立，精確倍數不成立。**

## 機制：路徑相依需要出場日錯開

待辦的機制描述是「99.8% 訊號被槽位擋掉，成交哪一百筆取決於槽位空出來
時誰在排隊」。我寫合成資料驗這句話，**第一版得到相反的結果**：

```
槽位排隊的傳播 0.0%   定期換倉的傳播 0.7%
```

原因是我的合成訊號全部同日出場（`exit_date = index + HOLD`）。
三個槽位永遠同時釋放，進場節點變成固定週期——**槽位排隊此時等價於
定期換倉，路徑相依消失。**

把出場日錯開（範圍 [3, HOLD]，模擬 triple-barrier／移動停損提前觸價）
之後：

```
情境              方案        重疊    傳播    分歧區間
出場錯開（真實）   槽位排隊   88.5%  14.4%  01-01 ~ 01-29
出場錯開（真實）   定期換倉   95.0%   0.7%  01-02 ~ 01-02
出場同日（退化）   槽位排隊   95.0%   0.0%  01-01 ~ 01-01
出場同日（退化）   定期換倉   95.0%   0.7%  01-02 ~ 01-02
```

移掉第一個決策日的一檔，槽位排隊下的分歧延續到 01-29——而**被擾動的
那個部位最晚 01-15 就出場了**。擾動活得比它擾動的部位更久，那就是
路徑相依的定義。

定期換倉下分歧只出現在 01-02 一天，關在被擾動的那一期裡。

### 所以待辦第 2 項的機制描述要補一句

```
待辦寫的     99.8% 訊號被槽位擋掉 → 路徑相依
應該寫的     99.8% 被擋 + 出場日不規則 → 路徑相依
```

**「被擋」是必要條件，不是充分條件。** 固定持有期 + 同步出場的系統
即使排隊比 400:1 也不會有路徑相依。

⚠️ 「傳播到序列末端」**不成立**。實測 14.4%，會自行收斂——候選池循環，
槽位最終重新同步。我原本斷言 `> 0.5`，那是憑空的數字，已改成斷言
可推導的部分（擾動活得比它的部位久）。

## 結論與處置

```
選項 1（相對排名）    ✗ 否證。改訊號數不改成交數與報酬
選項 2（提高 edge_z） ✗ 否證。同上，而且比值只從 493 降到 486
選項 3（定期換倉）    ✓ 採用。比值 1.0、擺盪從數百 pp 降到 24 pp
                       主線已在使用
```

### 要加的規格

```
□ 結論性的回測一律用定期換倉，不用槽位排隊
□ 槽位排隊路徑（simulate_portfolio）僅保留於重現歷史報告
□ 任何引用 v6/v7 那批數字（+1544%、+1738%、+1076%、+954%）的地方
  要註明它們來自槽位排隊，且擺盪數百 pp
```

⚠️ **v6/v7 那批數字不該被引用為策略能力。** 待辦開頭已經寫了
「+1738% 不該被當成策略的能力，它是一次抽樣的結果」——現在有機制
證據支持那句話。而 2026-09-18 的 bootstrap 工作進一步顯示，
即使在定期換倉下，累積報酬在 n≤36 也不可 falsify
（見 `2026-09-18_信賴區間讓累積報酬失去意義.md`）。

**兩件事疊起來：累積報酬先被路徑相依污染，再被抽樣變異蓋掉。**
那個數字沒有任何一層是可靠的。
