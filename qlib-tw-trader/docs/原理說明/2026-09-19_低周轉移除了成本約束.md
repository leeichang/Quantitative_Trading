## 一、低周轉：成本約束基本消失

專案至今測的全是高周轉（H=5 ~ 120，每年 2 ~ 50 趟），而每一次的結論
都被成本吃掉。2026-09-19 算出原因：

```
同一個 1.071% 的來回成本
事件策略 H=40   每年 6.30 趟  →  年化拖累 6.75%
買進持有 9 年   進出各一次    →  年化拖累 0.06 ~ 0.11%
```

**「成本吃掉一切」的前提是高周轉，而那個前提從來沒有被寫出來過。**

### 實測（進場後完全不動至 2023-12-29）

```
規則            2015     2016     2017     2018     2019   年化全距  回撤中位
市值前 1 檔     21.31%   23.57%   21.84%   20.32%   25.41%   5.09%  −44.80%
0051 買進持有   14.52%   18.70%   20.26%   19.15%   25.53%  11.01%  −31.30%
0056 買進持有   11.20%   13.72%   13.75%   13.91%   16.81%   5.61%  −25.86%
0050 買進持有   11.69%   14.46%   13.39%   12.53%   16.98%   5.29%  −33.83%
市值前 3 檔     13.01%   14.35%   11.07%    8.95%   14.42%   5.47%  −29.36%
市值前 5 檔     12.63%   11.29%    8.98%    7.12%   10.63%   5.51%  −28.06%
市值前 10 檔    10.00%   10.22%    6.58%    5.03%    8.04%   5.19%  −29.99%
```

成本明細：

```
0050／0051／0056   來回 0.571%   攤到 9 年 = 每年 0.0634%
市值前 1／3 檔      來回 0.671%   攤到 9 年 = 每年 0.0746%
市值前 10 檔        來回 0.991%   攤到 9 年 = 每年 0.1101%
```

### ⚠️ 這張表有三個陷阱

**1.「市值前 1 檔」五個進場年份全部是 2330。**

那不是策略，是**一檔股票的一個十年**。代價在回撤：**−44.80%，全表最差**。
分散度越低報酬越高、回撤也越大——那是同一件事的兩面。

**2. 五個進場年份不是五個獨立觀測。** 九年持有期互相重疊，
**有效樣本接近 1**。所以任何兩列的差異**都沒有統計意義**。

這與本週其他每一個發現同一個教訓：n 不足時，看起來一致的排序仍然
可能是一次抽樣。

**3. 2015-2023 是台股多頭。** 規則之間的相對比較還有意義，
絕對數字沒有。

### 為什麼測規則而不是測使用者的名單

使用者問的是「00712 ＋ 台積電 ＋ 台達電」。**那個名單不能誠實回測**：
它是 2026 年挑的，拿去跑 2015 起的歷史就是禁令 1 的 look-ahead——
我已經知道台積電這十年漲了多少。

所以測的是**事前規則**：決策日當天依市值排名選前 N 檔，名單由當時的
`universe_history` 快照決定。

⚠️ **這不是在回答「那個組合好不好」。** 那個問題無法誠實回答，
而且屬於個別投資建議。

⚠️ `market_cap` 快照從 2015-04-01 起（2015-01 那期缺，
見 `03_待辦與改進方向.md` 第 9 項），所以 2015 的進場日是 04-01。

## 二、滑價：唯一沒有量測的那一項，也是最大的一項

4 萬元零股單的來回成本 1.071% 拆開：

```
手續費 × 2     0.171%   法定上限 × 6 折，可談到 0.08%
證交稅         0.300%   法定，股票不可減（ETF 0.1%、當沖 0.15%）
滑價 × 2       0.600%   ← 最大項
```

而 `config/costs.py` 的滑價是兩段式：

```
零股   LARGE 0.3% / MID 0.4%   ← 禁令 4 明文規格，無量測
整股   0.1%                    ← 實證：490 筆實際持倉，半價差中位 0.0937%
```

**整股那個有量測，零股那個沒有。**

### 兩段式錯在哪

它把 2330（一張 241 萬）與 2884（一張 4.6 萬）當同一類。40 萬資金下
2330 永遠是零股——**而那與流動性無關，2330 是台股最活絡的標的。**

兩段式用價格高低代理流動性，把「買不起一張」和「流動性差」混在一起。

### 跳動單位模型，以及一個驗證點

新模型：`滑價 = 半價差 × 零股倍數 + 市場衝擊`，半價差由跳動單位算出。

264 檔實際標的池在 2023-12-28 的真實收盤價上實測：

```
每檔金額       模型                滑價中位   來回成本   買得起整張
133,333       舊：兩段式           0.1000%   0.6710%   173/264（66%）
133,333       新：跳動單位 × 1.0    0.1051%   0.6812%
 40,000       舊：兩段式           0.3000%   1.0710%    71/264（27%）
 40,000       新：跳動單位 × 1.0    0.0962%   0.6634%
 40,000       新：跳動單位 × 2.0    0.1602%   0.7914%
 40,000       新：跳動單位 × 3.0    0.2186%   0.9083%
```

**在 133,333 元、三分之二標的買得起整張時，新模型落在 0.1051%，
舊模型 0.1000%——新模型重現了那個唯一有量測支撐的數字。**

那是方法站得住的直接證據，也是為什麼 40,000 元那一行的分歧值得當真：
舊值是跳動單位的 3.1 倍，**而且比 3 倍倍數還高**。

### 這會碰到一個門檻

融資暴增訊號的區間在來回成本 ≤ 0.871% 時不含零。倍數 2.0 是 0.7914%。

```
零股滑價（單邊）        來回成本   年化       年化區間            含零?
0.30%（禁令 4）        1.071%   +4.09%   [−0.13%,  +8.53%]   含零
0.20%                 0.871%   +5.40%   [+1.14%,  +9.89%]   不含零
```

**所以「40 萬吃不到那個訊號」可能部分是一個未驗證參數的產物。**

⚠️ **不宣稱反面。** 三個理由：訊號本身的 +1.709% 有 skipna 污染
（見 `2026-09-19_訊號是真的但40萬吃不到.md` 的失效標記）；2.0 倍本身
沒有量測；而且這是開發集。要確認必須走 Codex 的 `capacity_economics`
重跑，而那條路目前卡在缺價分類。

### 處置：並列，不覆寫

`costs.SLIPPAGE` 原值不動——禁令 4 是明文規格，而且舊報告要能重現
（禁令 7、8）。新模組是第二個估計，用途是量化敏感度。

零股倍數是**顯式參數而不是內建常數**，docstring 要求任何用到它的結論
都必須附敏感度掃描。倍數小於 1 直接拋錯：零股簿比整股薄，不會更便宜，
允許小於 1 會讓「把零股調到比整股便宜」變成一個可以偷偷做的調參。

### 真正能驗證它的東西已經找到了

TWSE 每日行情有 **`最後揭示買價` / `最後揭示賣價`**：

```
00712 @ 2023-01-03   買 9.81   賣 9.82   → 半價差 0.051%
```

**所以「零股滑價無法量測」是錯的**——那個欄位存在，回溯到 2015。
但 `stock_daily` 沒存它（回補腳本把兩欄丟掉），所以還需要一次回補。

## 三、資料庫漏掉所有現代 ETF

為了抓 00712 才發現：

```python
ORDINARY_CODE = re.compile(r"^\d{4}$")   # 只收 4 碼
```

```
0050 / 0051 / 0056      有資料——因為它們恰好是 4 碼
00712 / 00878 / 006208  解析時就被丟掉，從未入庫
```

**所以 2026-09-17 否決 ETF 輪動時，可用標的只有那三檔。** 那個否決
可能仍然成立（正確稅率下最好一格 13.5%，仍輸 0050 的 15.3%），
但它的涵蓋範圍比讀起來窄得多。

### 那道規則為什麼是多餘的

原意是擋權證。但價格端點用 `type=ALLBUT0999`，**表格標題明寫
「不含權證、牛熊證、可展延牛熊證」**——權證在來源就沒了。
4 碼規則是第二道牆，而它實際擋掉的是 ETF。

籌碼端點 T86 沒有那個排除（一天 6,880 個代號絕大多數是權證），
那裡仍然需要過濾——而權證是 6 碼含字母或非 00 開頭，新規則照樣擋得住。

### 繼續排除的，而且是刻意的

```
00631L / 00633L   槓桿型，每日重設，複利路徑與持有期假設不相容
00632R / 00634R   反向型
00635U            期貨信託
00625K / 00636K   特殊類別
2887A / 2891B     特別股
```

先抓一天的回應把類別數清楚，不照 docstring 猜：980 個 4 碼、
77 個 5 碼 00 開頭、6 個 6 碼 00 開頭、26 個特別股、92 個含字母。

### 一條界線

**存進資料庫 ≠ 可以交易。** 交易候選的白名單是 `etf_universe.is_etf`，
**仍然只有 0050／0051／0056**，而且有測試釘住「解析規則放寬不會自動
擴大可交易集合」。把新 ETF 放進候選池必須是刻意的動作。

## 四、00712 沒補到：TWSE 限流

逐日走訪（`MI_INDEX?type=ALLBUT0999`）在約 35 次請求後被擋：

```
2015-03-04 起連續「HTTP 重試耗盡」
接著整個端點回 HTTP 307
「因為安全性考量，您所執行的頁面無法呈現。」
```

006208 只拿到 2015-01 ~ 03 的 32 列。

### 改用月報端點

```
逐日全市場   00712 從 2017-10 起 → 2,180 次請求
單檔月報     同上               →   108 次請求
```

`scripts/backfill_symbol_history.py` 已就緒，`--delay` 預設 3.5 秒且
低於 1 秒直接拒絕執行。**被擋之後要等，不是加重試**——重試只會延長封鎖。

解析已離線測過：民國年（`112/10/02` 是 2023 不是 1120）、
`--` 代表沒成交而不是 0。

### 兩條路

```
A. 等 TWSE 封鎖解除，再跑月報回補
B. .env 的 FINMIND_API_TOKEN 填入真實值（目前四個都是 placeholder）
```

⚠️ 測試套件現在有 4 個 integration 失敗，比先前多一個
（`test_market_cap::test_real_issued_shares_historical_date`）。
**那是 TWSE 封鎖造成的，不是程式回歸。** 封鎖解除會恢復。
