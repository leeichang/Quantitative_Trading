投組約束（同產業 ≤ 2、高波動 ≤ 1、相關係數 < 0.7、至少 1 支 defensive）

現行的動能突破 N=10 是純分數排序，完全沒有約束。後果直接可見：

```
  2880 華南金  2892 第一金   5880 合庫金     ← 金融保險 6 檔 / 10
```

**明顯違反「同產業 ≤ 2」。** 這一版不可推播。

## 為什麼不能直接把 Top 3 的數字套上去

CLAUDE.md 那四條寫在「投組約束（**Top 3**）」標題下：

| 約束 | 在 3 檔裡 | 在 10 檔裡 |
|---|---|---|
| 最多 2 支同產業 | 67% 集中度上限 | **20%** |
| 最多 1 支高波動 | 33% | **10%** |
| 至少 1 支 defensive | 33% | 10% |
| 兩兩相關 < 0.7 | 與檔數無關 | 同 |

**同一個數字，兩個完全不同的嚴格程度。** 而動能突破選出來的本來就是
齊漲的同族群、高波動名字，所以「維持 2 還是按比例放寬」是一個有代價的
決定。所以先量。

### 配對檢定（差異全部量不出來）

同一批決策日、同一份候選池，只有約束不同——所以必須**配對**相減，
未配對的標準誤裡含著「這一期市場好不好」的共同變異。

```

高波動 ≤ 3                 +0.07%   0.87%   +0.08   量不出差別
相關 < 0.7                 −0.97%   0.67%   −1.45   量不出差別

按比例放寬（3/3/0.7/def）     −0.62%   0.88%   −0.71   量不出差別
```

**全部 |t| < 2。**

### ⚠️ 我先看彙總表時讀錯了

看到「高波動 ≤ 1 把淨/趟從 3.28% 砍到 1.82%」我當下的結論是「這條約束
很貴」。**那是在解讀雜訊的點估計**——那 1.45 pp 的配對標準誤是 1.56 pp。

### 檢定力有多低要說清楚

```
配對標準誤 ≈ 1.6 pp/趟
2 SE      ≈ 3.16 pp
優勢本身   ≈ 3.28 pp/趟
```

**這個檢定只能偵測到「約束把整個優勢全部消滅」。** 再小一點的代價
——例如砍掉一半——都看不見。

所以正確的說法不是「約束是免費的」，而是：

```
可以排除   約束毀掉全部優勢（勉強）
無法排除   約束造成 1 ~ 3 pp/趟 的代價
```

### 為什麼 4% 的持股變動能移動 30% 的報酬

`相關 < 0.7` 在 36 期裡只剔除 15 檔（360 個名額的 4%），點估計卻掉
0.97 pp（淨/趟的 30%）。

這不是 bug，是先前已經記錄過的事實的另一個切面：
**每個策略族的優勢集中在 1.7 ~ 4.3 檔名字上。** 換掉幾檔就能大幅移動
結果，也正是這些數字雜訊大到量不出差異的原因。

---

## 結論：照原規格實作，不放寬

**沒有證據支持放寬，所以不放寬。**

看過回測結果之後把 2 改成 3，是「用回測結果放寬風控規格」——那正是
禁令 6 要防的事。而且點估計上 `同產業 ≤ 2` 還是最好的那一組
（+0.35%、Sharpe 0.59、最差年從 −4.82% 改善到 −3.45%），沒有任何
理由去動它。

`ConstraintLimits` 做成可掃描是**為了量測**，不是為了調鬆。
`DEFAULT_LIMITS` 維持 CLAUDE.md 原值，並有測試釘住：

```python
def test_constrained_variant_uses_claude_md_numbers_verbatim():
    assert CLAUDE_MD_LIMITS.max_same_industry == 2
    assert CLAUDE_MD_LIMITS.max_high_volatility == 1
    assert CLAUDE_MD_LIMITS.max_correlation == 0.7
```

## 量出一個真的規格缺陷：defensive 約束是空的

`至少 1 支 defensive` 的效果**與 baseline 完全相同**——不是誤差小，
是一模一樣。查了原因：

```
baseline 前 10 檔裡 beta < 1.0 的檔數
  中位 8 檔   最少 2 檔   最多 10 檔   等於 0 的期數 0/36
```

**它從來沒有綁到任何一期。**

原因是 beta 的基準是 0050，而 0050 由台積電主導、本身就是高 beta。
拿它當分母，150 檔大型股裡大多數的 beta 自然 < 1.0，
`DEFENSIVE_BETA_MAX = 1.0` 因此篩不掉任何東西。

這條約束目前**提供零保護**。可能的修法（都還沒做）：

| 方向 | 問題 |
|---|---|
| beta 基準換成加權指數 | 資料庫沒有指數序列 |
| 改用 beta 的橫斷面分位（如最低 30%） | 那是改規格，要先有依據 |
| 回到 CLAUDE.md 原文的「高股息」 | `stock_daily_per` 殖利率覆蓋率僅 4.3% |

**先如實記錄它是空的，不要因為「它通過了」就當成有保護。**

對照之下，高波動約束是真的在綁：

```
baseline 前 10 檔裡 ATR 分位 > 0.80 的檔數   中位 5 檔
自然滿足「≤ 1 檔」的期數                      4/36
```

150 檔裡有 30 檔是高波動，動能突破卻挑了 5 檔進前 10——
**2.5 倍的過度代表**。動能的優勢確實住在高波動名字裡。

## 新增的計算模組

`ranking/portfolio_features.py`：四個約束輸入的時點安全計算。

```
industry        stock_master.industry        ⚠️ 現行分類，非時點（見限制）
atr_percentile  ATR(14)/close 的橫斷面分位     只用 ≤ T 的 K 線
beta            對 0050 的 250 日迴歸          只用 ≤ T 的報酬
correlations    60 日日報酬的兩兩相關          只用 ≤ T 的報酬
```

### ATR 必須先除以股價

ATR 的單位是新台幣。1560（790 元）的 ATR 天生比 2801（27.9 元）大一個
數量級，**直接取橫斷面分位等於在排序股價**。所以一律用 `ATR(14)/close`。

測試用兩檔波動比例相同、股價差 28 倍的合成資料釘住這件事。

### 浮點雜訊也會製造任意排序

上面那個測試第一次跑是**失敗**的：兩個數學上相同的 ATR% 差了 ~1e-16，
`rank()` 把它們當成不同值，於是波動度排名多出一個沒有資訊的先後。

`HIGH_VOLATILITY_PERCENTILE = 0.80` 剛好切在中間時，那個雜訊會決定誰
佔用高波動額度。修法是取分位前先量化到小數 6 位（ATR% 實測落在
0.005 ~ 0.10，1e-6 遠細於任何有意義的差異）。

**這與 `tie_break.py` 修的是同一類問題：分不出來的時候不要假裝分得出來。**

### 缺值方向刻意相反

```
產業缺 → "未分類"（仍受同產業上限約束）
ATR 缺 → 0.0（低波動，不佔高波動額度）
beta 缺 → inf（非 defensive，不能用來滿足 defensive 要求）
相關缺 → 拒絕（不是填 0）
```

規則一致：**缺值不得取得好處**。反過來各自會怎麼錯——ATR 缺值填 1.0
是憑空的過度懲罰；beta 缺值填 0 會讓它假裝是 defensive，放過真正的
集中風險；相關缺值填 0 等於宣稱兩檔無關，正是約束要防的事。

### 逐日版與整段版共用同一段計算

`atr()` 每次呼叫都算完整序列再取最後一筆，逐日呼叫是 O(天數²)。診斷要
掃 36 期 × 150 檔，所以有 `atr_ratio_frame()` 一次算完。

**但兩者不可各自實作 ATR%**，否則遲早有一份會漂移。單日版
`atr_percentiles()` 直接呼叫整段版，只是先做 `bars.loc[:day]` 截斷讓
時點紀律在程式碼上看得見。

## 限制

### ⚠️ `industry` 不是時點資料

`stock_master` 是現況表，沒有產業分類的生效日期。所以 2017 年的決策會
看到該公司 **2026 年**的分類。

判斷它可接受的理由：產業分類是**風險分群**，不是報酬預測變數；用途是
「不要讓 6 檔金融股同時入選」，不是「金融股會漲」。台股分類也極少
跨大類搬家。

**但它仍然是禁令 1 的一個缺口。** 拿到帶生效日的分類資料後應該換掉。

### 還原價與實際價（只影響回測）

`resolve_tier` 用價格判斷「買不起整張」，而回測用的是還原價。還原是
回溯調整、錨在最新日，所以**決策日當天還原價 = 實際價**（實測 10 檔
落差全部 0.0%），帳本這邊沒有問題。

但回測的舊日期還原價會低於當時實際價，於是「買得起整張」會被高估、
成本被低估。方向是讓結果變好看的那一邊，**要記著**。

### 相關係數的 `abs()` 偏離規格

`constraints.py` 用 `abs(rho) >= max_correlation`，但 CLAUDE.md 寫的是
`相關係數 < 0.7`（帶符號）。rho = −0.9 的兩檔是互相對沖，不是集中風險，
拒絕它在風控上講不通。

實測 36 期裡**負相關剔除 0 筆**，所以這件事目前不影響任何結果。
先記錄，不動既有行為。

### 沒做的

- 投組約束**只接在帳本產出路徑**。`validate_oos_momentum.py` 仍然是
  無約束版——那份 OOS 報告的數字對應的是對照組，不是可推播的版本
- 沒有自動排程。要靠人每 40 個交易日跑一次 `record_forward.py`
- 下市股處理未驗證
