## 實測抓到的三件事

### 1. D7 原始參數內部矛盾（已修訂）

`horizon=5、atr×1.5、q=0.70、R:R>=2.0` 在 8,919 個決策日上：

```
覆蓋率   0.38%（34 筆）
類別分布 +1 = 0     0 = 28     −1 = 6
```

**`+1` 完全為空。** ATR×1.5 導出的停損約 3%，搭配 R:R≥2 要求約 7% 的目標，
5 個交易日內觸及 7% 的機率極低。

修訂為 `atr×0.8、q=0.85`（保留 5 日與 R:R≥2）：

```
覆蓋率   55.5%（4,946 筆）
類別分布 +1 = 951   0 = 1,404   −1 = 2,591
平均目標 6.20%   平均停損 2.38%   R:R 2.605
```

診斷：`scripts/diagnose_barrier_params.py`｜報告：`reports/barrier_param_diagnosis.txt`

### 2. 無條件期望值是負的 — 模型要跨的門檻已量化

```
基礎勝率（排除到期）   26.85%
損益兩平勝率           27.74%
無條件期望毛報酬/趟     −0.076%
一趟來回成本           −1.071%
無條件期望淨報酬/趟     −1.147%

→ 模型必須把勝率從 26.85% 提升到 40.22% 以上才有正期望
```

**這是紅線**：Walk-Forward 的 OOS 勝率站不上 40.22%，就是沒有優勢。

這比原本 CLAUDE.md 拍的 `P(+1) >= 0.55` 有意義得多——40.22% 是從實際柵欄
寬度與成本算出來的，0.55 是猜的。已改為動態門檻：

```
P(+1) >= (stop_pct + round_trip_cost) / (target_pct + stop_pct)
```

### 3. NaN 會靜默通過門檻檢查（真 bug，已修）

煙霧測試發現 2317 的平均目標是 `nan%`，而它竟然通過了 R:R ≥ 2.0 的門檻。

根因：2317 在 2025-07-30 有一列 OHLC 全為 NULL（上游資料洞）。單一 NaN
汙染 `np.quantile` → `target_pct = NaN` → `risk_reward = NaN` →
**`NaN < 2.0` 為 False，門檻靜默放行。**

> NaN 不會讓比較拋錯，它會讓比較「看起來通過」。

兩層修正：

- `barrier_width.derive_width()` 在門檻比較前用 `np.isfinite()` 明確排除
- `loader.load_prices()` 預設剔除 OHLC 缺漏列，並提供 `price_quality_report()`
  揭露被剔除了什麼（不靜默丟棄）

全標的池掃描結果：**11 檔有資料洞，共 12 列**

```
1101 [2025-08-13]   1102 [2024-06-05]   1504 [2025-07-30]
2207 [2025-12-18]   2317 [2025-07-30]   2449 [2024-04-26]
2884 [2025-11-05]   2887 [2024-08-22]   3036 [2023-09-14, 2025-07-15]

### 為什麼要新增 `portfolio_sim.py`

`backtest/engine.py` 把各期報酬依序複合，結構上只容得下一個持倉。
為了避免重疊持倉複合出天文數字，前一輪加了「前一筆出場後才開新倉」——
那條規則默默把 Top 3 改成了 Top 1：

```
移動停損 OOS 曝險   23 ~ 39%
等權買進持有曝險    100%
```

修正後跑贏隨機 3/9 → **8/9**、跑贏買進持有 0/9 → **3/9**。

兩個引擎職責不同，都保留：

```
engine.py         單筆交易的品質（報酬、成本、換手率）
portfolio_sim.py  整個組合的表現（權益曲線、曝險、回撤）
```

### 目前的結論：仍不推播

見 [04_路線A驗證結果.md](../../docs/需求規劃/202609/04_路線A驗證結果.md)。

「跑贏買進持有」在槽位數上會翻盤（2~3 槽贏、5~8 槽輸），有效獨立樣本
只有 5~16 個，而且 OOS 是 +305% 的極端多頭。

**站得住的是兩件事**：動能突破與籌碼跟隨相對隨機 4/4 勝出；
MaxDD 低於買進持有且曝險只有七成多。

### 已知限制（新增）

1. **分箱校準只給 6 個離散值。** 多檔落在同一箱時期望報酬完全相同，
   排序其實是任意的。輸出已揭露，但這代表 Top 3 的「名次」沒有意義。
2. **分批進場沒有被回測驗證。** 標記層假設 T+1 開盤一次買足。
   要驗證得做盤中撮合模擬 + 分價量資料。
3. **首次訓練期縮到 250 日**（約 1 年），是資料長度逼出來的妥協。
   取得 2015 年起的資料後應調回 500 以上。

### 最重要的發現

資料從 915 個交易日拉到 2,850 個之後，`04` 的結論翻盤：

```
20 日持有       04（1.56 年）    05（7.34 年）

**那個正報酬是多頭環境的產物，不是策略的能力。**

## 兩個已知資料限制（必須隨報告揭露）

### 標的池只有 100 檔，且是市值代理

D2 要求 0050（50 家）+ 0051（100 家）= **150 檔**。
上游只同步了「市值前 100」，目前以市值排名當代理：

- `rank <= 50` → 0050 級（滑價 0.3%）
- `rank > 50` → 0051 級（滑價 0.4%）

要補齊需取得真正的成分股名單。`UniverseWarning` 會在每次載入時輸出這個落差。

### 無歷史成分股快照 → survivorship bias

上游 `stock_universe` 只有一個 `updated_at`。用今日名單回溯歷史會高估績效
（被剔除的弱股不在樣本內）。這是已記錄的缺陷，回測報告必須標明。

補救方向：加一張 `stock_universe_history(as_of_date, stock_id, rank)` 每季快照。
