## 十二條禁令（不可協商）

任何策略、回測、特徵、標記的程式碼都必須滿足：

1. **禁止 look-ahead bias** — T 日決策只能用 T 日收盤前可得的資料
2. **禁止 survivorship bias** — 退市／被剔除的股票必須留在歷史樣本內
3. **必須加入交易成本** — 一律呼叫 `taiwan_quant/config/costs.py`，禁止他處重寫費率
4. **必須加入滑價** — 零股分層，0050 為 0.3%、0051 為 0.4%
5. **必須 walk-forward** — 滾動訓練，只用預測期之前的資料
6. **必須 out-of-sample** — OOS 區間只跑一次，不得回頭調參
7. **必須保存 strategy version** — 每次產出都要能反查是哪版程式、哪組參數
8. **必須保存 backtest parameters** — 含成本模型設定
9. **不得直接修改 production** — 已發佈的策略檔案不得就地改寫
10. **所有策略必須有 unit test** — 特徵與標記函式要比對手算值
11. **財報／月營收一律用公布日（announce_date）對齊**，不可用所屬期間
12. **一律用還原股價**；任何使用未還原價的地方必須寫明理由

## 四條實測逼出來的規格（來自 qlib-tw-trader 驗證）

13. **換手率是回測的一級輸出**，不是事後才算。任何策略報告都要並列週換手率與年化成本拖累。
    > 實測：週換手 9.9% → 年化成本 5.51%；271.5% → 115.56%。持有期是成本的主導因素。
14. **valid/live IC 相關係數必須監控**。接近 0 或為負時，模型選擇機制已失效，這時調參數是在調噪音。
    > 實測 qlib-tw-trader：valid IC +0.0362、live IC −0.0263、相關係數 **−0.159**。
15. **成本敏感度至少三檔並列**：無成本 / 含手續費稅 / 含滑價。
    > 實測：+0.41%（無滑價）vs −19.08%（含滑價），差 19.5 個百分點。
16. **look-ahead 掃描器不能用 qlib 的 `end_time` 做截斷**，必須物理重新匯出只到 T 的資料集。
    > 實測：`end_time="2026-06-30"` 下 `Ref($close,-3)/Ref($close,-1)-1` 仍算得出值。

## 核心建模方式

不預測價格，預測 **triple-barrier 標籤**：

```
給定 T 日收盤（只用 T 日及之前的資料）
    上柵 = entry × (1 + target_pct)
    下柵 = entry × (1 − stop_pct)
    時間柵 = T + 5 個交易日

y = +1  未來 5 日內「先」觸及上柵
    −1  未來 5 日內「先」觸及下柵
     0  時間柵到期都沒觸及
```

- 用當日 high/low 判定觸發；同一根 K 同時觸及兩柵 → 保守判 −1
- 進場時點固定 **T+1 開盤**（週五盤後決策 → 下週一開盤），因為三大法人資料 T 日盤後才公布
- `target_pct` / `stop_pct` **不可人工寫死**，須由 ATR 分位數與歷史相似型態報酬分布推導

## 柵欄參數（依 D7 修訂，2026-09-12 實測定案）

```
horizon          5       交易日（使用者需求）
min_risk_reward  2.0     風險紀律，不可為湊樣本放寬
atr_multiple     0.8     原 1.5 導致停損過寬、目標不可觸及
target_quantile  0.85    原 0.70 導出的目標過不了 R:R 門檻
```

原始 D7 參數（atr×1.5、q=0.70）實測覆蓋率僅 **0.38%** 且 **`+1` 類別為空**，
規格內部矛盾。修訂後覆蓋率 55.5%，三類各有 900+ 樣本。
診斷工具：`scripts/diagnose_barrier_params.py`

## 進場門檻（動態，不用固定 0.55）

```
P(+1) ≥ (stop_pct + round_trip_cost) / (target_pct + stop_pct)
```

門檻隨每檔標的的實際柵欄寬度與流動性分層計算，不是拍一個 0.55。

```
至少 1 支 defensive / 高股息 / 低 beta
```

## 部位規模（資金 40 萬，必須做零股）

```
建議股數 = floor(min(
    總資金 × 1% ÷ (entry − stop),     # 風險倒推
    總資金 × 33% ÷ entry              # 單檔資金上限
))
若 < 1 股 → 不推播此檔
```

每份回測報告都要並列：

### 無資訊對照組：與策略同結構、但與標籤無關

```
模型類策略   在每個日期之內打亂標籤後重訓，取前 N 檔
分數類策略   同一特徵集的隨機權重組合，取前 N 檔
```

**它的用途是驗證管線，不是提高門檻。** 2026-09-18 修正後實測：

```
真模型      淨/趟 +3.69%
標籤打亂    淨/趟 +0.56%
隨機 10 檔  淨/趟 +0.57%

打亂 − 隨機 = −0.01%／趟   SE 0.51%   t = −0.02   量不出差別
真模型 − 打亂 = +3.14%／趟  SE 1.11%   t = +2.82   顯著較好
```

**打亂之後掉到隨機水準，那正是要的結果**——它證明優勢來自特徵與標籤
的關係，不是來自切分或索引的洩漏。

毛報酬解剖：

```
持有全池              1.99%
隨機 10 檔（中位）     1.65%
任意函數取前 10        1.58%    ← 低於持有全池，沒有「集中化紅利」
手工分數取前 10        4.17%
模型取前 10           4.67%
```

### 稀疏隨機權重仍比隨機選股嚴格一些

```
隨機選股（中位）        +0.57%
稀疏隨機權重（中位）     +0.86% ~ +1.14%
標籤打亂               +0.56%
```

差距是 0.3 ~ 0.6 pp。「有多種構造時用最嚴格的那個」仍然有用。

### ⚠️ 持有期慣例：出場是 T+H，不是 T+1+H

```
進場   T+1 開盤
出場   T+H  收盤        →  closes.shift(-H) / opens.shift(-1) - 1
```

持有天數 = 出場位置 − 決策位置。持有期表的「20 日 → 每年 12.6 趟」
（252/20）就是這個定義。

**單一來源是 `data/integrity.holding_dates`。** 任何新的 forward 報酬
計算都要與它對齊，並加測試直接比對——2026-09-18 的 off-by-one 就是
五支腳本各自實作造成的，而其中三支寫成 T+1+H。

### 對照組的三條實作要求

```
1. 權重／模型在時間上固定或逐期重訓，與被比較的策略一致
   每期重抽權重會失去持續性，退化回隨機選股
2. 允許雙向（權重可正可負）
   手挑分數的方向是靠 _squash(-x) 內建的，對照組不給負權重就是綁住手
3. 稀疏度必須等於被比較策略的特徵數
```

第 3 條是實測逼出來的。密集對照組（32 特徵全部非零）比匹配稀疏度的弱：
32 個隨機正負權重會互相抵銷、接近雜訊，而手工分數只用 4~6 個特徵。

各構造的淨/趟中位（**40 日持有期，已更正**）：

```
虛無假設                        淨/趟中位
純隨機選股                       +0.57%
標籤打亂的 LightGBM              +0.56%
稀疏隨機權重（4~6 特徵，匹配）     +0.86% ~ +1.14%   ← 最嚴格
```

**有多種構造時用最嚴格的那個，並列出各構造的中位數。**

⚠️ 2026-09-17 版本寫 +1.05% / +1.45% / +1.58% / +2.94% 並說「標籤打亂
最嚴格」。那是 41 日持有期的結果——修正後**稀疏隨機權重才是最嚴格的**，
標籤打亂與純隨機無法區分。

### 累積報酬不可以當結論句（2026-09-18 實測定案）

樣本外那份已發佈的結果，**七個基準全部落在它自己的 95% 區間裡**：

```
動能突破 N=10 累積淨      +138.83%
95% 區間（block=1）      [−13.34%, +587.23%]   寬 600 pp
0050 +242.15%｜0051 +110.22%｜0056 +96.67%｜等權 +61.45%
隨機中位 +58.82%｜隨機 5% +15.10%｜隨機 95% +120.97%   ← 全在區間內
```

複利把每期變異放大，16 次乘法後尾部極長。**累積報酬在 n≤36 下不可
falsify。** 配對差異則存活（逐期相減消掉市場共同變動，SE 1.11% vs 1.97%）。

```
結論句要用   每趟配對差異 + bootstrap 區間
降級為附錄   累積總報酬、年化、以及任何跨組的累積比較
```

⚠️ **兩個方向的結論要用同一把尺。** 先前「輸 0050 −103 pp」被當成最
可靠的負面結論並寫進五份加註，而它和正面結論一樣落在區間內、一樣
做不出來。失效的方向對策略有利，但那不代表策略更好。

### 報告必須保存逐期序列（2026-09-18 新增規格）

```
□ 任何報告結論性數字的報告，必須存 per_period 或 series
```

區間估計是純後處理，讀逐期序列**不動用禁令 6 的區間**，所以可以隨時
重跑。但沒存逐期序列的報告，唯一的取得方式是重跑——而那是被禁的。

**實例**：`03_待辦與改進方向.md` 點名的 `+1076%`（籌碼跟隨 × 60 日）
算不出區間，因為沒有報告存了它的逐期序列。那個數字的不確定性是
**永久不可知**的。

工具：`scripts/diagnose_bootstrap_intervals.py`（兩種報告格式都吃）。
`validation/bootstrap.py` 的 `block_length` 與 `seed` 都是必填——
前者是要說明理由的選擇，後者要能寫進報告才可重現。

依據 `../qlib-tw-trader/docs/原理說明/2026-09-18_信賴區間讓累積報酬失去意義.md`


## 多重測試校正

掃 N 組參數 / N 個策略族時必須回報 **Deflated Sharpe Ratio** 或 **PBO**。
PBO > 0.5 → 該策略族判定過擬合，不得進入 Top 3 排名。

- **不可變優先**：回傳新物件，不要就地改寫傳入參數
  > qlib-tw-trader 的 `_feature_selection()` 就地改寫 `X_train`，在 pandas 3.0 下直接壞掉
- 檔案 200~400 行為常態，800 行為上限
- 錯誤要明確處理，不可裸 `except:`
- 系統邊界一律驗證輸入
- 秘密走環境變數或 `.env`，不得硬編碼
- 註解用繁體中文，與既有程式碼一致

## 資料來源

沿用 `../qlib-tw-trader` 已同步的 SQLite（`qlib-tw-trader/data/data.db`）。
不重寫資料同步層 —— 那部分已驗證可用。

## 測試

```bash
.venv/bin/python -m pytest -q                       # 全部
.venv/bin/python -m pytest -m unit -q               # 單元
.venv/bin/python -m pytest --cov=taiwan_quant       # 覆蓋率，目標 80%
```

TDD 流程：先寫測試（RED）→ 最小實作（GREEN）→ 重構（IMPROVE）。
特徵與標記的測試必須**比對手算值**，不可拿程式輸出反填預期值。
